# 配色方案：从「暖纸」到「中性工作室」

> 本文是**提案**，不涉及代码改动。所有取值都来自对参考截图 `Screenshot 2026-10-21 at 14.54.46.png` 的实际像素采样（3600×2338），不是目测。

---

## 1. 参考图到底是什么配色

采样结果（按像素占比排序）：

| 采到的颜色 | 占比 | 用途 |
|---|---|---|
| `#F9F9F7` | ~74% | **主背景**（内容区） |
| `#F7F7F5` | ~13% | 侧栏 / 顶栏底色 |
| `#F2F2F0` | ~6% | hover、次级面、选中态 |
| `#FAFAF8` | ~5% | 抬起面（很弱的层次） |
| `#000000` | ~4% | **正文与标题文字（纯黑）** |
| `#FFFFFF` | ~2% | 卡片、输入框、气泡 |
| `#2D2D2B` | — | 次级深色（图标/弱标题） |
| `#ECECEB` / `#E9E9E4` | — | 分隔线、边框 |
| `#2C67C5` | 极少 | **唯一强调色（蓝）**，只用于主操作 |

**关键特征**（和现在的差别）：

1. **几乎是中性灰白**。`#F9F9F7` 的 R=G=249、B=247 —— 只有 **2/255 的暖偏差**。而现在的主背景 `#f7f3ee` 是 R247/G243/B238，暖偏差 **9/255**，是明显的米黄纸感。
2. **文字是纯黑或近纯黑**`#000`，文字层级靠**字号/字重/纯度**拉开，不靠色相。
3. **只有一个强调色**，且只在"升级/主操作"这种极少数位置出现。界面整体是**无彩色**的。
4. **层次靠 4 级极浅的面**（`#FAFAF8 → #F9F9F7 → #F7F7F5 → #F2F2F0`），差值只有 2–7，非常克制；边框极浅（`#ECECEB`，对比度 1.16:1）。
5. **阴影是中性黑**（`rgba(0,0,0,0.04–0.10)`），不是现在这种暖褐色阴影 `#281f18`。

## 2. 现在的问题（为什么你"不喜欢"是有道理的）

| 问题 | 证据 | 后果 |
|---|---|---|
| 暖色叠加过多 | 背景暖偏移 9、文字 `#2f2b26` 也是暖褐、阴影 `#281f18` 还是暖褐 | 层层叠加后整体发黄发闷，像旧纸 |
| 文字层级用 alpha 表达 | `--text-secondary: #2f2b26b8`、`--text-muted: #2f2b267a` | 同一个 token 在不同底色上**对比度不同**，在 `--surface-bubble` 上会掉到 3:1 以下 |
| 没有强调色 | `--accent: #5a5a5a` 是灰 | 主按钮、焦点环、选中态全是灰，界面"没有重心" |
| 阴影与背景同色系 | 暖背景 + 暖阴影 | 阴影不透气，卡片浮不起来 |
| 反差不足 | `--border` 相对背景只有 1.16:1 | 分区分不出来，全靠留白 |

## 3. 建议方案：Token 映射表

### 3.1 基底（面）

| Token | 现在 | **建议** | 说明 |
|---|---|---|---|
| `--bg` | `#f7f3ee` | **`#F9F9F7`** | 与参考图完全一致；保留 2/255 暖度，避免冷灰发蓝 |
| `--surface` | `#fffcf8` | **`#FFFFFF`** | 卡片、输入框、气泡用纯白抬起 |
| `--surface-strong-translucent` | `#fffcf8f5` | **`#FFFFFFF2`** | 浮层（94% 白） |
| `--surface-hover` | `#fcf8f3` | **`#F7F7F5`** | |
| `--surface-secondary` | `#f1eee8` | **`#EFEFEA`** | 代码块 / 表格 / 次级按钮 |
| `--surface-bubble` | `#eee9df` | **`#E8E8E3`** | 用户气泡；必须比 `--surface-secondary` 深一档，否则和代码块混同 |
| `--input` | `#fbf8f3` | **`#FFFFFF`** | 输入框改为纯白，用边框区分而不是用底色 |

### 3.2 文字

| Token | 现在 | **建议** | 对比度（在 `--bg` 上） |
|---|---|---|---|
| `--text` | `#2f2b26` | **`#0D0D0C`** | 18.5:1（UI 标签、按钮、标题） |
| `--text-reading` | `#27231f` | **`#1A1A18`** | 16.5:1（长文正文，比纯黑柔和一点，减少长时间阅读的刺眼感） |
| `--text-secondary` | `#2f2b26b8` | **`#5F5F5A`**（实色） | 6.1:1 ✅ AA |
| `--text-muted` | `#2f2b267a` | **`#6B6B66`**（实色） | 5.1:1 ✅ AA |
| —— | —— | `#8A8A84`（新增层级，仅 ≥16px 或装饰） | 3.3:1（不达 AA，别用于 12px 元信息） |

> **重要**：把 alpha 文字改成实色。这是这次改动里收益最大的部分——现在 `#2f2b267a` 落在不同面上对比度会漂移，改成 `#6B6B66` 后**任何底色上都稳定在 5:1**。

### 3.3 边框与交互

| Token | 现在 | **建议** |
|---|---|---|
| `--border` | `#463b2d1f`（≈`#efeae1`） | **`#E9E9E4`** |
| `--border-strong` | `#463b2d33`（≈`#ddd6ca`） | **`#D8D8D2`** |
| `--hover` | `#5a5a5a14` | **`#0000000A`**（4% 黑） |
| `--text-selection`（新增） | 借用 `--hover` | **`#0D0D0C2E`**（18% 墨） | 文本选区；不能复用 `--hover`，否则要么几乎看不见、要么 hover 过重 |
| `--selection` | `#5a5a5a24` | **`#6B4A8F1F`**（12% 茄紫） |
| `--selection-strong` | `#5a5a5a38` | **`#6B4A8F33`** |
| `--focus-ring` | `#5a5a5a2e` | **`#6B4A8F3D`** |
| `--focus-ring-strong` | `#5a5a5a38` | **`#6B4A8F59`** |

### 3.4 强调色（新增"重心"）

| Token | 现在 | **建议** | 用途 |
|---|---|---|---|
| `--accent` | `#5a5a5a` | **`#6B4A8F`**（茄紫） | 链接、选中、焦点环、图标徽标、画布选中框 |

> 浅底强调不需要新 token：`--selection`（12% accent）已经承担这个角色，`--accent-soft` 不再单独引入，避免两个 token 表达同一件事。

**对比度**：`#6B4A8F` on `#F9F9F7` = **6.64:1** ✅ AAA；白字放在 `#6B4A8F` 上 = **7.0:1** ✅ AAA。两个方向都安全。

**为什么是茄紫，不是别的色？**

| 候选 | 对比度 | 否决理由 |
|---|---|---|
| 蓝 `#2C67C5` | 5.17 | 你明确排除 |
| 陶土红 `#A9492B` | 5.42 | 与 `--danger` 红、以及 diff 的 `-N` 红色**过近**，错误态和强调态会混 |
| 琥珀 `#9A6A00` | 4.49 | 与 `--warning` / `--warning-text` 撞色，且低对比 |
| 墨绿 | ~4.0 | 与 `--success` 及 diff 的 `+N` 绿色**过近** |
| 纯黑 | 19.9 | 与 `--text` 几乎无法区分，等于没有强调 |
| **茄紫 `#6B4A8F`** | **6.64** | ✅ 红/绿/琥珀三个语义色之外唯一未被占用的色相 |

> 画布选中框现在直接继承 `var(--accent)`（亮色块第 11 行）；暗色块单独保留浅紫 `#C3AEDE`。这样**只有一个真值**，换色相时不需要两处同步。
> 如果之后想换色相：改 `--accent` 与四个 `--selection/--focus-*` 即可，**不用动任何组件**。

## 5. 三个需要你拍板的决策

### ① 要不要保留那 2/255 的暖度？

- **A（已采用，= 参考图）**：`#F9F9F7`。中性里带一丝暖，不会像纯灰那样发冷、发蓝。
- **B（更冷）**：`#F8F8F8` / `#FAFAFA`。更像 Linear / Vercel。
- **C（保留一点纸感）**：`#F8F7F2`。暖偏移 6，介于两者之间。

> 我建议 A。你现在的 `#f7f3ee` 暖偏移 9 是"米黄纸"，A 是"白纸"，观感差别在"闷不闷"，不在"暖不暖"。

### ② 正文用纯黑还是近黑？

参考图 UI 是 `#000`。但你的场景是**长文阅读流**（消息流 + Markdown + 代码），纯黑在浅底上对比度 19.9:1，长时间阅读会累。

- **推荐**：UI 用 `#0D0D0C`，长文正文用 `#1A1A18`（16.5:1，仍远超 AAA）。
- 如果你要"和参考图一模一样"，就全用 `#000`。

### ③ 主按钮的颜色 —— 已按"保持黑"处理

`.primary-button` 仍是 `background: var(--text)`（黑底白字），和参考图一致。茄紫只出现在 **链接 / 选中 / 焦点环 / 徽标** 这类"次要但需要被看见"的位置。这样既满足"明显一点"，又不破坏参考图的克制感。

如果你想要更"跳"一点，把 `--accent` 换成 `#7A56A0`（对比度 5.43）即可，其余 token 不变。

- [ ] 12px 元信息文字对比度 ≥ 4.5:1

- [ ] 用户气泡、assistant 正文、代码块三者的边界在**灰度截图**下仍可区分（去掉颜色后不能糊成一片）

- [ ] 滚动条在浅底上不被误认为"边框"
- [ ] 截图转灰度后，层级仍然成立 —— **这是中性配色的唯一验收标准**

## 7. 顺带一句：建议现在就把 token 语义化

你现在没有暗色模式（`grep prefers-color-scheme` 无结果）。如果将来要加，**现在就该把 `--hover`、`--surface-bubble` 这类"视觉描述"改成"语义描述"**（如 `--bg-hover`、`--bubble-user`），这样暗色模式只要换一层值，不用改组件。

不做也行，但补的时候会很痛。
