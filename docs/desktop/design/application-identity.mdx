应用名称与 macOS 启动。

- 展示名称：`package.json.productName` 定义用户看到的产品名称 `I`。主进程窗口标题、应用菜单、About 面板、Renderer 页面标题和无障碍标题共同读取这一字段。Electron 内部名称使用 `package.json.name` 中的稳定标识 `agent-studio`，将产品展示与用户数据身份分别管理。

持久化身份。

- 内部身份：Main 在 Electron `ready` 之前设置内部应用名称，macOS 钥匙串继续使用 `agent-studio` 对应的 Safe Storage 服务与账户。
- 数据目录：`userData` 与 `sessionData` 使用 `appData/agent-studio`。会话 SQLite、Provider 配置、Canvas 文档和同一页面 origin 的 Chromium 偏好沿用既有目录。
- 隔离目录：显式传入 `--user-data-dir` 时，Main 将该目录用于 `userData` 与 `sessionData`，提供隔离运行和回归验证入口。
- 菜单：macOS 原生菜单使用 `I`、`About I`、`Hide I` 与 `Quit I`，保留系统菜单角色及标准快捷键。

开发与本地打包。

- 开发启动：`npm run dev` 与 `npm run preview` 使用专属 `I.app` 开发启动器。`scripts/macos-app.mjs` 通过 Electron Packager 生成系统元数据，再通过 `ELECTRON_EXEC_PATH` 交给 electron-vite；默认应用加载器继续加载当前工程入口，保留热更新与主进程重启行为。`process.defaultApp` 标记工程采用默认加载器启动，页面加载方式由 `ELECTRON_RENDERER_URL` 控制；`app.isPackaged` 反映专属原生应用包本身的形态。系统展示名来自应用包的 `I` 元数据。缓存身份绑定 Electron 版本、架构、产品名称、应用版本和图标内容，相关配置变化后生成对应启动器。
- 本地打包：`npm run package:mac` 先构建，再生成当前 Mac 架构的 `dist/I-darwin-<arch>/I.app`。本地包收录 `package.json`、完整 `out/`、生产依赖和 Canvas 的 MIT 许可声明，文件目录形式支持 ripgrep 原生可执行文件及 Canvas CLI 子进程。开发启动器和本地包都采用本地 ad-hoc 签名；对外分发阶段配置 Developer ID 签名、公证或 Mac App Store 发布身份。
- 运行时缓存：打包脚本将本机已安装的 Electron 运行时归档到版本与架构对应的缓存，通过 Electron Packager 的 `electronZipDir` 复用同一运行时。图标与原生启动器采用同样的本地缓存流程。

图标与展示名称。

- 图标资源：SVG 原稿保存在 `frontend/src/assets/app-icon.svg`，Renderer 直接将其用于 favicon。对应的 1024×1024 PNG 用于运行时 Dock 图标；打包脚本从 PNG 生成系统图标资源。开发启动器和本地包共同写入产品名称与图标，macOS 从实际应用包识别 `I`。
- 导航标识：工作台左侧 `I` 入口使用应用图标内部的矢量符号，透明底与导航文字共同继承主题颜色；Dock、favicon 和原生应用包继续使用完整应用图标。
- 商店身份：App Store Connect 的商店名称独立于本地应用包名称，遵循商店名称的本地化与长度规则。Bundle ID 则保持系统应用身份稳定。

应用生命周期。

- 资源属主：Main 在应用启动时创建共享 SQLite Repository、项目路由、Recorder 缓存与 Canvas 存储，窗口通过同一组服务处理请求。
- 生命周期：`ApplicationLifecycle` 使用 `running`、`draining` 和 `terminating` 管理业务接入、退出准备与资源释放；菜单退出、SIGTERM 和 SIGINT 进入同一个退出任务，重复退出请求共享该任务。
- 接入门控：`running` 接纳业务 IPC；`draining` 等待已接纳的请求和运行收尾，已有窗口继续处理当前退出请求对应的 Canvas 保存与回执；退出准备期间的其他请求取得明确的退出状态错误。
- 画布准备：Preload 在 Renderer 注册 `onPrepareToQuit()` 时登记窗口就绪状态；Main 以独立 `requestId` 请求各已就绪窗口保存画布，Renderer 等待 `CanvasSurface.flush()` 完成后调用 `completeQuitPreparation()`；Main 同时校验窗口身份与请求身份。
- 保存反馈：画布保存失败或回执超时后，生命周期恢复 `running` 并展示保存错误，共享数据库和业务服务继续可用，用户可处理保存问题并再次退出。
- 资源释放：画布回执完成后，Main 排空已接纳的持久化操作，释放语音和 Canvas 执行器，等待 Canvas 存储与 Recorder 完成写入，再进入 `terminating`，关闭共享数据库一次并调用 `app.exit()` 结束进程。
- 窗口恢复：macOS 关闭最后一个窗口时保留应用服务；`activate` 在 `running` 且窗口列表为空时创建窗口，继续使用原有 Repository。退出准备与资源释放期间保持现有窗口集合。
- 窗口属主：`registerWindowResources()` 在窗口创建时保存 `WebContents.id` 并登记音频权限属主；同一个 `destroyed` 回调使用保存的数字 ID 注销权限登记、释放退出准备回执并取消该窗口的语音转写，每个窗口执行一次属主清理。
- 实现位置：`shell/main/application-lifecycle.ts` 管理接入、窗口属主清理与退出顺序，`shell/main/quit-preparation.ts` 管理 Renderer 保存回执；`shell/main/index.ts` 装配资源，`shell/shared/ipc.ts` 与 `shell/preload/index.ts` 提供受限退出准备协议。
