Composer。

- 位置：固定在工作台内框消息主列底部，覆盖在同一列的消息流滚动容器之上，定位范围与内框主列一致（覆盖关系见滚动条）。
- 尺寸：最大宽度760px，最小高度116px。
- 材料：`--input` 与 `--bg` 共用页面底色，浅色 #F8F8F8、深色 #171717；外壳采用20px圆角、1px通用边界，以及 `0 1px 3px` 和 `0 8px 24px` 两层轻量阴影。
- 内边距：顶部18px，水平14px，底部10px。
- 布局：附件区，任务输入区和内部操作带三个区域共用同一表面，区域之间8px间距；左侧图标组保持完整热区，右侧模型名称在剩余空间内单行省略。
- 悬停：外壳保持页面同色，内部按钮按各自热区显示交互反馈。
- 焦点：内部焦点出现时外观沿用常态。
- 高度：根据附件和输入高度向上扩展。
- 重排：外壳留白、窗口尺寸、左侧项目列表和右侧工作侧栏共同确定内框消息主列的可用宽度，Composer 在该列内同步重排；内框标题行下方的内容区提供定位高度，高度测量与消息底部占位沿用既有链路。

项目范围。

- 入口：左侧 `I` 进入普通对话，`Project` 展开项目列表；项目添加与条目选择由[项目导航](./project-navigation.mdx)定义。
- 布局：Composer 使用一个输入外壳，顶部空间由外壳内边距和附件区高度构成，底部消息占位继续使用实际测量高度。
- 输入：App 将活动项目描述交给 Composer，`projectId` 继续用于 RunRequest、SteerRequest 和语音输入的作用域。
- 协作：项目切换由 App 与 Main 完成，Composer 接收目标范围并沿用现有发送条件、草稿与材料清理规则。

模型选择热区。

- 结构：模型名称、展开箭头和水平内边距组成一个可见胶囊热区。
- 尺寸：高度28px，圆角14px；名称和箭头在热区内垂直居中。
- 材料：默认保持透明，悬停、聚焦和展开使用 `surface-bubble`，形成交互时可见的选择器背景。
- 交互：点击、键盘聚焦和展开状态共享同一胶囊热区视觉；热区宽度继续根据模型名称自适应。

项目上下文。

- 项目目录地图由 Main 扫描并缓存到 `project_context`；缓存保存优先排序的有界路径树、目录省略信息、hash、扫描时间、策略版本和 dirty 状态。
- 每次项目范围的模型请求收到项目名、当前工作目录、带深度/条目/总量说明的可读导航地图，以及按需使用文件工具的提示；提示文本有字符上限，目录地图提供路径导航，文件正文通过工具按需读取，地图作为本轮运行期材料使用。
- 文件工具以同一项目根目录作为运行 `cwd`；列表、查找、内容搜索和文件读取按模型当前任务提供更深入的文件信息。
- 缓存保持有效时，新的用户消息直接复用缓存；工具修改文件后，Main 标记缓存 dirty，下一次运行刷新目录树。
- 无项目历史使用 `project_id = NULL`；模型请求使用历史、默认工作目录和当前任务，并继续获得相同的文件工具；项目目录地图保持为空。

附件区。

- 位置：任务输入上方。
- 空状态：高度为0。
- 间距：附件之间8px，根据可用宽度换行。
- 尺寸：图片与视频卡片宽160px，预览区域采用16比9比例，底部文件信息带高36px；普通文件引用采用42px高、最大230px宽的紧凑卡片。
- 材料：输入表面颜色，12px圆角，通用边界；媒体预览与文件信息带组成同一卡片，预览使用 contain 保留完整画面。
- 文件引用：普通文件卡片展示文件图标、文件名与大小；图片卡片展示真实缩略图，视频卡片展示采样封面、播放标记与时长，底部名称采用单行省略。草稿卡片右上角提供28px移除热区。
- 预览：点击媒体卡片打开可关闭的预览层，图片展示完整画面，视频提供本地副本的播放控件；Esc 与关闭按钮返回输入区域。
- Canvas 引用：Use selection 创建的 chip 与文件引用共用布局和移除入口，展示选区名称及元素数量；Renderer 通过 contextId 持有已冻结的选区 JSON 引用。
- 草稿：Renderer 同时保存文件附件与 Canvas 选区引用，分别按 attachmentId 和 contextId 合并重复项。
- 提交：Composer 在同一份 RunRequest 中提交用户原文、attachmentIds、canvasContextIds 和 projectId；有效文字或已准备好的附件均满足初始任务的内容条件。Main 校验附件身份、处理结果与 Canvas 引用的项目归属，Runner 将附件引用绑定到同一条用户消息。
- 项目切换：Renderer 更新项目描述并清理前一项目的 Canvas 引用 chip；Main 同步校验待发送 contextId 的所属项目。
- 移除：移除入口更新 Composer 草稿，文件资源与 Canvas 场景继续遵循各自的生命周期；运行期间移除入口禁用。

上传文件模块。

- 归属：`composer/upload-files` 管理文件入口、拖放状态、附件草稿、预览卡片与错误反馈，Composer 负责模块装配与发送决策；Canvas 选区继续由画布上下文模块管理。
- 添加：加号选择器与文件拖放共用 Main 附件接入服务。Preload 使用 Electron `webUtils.getPathForFile` 获取本地文件路径，经显式 IPC 交给 Main；内存 File 通过有大小限制的字节载荷接入。
- 拖放：文件进入输入外壳时显示覆盖式圆角提示，拖放计数覆盖嵌套子元素，外壳尺寸保持稳定；文本拖放沿用输入框行为。运行、发送确认与语音操作期间，文件入口呈现禁用状态并接管文件导航行为。
- 状态：模块通过附件卡片与上传按钮的忙碌语义呈现接入状态；附件处理期间 Composer 保持原有布局和输入区域，处理完成后显示附件卡片，失败时展示可读原因；一次接入按文件返回结果，已成功接入的附件保持可用。
- 作用域：附件属于消息资料，应用管理的副本通过稳定 ID 引用；项目 ID 选择历史归属，普通对话与项目对话共用附件能力。异步接入结果按照发起时的草稿作用域处理。
- 保存：Main 将原始字节保存到应用数据目录的附件存储，元数据与可再生处理产物按附件 ID 管理；历史 entries 保存用户原文、附件身份和有预算的输入摘要，媒体字节在构造请求时读取。
- 存储位置：`userData/attachments/<attachmentId>/` 保存原始副本、`manifest.json`、提取文本与预览资源；`userData` 由固定存储身份统一装配，开发启动与安装应用共用[应用数据目录](./session-storage.mdx)规则。附件 ID 由内容、名称和处理策略版本共同确定，重复接入复用同一份已准备资源。
- 处理：Main 的附件服务统一调度轻量文档进程、可选 Docling Python 进程与 FFmpeg、FFprobe 进程；文档解析器通过注册表提供身份、版本、能力说明、就绪检查与执行入口，处理队列和资源预算由共同管线维护。
- 默认策略：普通文本直接读取有预算的文字，PDF 使用 PDF.js 提取文字层并渲染有预算的页图，DOCX、PPTX、XLSX 使用 OOXML 结构读取正文、表格与来源位置；扫描页通过页图交给当前视觉模型理解。
- 高级策略：Docling 作为可选的本地高级解析器提供布局、表格与 OCR 能力；安装包提供下载入口与安装脚本，用户点击下载后把 Python 环境、解析依赖和本地模型写入应用数据目录。默认解析与启动流程只使用轻量解析器。
- 选择入口：通用设置展示文档解析器选择、能力说明与高级运行时就绪状态，界面复用共享选择器；设置确认成功后影响后续上传，已添加附件与历史继续引用各自捕获的处理结果。
- 缓存身份：每批上传在接收时捕获解析器及版本，文档缓存键同时包含源内容、文件名与解析策略身份；图片、视频和文本使用各自稳定的处理策略，解析器切换保持已有附件内容一致。
- 模型输入：图片使用原生视觉内容块；文档使用带文件名和来源信息的有预算文字及必要页面图片；视频使用带时间戳的有限采样帧。资料内容保持用户资料语义，所选模型与服务决定视觉输入的兼容范围。
- 深入查看：`attachment_read` 通过附件 ID 分页读取处理文字，并查看准备好的页面图片或视频帧；工具返回明确的覆盖范围与继续读取位置。
- 请求：Provider Adapter 将用户原文与附件输入组成同一条 user 消息，Runtime 的上下文预算同时计入附件文字与图片；后续请求复用本地处理产物，模型上下文选择沿用现有历史投影策略。
- 运行时：轻量文档处理随主程序提供 PDF.js、OOXML 解析、页面渲染与图像编码依赖；Docling 的 Python 环境、依赖和模型独立存放在应用数据目录。设置页根据运行时文件判断高级解析器是否就绪，下载按钮只触发用户显式请求。
- 高级运行时准备：`npm run setup:attachments` 是用户主动准备 Docling 的入口，在 `userData/attachment-runtime` 建立 Python 3.12 环境，安装固定版本 Docling 并准备布局、表格与中文 OCR 模型；`ATTACHMENT_RUNTIME_DIRECTORY` 指定自定义位置。高级文档转换使用本地模型和离线策略，轻量文档转换直接使用主程序提供的解析库。
- 退出：应用退出时先取消附件处理并等待子进程与暂存目录清理，再完成已接收请求、历史和画布的关闭流程。

上传文件按钮。

- 位置：内部操作带左侧。
- 热区：28乘28px 圆形。
- 材料：透明背景，次要文字颜色，悬停使用悬停反馈颜色和主要文字颜色。
- 图标：加号图标（plus）18px，与单一操作按钮的图标同尺寸。
- 交互：在用户触发按钮后打开系统文件选择器，并把选择结果加入附件草稿。
- 运行期间：禁用。

本地语音输入。

- 范围：Composer 提供本地语音转文字入口，识别结果写入当前任务草稿；用户继续编辑并确认发送后，任务沿用现有 `run` 或 `steer` 链路。
- 位置：语音按钮位于内部操作带左侧、上传文件按钮右侧，与上传入口共用28px圆形热区和7px间距。
- 结构：空闲状态显示麦克风图标；录音状态显示中断方形并启用一次呼吸式外环提示；转写状态保持按钮可见并显示忙碌反馈。
- 图标尺寸：录音中断图标使用18px SVG，与发送／中断按钮共用同一尺寸和方形路径；麦克风图标使用17px SVG。
- 波形条：录音期间工具栏隐藏上传、模型选择和发送控件，变为暂停键、整行波形条和叉号取消键；新条形在暂停键一侧以完整高度进入并向右滚动，条形固定3px宽度与3px间距、两端全圆角，安静时呈现约2.4px圆点；条形高度上限为行高扣除上下各4px边距，两端各以渐变遮罩淡入淡出。
- 人声门控：波形条对100Hz至4000Hz语音频段能量做自适应噪声底估计，语音能量越过噪声底5倍时才让条形涨高，条形进入时直接呈现当前能量对应的高度，环境噪声保持圆点。
- 绘制：波形条使用独立 Canvas 组件读取 AnalyserNode 频域数据，由 requestAnimationFrame 直接绘制，Composer 在录音阶段只渲染一次 Canvas，逐帧绘制不触发 React 更新。
- 反馈：授权、录音和转写阶段通过按钮状态呈现，错误发生时展开可关闭的提示行。
- 材料：默认使用透明背景和次要文字颜色；录音或转写期间使用 `selection` 背景和主要文字颜色；悬停沿用通用悬停反馈。
- 交互：空闲时点击开始录音；录音中工具栏变为暂停键、整行波形条和叉号取消键，点击暂停键结束录音并提交本地转写，点击叉号取消本次录音；请求权限或转写期间点击取消当前语音操作。
- 状态：Composer 区分空闲、麦克风授权、录音和本地转写四个阶段；语音阶段与 Agent Run 阶段彼此独立。
- 回填：转写完成后把识别文本追加到最新任务草稿末尾，按需增加换行，并通过统一草稿入口把 `taskRevision` 增加一次。
- 保留编辑：录音和转写期间 textarea 保持可编辑；回填读取最新草稿，用户在等待期间输入的文字与识别文本按先后顺序保留。
- 发送边界：转写完成只更新 Composer 草稿；用户点击发送或按 Enter 时，Composer 才构造现有 `RunRequest` 或 `SteerRequest`。
- 运行边界：活动 Run 期间语音入口呈现禁用状态；授权、录音和转写期间发送按钮等待语音操作结束，textarea 保持可编辑。
- 权限：Main 按登记的应用窗口、主框架和 Renderer 页面地址校验音频媒体请求；macOS 打包元数据提供 `NSMicrophoneUsageDescription`，系统拒绝时 Composer 提示用户在系统设置中恢复权限。
- 错误：权限拒绝、无可用设备、设备占用、引擎缺失、模型缺失、空语音、超时和识别失败分别显示清晰提示；错误提示保留在 Composer 内，并由关闭入口清除。
- 容量：用户点击停止后进入转写；单次音频达到20MiB资源预算时自动停止并转写已录内容，当前格式可容纳约10分55秒。
- 音频：Renderer 采集单声道 PCM，统一为16kHz、16-bit WAV；Renderer 和 Main 共用20MiB的音频字节预算。
- 内存：Renderer 按音频字节预算扣除44字节 WAV 头后派生 PCM 缓冲容量，音频帧保持在 Hook 内部；波形条使用固定长度缓冲区，React 状态保存语音阶段、错误文本和 AnalyserNode 引用。
- 传输：停止录音后 Renderer 一次性把完整 WAV `ArrayBuffer` 经语音专用 IPC 发送给 Main；音频保留在 Composer 语音边界内，Agent Runtime、模型上下文和持久历史只接收确认发送的文本。
- Main：Main 校验16kHz单声道 PCM16 WAV、音频字节预算和引擎资源，把音频写入应用临时目录，启动独立 `whisper-cli` 子进程，读取结构化 JSON，并把纯文本返回 Renderer；原生推理由独立进程执行。
- 模型：使用 whisper.cpp 与 Whisper GGML 量化模型；默认随包 `ggml-large-v3-turbo-q5_0.bin`，Voice 设置提供六个可下载模型，用户选中已安装模型后转写优先使用该模型，否则回退随包模型；语言由 Whisper 自动识别，语音模型选择与聊天模型选择解耦。
- 资源：开发运行从仓库 `resources/whisper` 读取引擎与模型；打包应用从 `Contents/Resources/resources/whisper` 读取同一组资源；打包前按固定 SHA-256 校验约547MiB的模型并检查引擎架构，分发目录附带上游许可证。
- 兼容：随包提供的原生引擎面向 Apple Silicon，最低运行系统为 macOS 15.0；安装后的应用直接读取随包模型完成本地识别。
- 资源寻址：Main 通过 `process.defaultApp` 识别默认加载器启动的开发和预览应用，并以 `app.getAppPath()` 定位应用目录中的资源；独立安装包以 `process.resourcesPath` 定位包内资源，改名开发外壳的 `app.isPackaged` 值与加载方式一起参与判断。
- 取消：取消录音立即停止媒体轨、断开音频节点并关闭 AudioContext；取消转写向 Main 发送同一 `requestId`，Main 校验窗口归属，终止子进程并在退出确认后清理临时目录。
- 过期结果：每次录音生成独立 `requestId`；授权与转写回调按当前请求归属接纳结果，取消、项目切换和组件卸载使旧请求失效。
- 生命周期：组件卸载、项目切换和窗口销毁触发语音清理；应用退出等待原生进程终止和临时目录删除。
- 临时资源：Main 为每次转写创建独立临时目录；成功、失败、取消和超时路径都在进程结束后删除音频与 JSON 输出。
- 并发：Main 使用全应用共享的单次转写执行槽，其他请求获得忙碌提示，内存峰值由一份本地模型推理约束。
- 静音：PCM16样本全部为零时直接返回空语音提示；包含非零样本的录音继续进入模型识别，保留微弱语音。
- 重试：语音错误显示在 Composer 错误提示行，用户修正权限或设备后点击麦克风重新录音；失败时 Composer 保留已有任务草稿。

任务输入框。

- 位置：附件区和内部操作带之间。
- 材料：透明背景，边界和阴影沿用 Composer 共用表面。
- 尺寸：最小40px，最大180px。
- 文字：14px，行高22px，Placeholder 为 What's up?。
- 高度增长：根据输入内容调整高度，超过最大高度后输入框内部滚动。
- 提交：Enter 提交任务，Shift Enter 插入换行；输入法（拼音等）组字期间的 Enter 只完成候选确认并上屏，组字结束后再次 Enter 才提交，提交判断读取 keydown 原生事件的 isComposing 标记区分组字状态与真实提交。
- 运行期间：文本输入持续可编辑并保持正常视觉与焦点反馈。运行中提交的载荷为当前文本快照，沿用已启动 run 的项目、模型、附件和画布配置。
- 提交后清理：Composer 在一次提交等待 ACK 时保护当前草稿并显示忙碌状态；初始任务在 Main 返回 `runAccepted` ACK 后清理对应任务草稿、附件和 Canvas 引用；运行中补充文本在 `steer` ACK 后清理对应文本快照并重置输入框高度。确认结束后，输入框接收下一份草稿。
- 失败保留：Main 业务拒绝、IPC 异常或运行启动失败时，Composer 保留对应草稿并显示可重试错误。运行中补充输入被接收后，后续停止或失败由消息流展示“未应用”状态与重发入口。

模型选择按钮。

模型选择状态与名称恢复。

- Composer 持有唯一的 `selectedModelOptionId`，并以它构造每次运行的 `RunRequest`。
- Composer 在 Renderer 首次创建时同步读取 `localStorage` 偏好 `workbench.modelPickerLayout.v1`，恢复 `modelOptionId` 与最近一次确认的 `displayName`。名称在提供商目录通过 IPC 返回前呈现，按钮宽度在绘制前按当前字体测量。
- `workbench.modelOptionId` 继续作为兼容入口。两份偏好的标识出现差异时，以独立标识中的最新用户选择为准，再由当前目录确认模型名称。
- ProviderCatalog 通过 `providers:list` 提供模型目录数据；目录完成加载后，Composer 按 `modelOptionId` 校验模型是否仍在最近一次拉取目录中。模型被远端移除时清除当前选择，后续目录重新出现时可以再次匹配本地偏好。
- 模型名称和模型标识共同驱动布局测量；像素宽度归属当前组件生命周期，模型偏好持久化业务标识与显示名称。启动阶段在 `useLayoutEffect` 中完成静态测量与校正，用户主动切换模型时执行宽度过渡。
- 本地偏好保存在 Renderer 的界面存储，ProviderStore、提供商配置和项目历史分别维护各自的数据。Main 继续负责提供商、模型目录和加密凭据；App 负责提交 Composer 构造的运行请求。
- 位置：内部操作带右侧，单一操作按钮左侧。
- 宽度：按钮自适应，宽度完全由名称文字与水平间距构成（左右边距各8px，名称与展开指示之间12px，展开指示15px），名称按自然宽度完整显示，同一行剩余空间不足时单行省略；启动时按当前字体测量宽度，窗口可用空间不足时由当前布局约束截断。用户主动切换模型后，按钮只为这次名称变化执行一次文本测量，并在180ms内平滑过渡到新宽度；布局校正保持当前模型业务状态。
- 尺寸：高度28px，圆角14px，文字14px、行高22px。
- 材料：默认透明背景和主要阅读文字颜色；悬停、聚焦与打开时使用气泡表面颜色和主要文字颜色。
- 文字：当前模型名称水平居中，使用正文字型（SF Pro Text／苹方，14px，字重400），颜色与模型消息正文一致（主要阅读文字颜色）；展开指示（chevron-right 15px）与名称间距12px、参与布局排位；收起时指向右，展开后顺时针旋转90度指向下，名称过长时单行省略。
- 共享结构：模型、Appearance 与 Language 共用 `frontend/src/shared/ui/Select.tsx` 和 `Select.css`，展开、关闭、选项、选中标记与箭头样式由共享控件维护；Composer 保留模型目录、选择偏好和名称宽度动画，通过紧凑尺寸、上方展开、响应式对齐与局部样式配置模型菜单。
- 加载态：有有效名称偏好时，模型目录读取期间直接显示缓存的模型名称并保持禁用；缓存为空时显示读取模型…并保持禁用。目录读取完成后显示已校验的模型名称或选择模型。
- 空态：未选择模型时显示选择模型。
- 显示范围：按钮呈现当前模型名称与展开指示，提供商名称、Model ID、API Base URL 和其他连接元数据由提供商设置管理。
- 交互：在用户触发按钮后打开模型面板并更新 aria expanded。选择其他模型后关闭面板，将焦点返回模型选择按钮，更新 Composer 的 `selectedModelOptionId`，立即写入模型选择偏好；按钮按新名称完成宽度测量，名称偏好跟随目录确认结果保存，并更新下一次运行使用的 `modelOptionId`。重新选择当前模型沿用现有宽度与布局。
- 运行期间：禁用。

模型选择面板。

- 位置：直接位于模型选择按钮上方，与按钮间距8px；视口宽度大于700px时使用250px宽度并与按钮中心对齐，700px及以下使用220px宽度并沿按钮右侧对齐。
- 材料：主要表面颜色，4px内边距，16px圆角，通用边界，中等阴影。
- 动画：以右下角为变换原点，通过4px向下位移，轻微缩放和透明度变化完成150ms展开动画。
- 尺寸：条目最小高度28px，面板最大高度300px，超出内容在内部滚动，相邻条目间距为0；当前选中条目在名称右侧显示 check 标记。
- 空状态：模型目录为空时显示添加可用模型的空状态提示。
- 键盘：触发器使用 combobox 语义，面板使用 listbox 语义，条目使用 option 语义并提供选中状态；焦点保留在触发器，Arrow Down 和 Arrow Up 移动活动选项，Home 和 End 跳转到首尾，Enter 或 Space 确认选择，Tab 按方向移交焦点并关闭菜单。
- 关闭：Esc 关闭面板并把焦点返回模型选择按钮，点击模型选择区域外部关闭面板。
- 内容：只渲染最近一次模型拉取返回且当前凭据可用的模型。

模型条目。

- 尺寸：最小高度28px，水平内边距4px，圆角16px，宽度占满面板内容区。
- 材料：默认透明背景和次要文字颜色；悬停或聚焦时使用次级表面颜色，名称在悬停或选中时切换为主要文字颜色。
- 文字：名称使用正文字型（14px，行高22px，字重400），单行省略。
- 布局：名称位于条目左侧，选中标记位于右侧，两端对齐；条目高度28px，水平内边距4px，圆角16px。
- 热区：条目默认保持透明；鼠标悬停或键盘聚焦时显示 `surface-secondary` 圆角背景，文字切换为主要文字颜色。
- 选中标记：check 图标16px，使用主要文字颜色，仅当前选中条目显示。
- 间距：相邻条目间距为0。

运行中输入实现。

- 范围：运行中的 `steer` 载荷为文本消息；项目、模型、附件和画布选择沿用本次运行捕获的配置。运行期间项目选择、模型选择、文件上传、附件移除和画布引用操作保持锁定。
- 发送：Composer 在点击或按 Enter 时捕获文本快照、`activeRunId` 和 `projectId`，为每次发送生成独立 `inputId`，经 Preload 调用 Main 的 `steer` IPC。两次连续发送产生两份快照与两个 `inputId`。
- 确认：Main 校验运行归属并持久化待处理文本后返回 ACK。ACK 表示输入已绑定当前 run；Renderer 随即在消息流显示普通用户气泡。当前模型和工具继续执行，实际进入模型上下文由安全边界的 `inputsApplied` 事件确认。
- 顺序：多个 ACK 按 Main 的接收顺序展示为独立气泡；当前助手和工具过程在原消息块中继续更新，新的模型输出显示在补充气泡下方。
- 可编辑性：活动 run 的 textarea 与操作按钮可用；单次提交等待 ACK 时，Composer 保持草稿并显示忙碌状态；`activeRunId` 确定后，按钮根据草稿内容提供中断或 steering。停止过程中 textarea 保留草稿，按钮呈现中断忙碌状态。

单一发送／中断按钮。

- 位置：按钮始终位于内部操作带右下角；模型选择按钮位于左侧，间距7px。
- 结构：同一个 `<button>` 节点持续挂载，图标、视觉状态、无障碍名称、Tooltip 和点击动作由统一的按钮模式派生。热区、焦点与键盘操作位置保持稳定。
- 尺寸：圆形热区28乘28px；发送箭头和中断图标均以18px SVG 渲染。中断图标沿用24px viewBox 内的11乘11方形路径，18px SVG 下渲染为8.25px。
- 材料：两种模式沿用同一个主要文字颜色背景；发送箭头与中断方形均使用白色。图标在同一按钮内完成120ms淡入切换。
- 模式：空闲时按钮呈现发送；活动 run 且草稿为空时呈现中断；活动 run 且草稿含有效文字时呈现发送。启动确认期间保持发送忙碌状态，文本提交确认期间保持发送忙碌状态，停止处理中保持中断忙碌状态。
- 行为：空闲发送启动 `RunRequest`，运行中发送提交 `steer` 文本，中断模式取消当前 run。steering ACK 成功后清空本次草稿，按钮随即恢复中断模式。
- 焦点：鼠标点击发送并收到 ACK 后，焦点回到 textarea；键盘连续输入在输入框继续进行，按钮状态切换保持原有热区。
- 反馈：悬停时亮度降低为百分之九十，按下状态在80ms内缩放到原尺寸的百分之九十四；发送条件等待时透明度为百分之三十八，中断请求处理中透明度为百分之七十二。
- 发送条件：初始任务需要有效文字或已准备好的附件、可用模型和已完成的历史加载；运行中补充输入需要非空文本、已确认的 `activeRunId` 和可接收输入的活动 run。

运行期间状态。

- 定义：运行期间覆盖启动、运行和停止过程，当前 run 保持固定的项目、工作目录、模型、附件与画布选区配置。
- 可用的控件：任务输入框在活动 run 中保持可编辑；操作按钮在空草稿时提供中断，在有效文本草稿时提供 steering 发送。
- 锁定的控件：项目选择、文件上传、附件移除和模型选择保持本次运行配置，语音入口呈现禁用状态。停止处理中发送按钮等待终态，输入框保留草稿。
- 恢复：运行终态到达后，操作按钮恢复初始任务发送语义，其他控件恢复正常操作，已产生的消息和工具活动继续保留。
- 提示文字：任务文本非空而当前模型处于失效状态时，发送按钮保持禁用，Composer 保留任务文本，外壳底部左侧显示提示文字。
- 提示规格：10px文字，危险操作颜色，内容为请选择可用模型。
