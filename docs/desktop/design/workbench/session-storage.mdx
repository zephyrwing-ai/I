会话存储装配。

Main 生命周期。

- Main 在应用就绪时使用 `app.getPath("userData")` 生成会话数据库路径，并创建一个 `SqliteSessionRepository`。
- Repository 使用 Electron 内嵌 Node 提供的 `node:sqlite`，数据库连接保持在 Main 进程。
- Main 的会话路由在每次运行前返回一个确定的 `sessionId`。
- Runner 使用该 `sessionId` 创建或取得 `SessionRecorder`，并把 Recorder 与运行事件接收器注入 Runtime。
- Main 在应用退出阶段先请求 Runner 取消当前运行并等待其进入空闲，再等待 Recorder 刷新活动草稿并关闭数据库连接。

Runner 注入。

- Runner 为一次运行创建 `runId`，接收会话路由提供的 `sessionId`，并取得该会话的 Recorder。
- Recorder 通过方法接收消息和增量，运行事件接收器通过回调接收 AgentEvent；二者采用主动推送接口。
- Runtime 是 Recorder 和 AgentEvent 的调用方。Runner 创建并注入两种接收器，同时负责把 AgentEvent 转发到 IPC。
- Recorder 维护私有的消息快照、活动草稿和 SQLite 写入队列。
- Renderer 维护私有的 AgentEvent 数组队列，并在动画帧中把队列事件交给 Reducer。
- Recorder 与 Renderer 使用各自的数据结构，通过 `runId`、`turnId`、`toolCallId` 和冻结事件值保持关联。

流式事件链路。

```text
Provider Adapter
  → Runtime 接收 delta
      → SessionRecorder 更新内存草稿并调度 SQLite 刷新
      → AgentEvents 发出 reasoningDelta 或 assistantDelta
          → Runner emit
              → Main IPC
                  → Renderer eventQueue
                      → agentReducer
```

- Recorder 的草稿更新和 Renderer 的流式渲染共享同一个 Runtime delta 来源。
- Recorder 的500毫秒或4096字节刷新策略影响 SQLite 写入节奏。
- Renderer 按动画帧批处理事件，并保持现有流式渲染节奏。
- 模型完成时，Runtime 等待 Recorder 提交完整 Assistant Message，随后发出 `assistantCompleted`。
- 工具完成时，Runtime 等待 Recorder 提交完整 Tool Message，随后发出 `toolCompleted`。
- 运行终态由 Recorder 完成草稿刷新后进入 IPC 事件流。

IPC 边界。

- AgentEvent 延续现有 `agent:event` 通道。
- 会话写入通过 Main 内的直接对象调用完成。
- Renderer 通过 AgentEvent 接收实时过程，通过 `session:load-page` 接收持久化页面数据。
- 本地存储接入保持现有 Composer 提交字段和消息流事件格式。

历史页面读取与虚拟渲染。

- Main 在应用就绪阶段持有 active `sessionId`；Renderer 启动后先注册 AgentEvent，再通过 Preload 调用 `loadSessionPage({ cursor: null, limit: 100 })`。
- `session:load-page` 进入 Main 的历史读取服务，历史服务校验 active session、cursor 和 limit，调用 Repository 读取最新一页 entries，返回 `entries`、`nextCursor`、`hasMore` 和 `snapshotSeq`。
- Main 将 SQLite 倒序查询结果恢复为 `sessionSeq` 升序后返回 Renderer。Renderer 保存历史页和游标状态，并通过历史投影转换为 `RunState`、`TurnState` 和 `ToolState`。
- `user_message` 创建 RunState 并使用 entry 的 `createdAt` 作为用户消息时间；`assistant_message` 提供正文、`updatedAt` 映射为 TurnState 的 `assistantAt`、reasoning 和 toolCalls；`tool_result` 通过 toolCallId 关联工具状态。折叠摘要和展开状态由 Renderer 生成，SessionRecorder 继续保存完整事实。
- 用户向上滚动接近历史顶部时，Renderer 使用 `nextCursor` 请求更早的一页。返回记录插入历史缓存前面，投影层只处理新增记录，滚动锚点通过新增内容高度差保持稳定。
- MessageStream 直接重构为虚拟渲染消息流。历史缓存保存已加载的页面，MessageStream 只挂载视口附近的可见块和 overscan 块，并使用上下占位维持完整滚动高度。
- 历史恢复期间到达的实时 AgentEvent 进入 Renderer 缓冲队列；历史 hydrate 完成后按原顺序回放，历史数据和实时运行共同进入现有 agentReducer 与 MessageStream。
- 历史分页、历史投影和虚拟渲染属于 Desktop/Renderer 历史交付，Agent Runtime、Provider Adapter、SessionRecorder 和工具执行契约保持原有职责。
- 分页 DTO、hydrate 状态、投影合并与实时事件竞态以[历史投影](./history-projection.mdx)为准；虚拟窗口和动态高度以[消息流](./message-stream.mdx)为准。

Main 历史服务。

- `shell/main/session-history.ts` 接收 active sessionId 和 Repository，通过 `loadPage(cursor, limit)` 返回页面 DTO。
- `cursor=null` 表示读取会话尾部最新一页；非空 cursor 表示读取该稳定边界之前的记录。
- 历史服务限制页大小、拒绝未知 session、合并相同 cursor 的在途请求，并阻止重复 cursor 形成循环。
- Repository 负责 SQLite 顺序查询，历史服务负责协议 DTO 和游标状态；两层都不生成 RunState 或页面折叠内容。

IPC 契约。

- `SessionPageRequest` 携带 `cursor` 和有上限的 `limit`。
- `SessionPageResult` 携带 active `sessionId`、正序 entries、`nextCursor`、`hasMore` 和 `snapshotSeq`。
- Preload 只暴露 `loadSessionPage()`；Renderer 无法取得数据库路径、Repository 或任意 sessionId 查询能力。
- IPC 读取失败返回结构化错误，Renderer 保留原 cursor 并提供重试。

错误收敛。

- 用户消息提交失败时，Runner 返回运行失败并保留 Composer 已有错误呈现路径。
- Assistant Message 提交失败时，Runtime 结束本次运行并跳过工具执行。
- Tool Message 提交失败时，Runtime 结束本次运行并跳过下一次模型请求。
- 草稿定时刷新失败时，Recorder 保存失败状态，终态提交读取该状态并把运行收敛为失败。
- 数据库初始化失败时，Main 启动装配流程报告初始化错误并停止创建工作台，避免在存储不可用时启动无持久化运行。

实现入口。

- `shell/main/index.ts` 创建和关闭 Repository。
- `shell/main/session-history.ts` 提供 active session 的游标分页读取。
- `shell/main/runner.ts` 取得 SessionRecorder、注入 Runtime、转发 AgentEvent，并在退出时提供运行空闲屏障。
- `agent/memory/session-recorder.ts` 提供会话 Recorder 与缓存，Main 负责创建并注入。
- `shell/shared/ipc.ts` 同时定义实时 AgentEvent 和只读历史分页契约。
- `frontend/src/App.tsx` 保持现有 `eventQueue`，并协调首次 hydrate 与实时事件回放。
