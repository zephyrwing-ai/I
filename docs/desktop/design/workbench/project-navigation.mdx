项目导航。

- 位置：导航轨道位于应用外壳左侧，项目列表位于工作台内框左侧，并与内框消息主列和右侧工作侧栏水平并列。
- 入口：导航栏提供 `I`、`Project` 和 `Settings` 三个入口；`I` 与 `Project` 以图标和名称组成可点击区域，Settings 以齿轮图标单独呈现。
- 视图模式：同一 App 使用 `selectedView` 区分 `ordinary` 与 `projects`，导航选中态、标题分隔线与项目开合入口共同读取这一状态；列表展开状态和活动 `projectId` 分别管理。
- 尺寸：导航轨道实际宽度为 `calc(var(--project-navigation-width) + var(--workbench-frame-gap))`，当前为56px加8px，共64px；导航轨道、内框留白和项目列表宽度读取[设计令牌](./tokens.mdx)，项目列表按展开状态参与内框列宽分配。
- 横向对齐：导航轨道采用 `border-box`，横向 padding 为 `--workbench-frame-gap`，当前每侧8px；按钮横向填满48px内容区，左边缘距窗口左边8px，右边缘距 `workbench-frame` 左边8px。
- 范围：`I` 对应 `projectId = NULL` 的普通对话；项目列表条目对应真实项目的稳定 `projectId`。
- 启动：应用打开普通历史范围，导航选中 `I`；消息区沿用现有首屏历史加载流程。
- 视觉：导航使用外壳表面，项目列表与标题栏使用内框表面，浅色边框和柔和阴影共同形成抬升层次；文字、图标、悬停、选中和键盘焦点沿用[设计令牌](./tokens.mdx)。
- 入口反馈：`I`、`Project` 和 `Settings` 的悬停与选中背景共同使用 `--hover`，与右上角按钮的悬停和激活反馈保持相同轻重；项目列表条目继续使用选中背景标记当前项目。

设置入口。

- 位置：左侧导航轨道底部，使用自动剩余空间将入口推至底部并与导航轨道保持统一内边距。
- 图标：入口单独显示22px的 settings 齿轮图标，Tooltip 与 `aria-label` 均保留 `Settings` 名称。
- 交互：点击后进入完整接管窗口的[Settings 页面](./titlebar/sidebar/settings.mdx)，`aria-expanded` 与页面开合状态保持同步；左侧显示 Back、General、Providers、Usage、TTS，右侧显示当前模块。
- 展示：Settings 打开期间，原项目导航、工作台及其浮层退出视觉展示、指针命中、键盘访问和原生拖拽热区；工作台组件继续挂载，历史、Composer 草稿和 Canvas 场景保留当前状态。
- 拖拽：Settings 使用顶端独立窗口拖拽带，Back 和模块按钮位于下方的 `no-drag` 内容区；页面沿用现有字体、颜色和几何 token。
- 焦点：Settings 打开后焦点进入 Back；Back 恢复工作台展示与交互后，焦点返回左下 Settings 入口。

普通对话入口。

- 标识：图标使用应用标识内部的矢量符号，透明底与文字共同继承导航颜色，名称显示为 `I`，选中时采用导航选中态。
- 交互：成功激活普通历史范围后进入 `ordinary` 模式，收起项目列表栏；范围切换通过 `clearProject()` 与 `history.reload(null)` 恢复普通对话。
- 标题：普通模式的标题栏与消息区呈现连续表面，标题栏保留右侧输出、Canvas 和搜索入口，设置入口位于左侧导航底部。
- 历史：普通范围沿用原有连续历史，用户继续在同一个 Composer 中发送消息。

项目入口与列表。

- 展开：点击 `Project` 进入 `projects` 模式并展开紧邻导航栏的项目列表栏，项目开合入口随模式呈现；消息区保持当前历史范围，用户选择项目条目后进入对应项目对话。
- 模式保持：浏览项目列表、收起列表和等待项目选择期间继续保持 `projects` 模式，活动历史范围沿用当前 `projectId`。
- 标题：项目列表顶部显示 `Projects`，右侧依次提供 `＋` 添加项目按钮和收起按钮；标题区域与列表正文共同位于内框。
- 数据：首次展开时通过 `listProjects()` 读取已登记项目，按 `pinned DESC, created_at ASC, id ASC` 稳定排列；列表读取仅取得项目元数据。
- 缓存：Renderer 保存项目列表及 `loaded`、`loading`、`error` 状态，再次展开、收起和切换项目沿用已取得的列表；页面重新加载后从 Main 恢复项目元数据。
- 请求：同一列表读取期间共享在途请求，结果通过请求身份提交；读取失败保留既有列表，重试重新发起列表读取。
- 更新：添加成功后读取一次最新列表；置顶、改名和删除成功后使用 Main 返回的列表替换前端缓存；目录定位和取消操作沿用既有缓存。
- 顺序：置顶项目排在前面，同组按登记时间和稳定 ID 排列；项目激活更新 `lastOpenedAt`，条目保持该排序位置。
- 条目：显示项目名称，完整规范路径通过 Tooltip 提供；重名项目通过路径区分，点击操作使用稳定 `projectId`。
- 选中：列表条目以当前活动 `projectId` 标记选中态；导航入口的展开状态与当前对话范围分别维护。
- 列表滚动：项目较多时在列表栏内独立滚动，列表开合保留自身滚动位置，消息流保持自己的滚动位置。
- 空态：项目列表为空时提供添加项目提示，并保留顶部 `＋` 入口。
- 选择：点击已有项目调用 `activateProject(projectId)`，Main 校验项目目录并准备对应历史与项目上下文，Renderer 接收项目描述后调用 `history.reload(projectId)`。
- 重复选择：再次点击当前活动项目保持当前对话、已加载历史和滚动位置。

列表开合。

- 状态：列表展开状态独立于视图模式、活动项目和运行状态，工作台显示期间外壳左侧导航持续保留；`I` 入口进入普通模式并收起列表，`Project` 入口进入项目模式并展开列表，标题按钮与边界拖拽使用同一个开合状态。
- 持续入口：`projects-sidebar-toggle` 随 `projects` 模式呈现，并由列表展开状态确定位置；展开时位于项目标题的 `＋` 右侧并显示 `Hide projects`，收起时位于内框主标题栏左端并显示 `Show projects`。当前入口使用侧栏按钮样式，`aria-expanded` 和 `aria-controls` 共同描述列表状态。
- 动画：列表占用宽度在当前有效宽度与0之间以180ms过渡，消息主列随剩余空间同步重排；指针调整宽度时直接跟随，减少动态效果偏好使用即时切换。
- 隐藏：收起后的列表通过 `visibility: hidden` 退出原生命中与拖拽区域，使用 `inert` 与 `aria-hidden` 隔离键盘和辅助技术访问；开合按钮切换位置时，操作焦点跟随当前可见入口。
- 保留：列表组件在开合期间保留已有条目和滚动位置，当前项目身份、聊天记录和 Canvas 场景继续沿用原范围。
- 运行：模型运行期间列表开合保持可用，项目选择、添加和菜单修改继续使用原有空闲门控。

项目列表宽度。

- 几何：壳体通过自身实际宽度参与内框第一列布局，内框使用自动列宽接纳开合与拖拽结果；默认宽度、最小宽度与交互步进由[设计令牌](./tokens.mdx)定义。
- 可用空间：Projects 壳体与消息主列的实测宽度之和构成局部可用宽度，右侧工作侧栏保留自己的占用；项目列表有效最大宽度按该可用宽度减去消息主列最小宽度计算。
- 偏好：已确认宽度写入 `workbench.projectsSidebarWidth`；窗口缩小时使用受可用空间约束的有效宽度，空间恢复后继续使用用户偏好。
- 拖拽条：位于项目列表与消息主列之间，提供8px热区与1px可见边界；默认线和强调反馈读取侧栏拖拽共享令牌，向右增大项目列表宽度，向左缩小，布局宽度按动画帧更新。
- 消息重排：宽度变化由既有 ResizeObserver 更新消息块测量和虚拟布局，已加载历史、稳定 blockId、搜索结果与滚动锚点继续沿用当前范围。
- 收起阈值：原始拖拽宽度小于或等于最小宽度减48px时显示待收起状态，松开后进入关闭流程，宽度偏好保留拖拽前的确认值。
- 取消：拖拽期间按 Escape 恢复拖拽前的宽度，持久偏好沿用原值。
- 恢复默认：双击拖拽条恢复默认宽度，实际显示宽度继续受局部可用空间约束。
- 键盘：Arrow Left 缩小、Arrow Right 增大，基础步进16px，Shift 步进64px；在最小宽度继续向左调整时收起列表，确认后的调整写入本机偏好。
- 无障碍：拖拽条提供纵向 separator 语义，暴露当前有效宽度、最小宽度和实时最大宽度；列表收起后退出键盘导航。

项目菜单。

- 打开：右键项目条目展示操作菜单，菜单锚定点击位置并限制在窗口可见范围内；点击菜单外部或按 Escape 关闭菜单。
- 尺寸：菜单宽200px、内边距4px；条目字号13px、行高18px、字重400，最小高度28px、内边距4px 8px，图标16px，图文间距8px。
- 置顶：`Pin` 将项目的 `pinned` 保存为 `true`，已置顶条目显示 `Unpin`，执行后保存为 `false`；项目列表使用返回的元数据更新顺序。
- 定位：`Reveal in Finder` 由 Main 定位该项目的规范目录路径，活动项目和聊天历史保持原范围。
- 改名：`Rename session` 在条目内编辑显示名称，提交后更新 `displayName`；名称去除首尾空白后使用1至200个字符，`projectId`、规范路径和磁盘文件夹保持原值。
- 删除：`Delete session` 由 Main 展示系统确认框，确认后清理应用内的项目记录、聊天历史及关联运行记录；项目文件夹和其中的用户文件继续保留。
- 活动项目：删除当前活动项目后激活 `projectId = NULL`，Renderer 按普通历史范围恢复消息和 Canvas 路由；删除其他项目时保持当前对话。
- 取消：取消改名或删除确认时保持既有项目名称、列表和活动范围。
- 状态：菜单操作沿用项目操作的空闲门控和错误重试反馈，进行中的操作使用统一禁用状态。

添加项目。

- 入口：添加按钮位于项目列表标题右侧，图标使用 `plus`，Tooltip 与无障碍名称为 `Add project`。
- 操作反馈：添加过程中持续显示加号，通过禁用状态与 `aria-busy` 表达操作占用；项目条目在切换过程中保留名称和置顶标记，以 `aria-busy` 表达加载状态。
- 交互：点击后复用 `selectProject()` 打开系统目录选择器；Main 规范化目录路径，已有目录沿用原项目身份，新目录创建项目记录。
- 成功：添加完成后刷新项目列表，选中新项目，并进入同一项目激活与历史加载流程。
- 取消：用户取消目录选择时保持原有活动项目、历史页面与 Canvas 场景。
- 反馈：读取列表或添加项目失败时，在项目列表栏显示错误和对应重试入口，已显示的对话继续保留。

切换与加载。

- 调度：App 统一协调普通入口、项目条目和添加项目后的范围切换，Main 统一管理活动项目。
- 准备：切换先等待当前 Canvas 的 `flush()` 成功，再激活目标项目；激活失败保留原活动项目和 Canvas 文档。
- 提交：激活成功后更新项目描述，清理前一项目的 Canvas 引用与语音请求，按新项目预加载 Canvas 文档，并调用 `history.reload(projectId)`。
- 历史：项目范围与请求代次继续约束首页、旧页分页和搜索结果，历史投影与 MessageStream 虚拟窗口沿用[历史投影](./history-projection.mdx)和[消息流](./message-stream.mdx)的规则。
- 加载期间：项目入口保持可操作，后续选择取代前一次在途历史加载，页面接纳最新目标范围的结果。
- 运行期间：普通入口、项目激活、添加项目和项目菜单操作处于禁用状态，项目列表开合保持可用；当前 run 使用启动时捕获的项目、工作目录与上下文。
- 布局重排：项目列表展开占据内框左侧列宽，消息内容与 Composer 在剩余消息主列内共用最大760px的居中布局；右侧工作侧栏按内框扣除项目列表后的可用宽度约束尺寸。
- 标题区：主标题栏与项目标题共同位于内框标题行，项目列跨越标题与内容两行；导航、添加、列表开合和菜单操作使用各自的可点击热区，消息滚动条使用标题行下方的局部视口尺寸与边界。
- 表面：项目标题与项目列表共同使用连续的 `--workbench-frame-surface`，标题下方保持同色表面；项目列表右侧使用1px `--workbench-boundary` 与消息区区分，内框外边缘和右侧工作侧栏边缘继续使用工作台分隔颜色。

代码衔接。

- 左侧组件：`frontend/src/workbench/navigation/ProjectNavigation.tsx` 提供外壳导航入口，`frontend/src/workbench/project/ProjectsPanel.tsx` 提供内框项目列表、添加与收起按钮、开合展示、操作菜单和名称编辑；`frontend/src/workbench/titlebar/TopBar.tsx` 在项目模式且列表收起时提供展开入口，两个位置共用 `frontend/src/workbench/project/ProjectSidebarToggle.tsx` 的开合按钮契约。
- 元数据缓存：`frontend/src/workbench/project/useProjects.ts` 统一保存项目列表、加载状态、错误、在途请求和结果代次，首次读取与添加后的刷新通过同一请求链路执行，项目修改结果通过同一缓存提交入口接纳。
- 宽度交互：`frontend/src/shared/sidebar/useResizableSidebar.ts` 为项目列表与右侧工作侧栏提供共同的指针、键盘、阈值收起和宽度偏好交互，`frontend/src/shared/sidebar/sidebarGeometry.ts` 提供共享宽度计算；项目列表从 `frontend/src/workbench/project/projectSidebarState.ts` 取得 `PROJECTS_SIDEBAR_POLICY`，传入左侧方向、局部可用宽度与对应偏好键。
- 页面协调：`frontend/src/App.tsx` 组合外层导航、含标题栏与内容区的工作台内框、全局浮层及 Settings 页面，分别持有视图模式、列表展开状态、活动项目描述和切换请求身份，调用项目元数据缓存及已有历史与 Canvas 链路；Settings 接管窗口时保持工作台挂载并切换展示与交互状态，菜单操作接收 Main 返回的活动项目与可选列表，历史范围变化时调用历史重载。
- Main：`shell/main/project-registry.ts` 统一目录登记、按 ID 激活和项目元数据更新；`shell/main/index.ts` 注册项目操作 IPC，执行 Finder 定位、删除确认与 Recorder 生命周期协调。
- 桥接：`shell/shared/ipc.ts` 和 `shell/preload/index.ts` 提供受限项目操作，具体契约见[历史存储装配](./session-storage.mdx)。
- Composer：接收活动项目描述并在 Run、Steer 和语音请求中继续使用对应范围，输入区规则见[Composer](./composer.mdx)。
