消息流。

消息流区域。

- 容器：消息主列位于工作台内框中间的内容行，主列高度由内框扣除标题行后的剩余空间确定；`scrollRef` 继续指向 `.stream-scroll`，消息内容在该局部视口中独立滚动。
- 区域内边距：仅保留上下各30px的垂直间距，水平内边距为0；内容列与 Composer 共用最大760px宽度。
- 内容列最大宽度：760px，水平居中。
- 空状态：历史加载完成且消息列表为空时，主列在内框消息区顶边与 Composer 上缘之间居中显示 `What can I do for you ?`；文字使用 20px、400 字重和纯黑色。当前范围由左侧 `I` 入口或项目列表选中条目标识，Composer 继续提供任务输入。

历史投影与虚拟渲染。

- MessageStream 接收统一的 AgentState，历史恢复和实时运行使用同一套 RunState、TurnState 和 ToolState。
- 历史投影负责把 HistoryPageEntry 转换为页面状态，并向 MessageStream 提供当前 `projectId: string | null` 与历史就绪状态。
- `projectId` 标识一份独立的消息流作用域；`null` 标识无项目历史。MessageStream 将该作用域作为虚拟窗口缓存、测量结果和滚动跟随状态的生命周期边界。
- MessageStream 始终使用虚拟窗口：根据 scrollTop、viewportHeight 和已测量消息高度计算 visibleRange，并渲染可见消息与 overscan 消息。
- 虚拟窗口前后使用占位高度保持完整滚动范围；历史缓存可以包含多页消息，DOM 只挂载当前可见区域附近的消息。
- 阅读锚点由虚拟窗口统一持有：用户滚动时记录首个可见 `blockId` 及其视口像素偏移，历史消息从顶部追加时先用新布局计算该锚点对应的可见范围，再在首帧绘制前瞬时恢复位置；读取期间继续滚动时，锚点跟随当前阅读位置更新。
- 高度补偿：ResizeObserver 将首次估算、正文增长、折叠和宽度重排产生的真实尺寸写入布局缓存，同一锚点恢复流程根据更新后的块位置消化尺寸差值。助手块末尾28px间距计入被测块的内边距，布局累计尺寸与 DOM 占用高度保持一致。
- 坐标归属：锚点定位使用消息根节点在滚动内容中的布局起点，统一计入上方留白与提示区域；消息块相对根节点的位置抵消共有弹性位移。虚拟窗口管理滚动锚定，自身定位事件沿用既有锚点，用户滚动事件更新阅读锚点与底部跟随状态。
- 首次历史加载、项目切换和历史重新 hydrate 使用明确的历史切换策略；新范围首轮布局完成后，虚拟窗口瞬时定位到底部，随后实时 AgentEvent 按底部跟随规则更新同一 AgentState。
- 展开状态：活动组、组内工具组与单条工具详情使用 Renderer 组件的本地视图状态，稳定 blockId、turnId 与 toolCallId 关联挂载期间的交互；虚拟重挂载时按恢复的运行与工具阶段建立默认值。原生 `content`、原始 reasoning、toolCalls、tool_result 与历史 `progress` 由项目历史存储提供。
- 分页、hydrate 和实时事件合并以[历史投影](./history-projection.mdx)为准。

项目范围切换与虚拟窗口生命周期。

- 历史作用域以 `projectId` 标识；项目切换和进入无项目历史都产生新的作用域。
- 历史控制器开始加载目标作用域时，AgentState 同步切换到目标 `projectId`、清空旧范围的消息投影并标记为加载中。消息流在新页面返回前呈现空状态或加载状态，当前展示范围始终与目标项目一致。
- MessageStream 收到新的 `projectId` 或历史替换代次后重置该作用域的 `measuredHeights`、已提交窗口、阅读锚点、分页在途标记、搜索定位序号、视口快照和 `stickToBottom`。新范围从消息估算高度建立虚拟布局，ResizeObserver 再逐块写入真实高度并更新累计尺寸。
- 布局重建同时把首屏可见范围初始化到新消息序列末端。首轮 DOM 提交后，虚拟窗口根据最新 `scrollHeight - clientHeight` 设置实际 `scrollTop`；真实高度随后变化时，底部跟随状态继续修正到底部，让首屏直接呈现最新消息位置。
- 空历史范围显示空状态，滚动位置归零；有历史记录时定位到最新消息。两种结果都由当前作用域的 hydrate 完成事件决定。
- 每次历史读取绑定发起时的作用域和请求代次。响应只有在作用域及代次仍与当前页面一致时才进入 Reducer；旧项目的迟到响应按过期请求处理。
- 同一作用域的旧页分页保留首个可见 block 锚点；同一作用域的重新 hydrate 建立新的首屏布局并定位到底部；实时追加遵循当前 `stickToBottom` 状态；搜索定位按 `blockId` 居中目标块。
- 搜索目标与历史加载代次随作用域更新。切换后清除旧范围的活动搜索定位，再使用新范围的完整 MessageBlock 序列生成结果。

虚拟窗口数据模型。

- `RunState.timeline` 按 entry 与 AgentEvent 的顺序保存用户输入和助手 turn；MessageBlock 根据时间线投影为用户消息、活动组和最终助手回复。
- 用户消息块使用 `inputId` 作为稳定 `blockId`；活动组使用 `runId + anchorInputId` 作为稳定 `blockId`。`anchorInputId` 标识该组开始前最后一条已应用的用户输入，并服务虚拟窗口、高度缓存和搜索定位。
- `RunState.appliedInputId` 保存当前模型上下文的输入边界；每个 turn 在建立时将该边界捕获为固定的 `anchorInputId`。活动组由回合锚点组织，并位于对应用户输入之后；待应用消息与实际执行上下文分别表达。
- 一个活动组可以包含多个 `turnId` 及其工具调用；模型回合身份继续用于事件关联和状态更新，消息块身份服务阅读流、搜索与虚拟布局。
- MessageBlock 以用户消息和助手活动组两类记录表达阅读流。用户记录保存 `inputId` 和用户正文；助手记录保存 `anchorInputId`、`turnIds`、`answerTurnId`、计时归属与回答正文。
- 搜索文本：用户正文与各助手活动组在折叠外呈现的回答正文提供索引内容，渲染与搜索复用同一 `answerTurnId` 和文本字段。活跃组回答由 `finalTurnId` 确认，已应用 steer 后的前组沿用已提交的无工具回答身份；流式正文、工具活动与兼容过程字段按 `turnIds` 归入所属活动详情，原始 reasoning 由数据层保留。
- 每个 MessageBlock 保存估算高度和已测量高度；首次布局使用估算值，ResizeObserver 返回真实高度后只更新受影响区间的累计高度。
- 侧边栏拖拽改变主列宽度时，已挂载 MessageBlock 的宽度变化由同一组 ResizeObserver 捕获；正文与 Markdown 围栏代码按可用宽度折行后产生的新高度进入既有高度缓存和虚拟布局计算，MessageStream 继续复用原有渲染、测量与锚点修正流程。
- 主列内容宽度大于内容列上限时，消息内容列宽度保持稳定，侧边栏拖拽只改变外部剩余空间；主列内容宽度进入内容列上限以下后，宽度变化触发已挂载块重新测量。
- 可见范围通过 scrollTop、viewportHeight 和累计高度索引计算；overscan 在视口上下各保留一段内容，覆盖快速滚动和动态高度误差。
- 视口尺寸由 `.stream-scroll.clientHeight` 与局部元素几何提供；内框留白、窗口缩放和侧栏开合通过既有 ResizeObserver 更新虚拟布局、滑块与锚点位置。
- DOM 结构固定为顶部 spacer、可见 MessageBlock 和底部 spacer，两个 spacer 共同表示未挂载内容的总高度。
- 当前流式 Assistant Message 保持在虚拟窗口中；增量改变高度时更新测量缓存，并在用户停留底部时保持吸底。

分页触发与滚动锚点。

- MessageStream 接近顶部阈值时调用 `onLoadOlder`，请求状态和 cursor 由历史 hook 管理。
- 旧页面插入前记录第一个可见 blockId 及其视口偏移；插入和测量完成后恢复同一 blockId 的偏移。估算高度、真实高度和块间距都属于虚拟布局尺寸，外部 CSS margin 同步计入布局模型。
- loadingOlder 期间显示保持布局高度稳定的顶部加载状态，并锁定本次加载入口。
- hasMore=false 时顶部进入正常弹性边界；hasMore=true 时历史加载先于“已经到达完整历史开头”的语义。
- 历史请求失败保留当前列表和锚点，顶部状态提供重试，已加载页面继续保留。

折叠与动态高度。

- 展开依据：Run 活动组与组内工具组使用运行、回合和工具状态派生默认展开值，Renderer 本地状态保存当前工作或结算阶段的手动覆盖；阶段变化后采用新的默认值，历史 hydrate 按恢复的状态建立相同默认值。
- 高度更新：活动组和工具组展开、过程说明与正文流式更新共同改变 MessageBlock 高度，ResizeObserver 更新高度缓存并保持当前锚点。
- 主列宽度变化引起的文本换行使用相同的高度测量路径；侧边栏拖拽保持已加载 AgentState、blockId、搜索索引和历史 cursor。
- 数据恢复：原生 content、原始 reasoning、toolCalls、tool_result 与兼容 progress 由项目历史存储提供，虚拟渲染沿用所属字段的保存和恢复规则。

搜索边界。

- AgentState 是 Renderer 已加载项目历史范围内容的内存状态，MessageBlock 是由该状态派生的完整虚拟消息序列，DOM 承载当前可见范围。搜索覆盖完整 MessageBlock 序列。
- 索引范围：搜索以 MessageBlock 为定位单位，索引各条用户正文与折叠外的模型回答；回答身份包括运行完成确认的最终回合及已应用 steer 结束前组后保留的已提交无工具回答。每个含索引正文的消息块汇总为一行结果。
- 索引更新：活跃组的工具回合、中间回合和最终身份确认前的流式正文由活动详情承载；`runCompleted.finalTurnId` 确认后，同一稳定 blockId 接续回答正文索引。下一已应用输入组启动后，前组已提交回答沿用原 blockId 与搜索行为；兼容 progress 保留在活动区，搜索定位与折叠交互分别使用所属视图状态。
- 每条结果保存稳定 blockId、消息块原始文本、围绕首次命中的摘要和匹配范围；搜索列表以统一中性标记和单行消息摘要呈现全部结果。
- 已挂载结果由 MessageStream 直接滚动到对应 block DOM；离屏结果由虚拟布局根据 blockId 计算目标位置，更新滚动容器并将该块带入 visibleRange 完成挂载。
- MessageStream 提供按 blockId 显示消息块的定位能力。定位过程负责虚拟窗口和阅读位置，数据库读取由统一历史加载器负责；主消息流在块挂载后根据同一 blockId 恢复选中高亮。
- 持久化消息经过历史加载和 AgentState 投影后生成新的 MessageBlock 与搜索结果；查询非空且 `hasMore=true` 时，搜索控制器通过统一历史加载器读取更早页面，再执行同一套 blockId 定位流程。
- 搜索加载旧页面与用户滚动加载旧页面共享 cursor 和在途请求去重；两种入口都使用原有 prepend 锚点修正，搜索控制器直接调用历史加载器。
- 用户停留底部时，实时新增消息块继续吸底；用户在中间阅读或查看搜索结果时，新增消息和旧页插入都以当前 blockId 保持视口锚点。

运行中输入与历史身份。

- 输入顺序：初始任务后依次显示补充文本 1、补充文本 2；每条补充文本拥有独立 inputId，在 Main 持久化 ACK 后按 FIFO 顺序呈现。
- Main 的运行 ACK 携带已持久化初始用户 entry 使用的 `inputId`；补充输入 ACK 携带对应的 `inputId` 与 `acceptOrder`。实时投影和历史恢复沿用同一 ID；模型上下文接收时间由后端的 `inputsApplied` 事件确认。
- 安全边界提交 completed 用户 entries 后，投影以相同 `inputId` 归并实时状态；连续输入按 Main 的 `acceptOrder` 排列，历史顺序由 `entryOrder` 重建。
- `runCompleted.unappliedInputIds` 与 interrupted 用户 entry 沿用相同 `inputId`，项目切换、历史分页和历史重载据此复用稳定消息身份；消息块与活动组规则见下方“模型消息与助手活动折叠组”。

滚动区域与覆盖。

- 覆盖关系：Composer 固定在内框消息主列底部，消息在其后方滚动，重叠区域由 Composer 表面覆盖；工作台内框裁剪该区域的外部视觉溢出。
- 底部占位：内容列末尾预留与 Composer 实际高度相等的占位，高度随输入与附件增减同步更新，保证滚动到底时最后一条消息完整停在 Composer 上缘。
- 自动跟随：消息流以距底部24px作为“停留在底部”的判据；用户停留底部时，生成中的消息高度变化和新工具活动继续推动视口到底部。
- 手动阅读保护：用户向上滚动超过24px后，消息流关闭自动跟随；后续模型增量、工具事件和高度变化只更新消息内容，阅读位置由当前滚动锚点保持。
- 恢复跟随：用户重新滚到底部后恢复自动跟随；需要跳转到最新消息时必须由明确的用户操作触发，普通流式事件继续沿用当前跟随状态。
- 首次打开：历史 hydrate 和首轮布局测量完成后，消息流以瞬时滚动定位到最新消息；页面首帧直接呈现底部位置，后续运行沿用同一套底部跟随规则。
- 实现入口：`frontend/src/middle-column/message-stream/useVirtualMessageWindow.ts` 统一持有作用域级测量缓存、锚点、底部判据和自动跟随；`MessageStream` 将作用域及历史就绪状态传入虚拟窗口；`frontend/src/App.tsx` 负责页面组合、作用域切换和 Composer 高度占位。
- 滚动条与回弹：滚动条样式、跟手与回弹交互见[弹性回弹滚动](./elastic-scroll.mdx)。

用户任务消息。

- 对齐：右对齐，与消息流同列。
- 文字：14px，行高24px，主要文字颜色，字距0.02em。
- 圆角：四角一致，均为16px。
- 背景：沿用 `--surface-bubble`，浅色 #F3F3F3、深色 #242424，与页面背景保持相邻色阶。
- 内边距：垂直8px，水平14px。
- 最大宽度：内容列的76%。
- 间距：与后续内容28px。
- 形态：四角一致的扁平纯填充气泡，层次由气泡表面颜色与页面背景区分。
- 宽度：随内容收缩（fit-content），短文本按自身内容宽度显示。

时间戳与复制行。

- 位置：右对齐，与气泡下缘间距8px。
- 可见性：时间与复制按钮始终可见；鼠标悬停和键盘聚焦期间保持稳定显示。
- 组成：消息时间加复制图标，同行。
- 时间来源：用户消息使用 entry 的固定 `createdAt`，初始运行 ACK 和补充输入 ACK 提供相同的实时日期值。
- 时间文字：13px，低强调文字颜色，格式如 Thu Sep 17 11:45 AM（英文星期缩写、英文月份缩写、日期、12小时制时:分和AM/PM，字段以空格衔接）。
- 复制图标：复用系统 Icon 复制图标，14×14px、`strokeWidth=2`，低强调文字颜色，无背景，悬停保持相同颜色；点击写入剪贴板，成功后切换为相同14×14px和`strokeWidth=2`的 Check 图标，使用主要文字颜色保持2秒，随后恢复复制图标；失败时使用危险色和失败提示；按钮提供 Tooltip、动态无障碍名称和状态播报。
- 图标间距：与时间文字约8px。

模型消息与助手活动折叠组。

- 宽度：与消息内容列一致，在内容列上限760px内占满可用宽度。
- 文字：使用 `--font-size-body` 的14px字号与24px行高，颜色沿用 `--text-reading`（浅色 #444444、深色 #EEEEEE），字距0.02em。
- 间距：与前一条时间线消息保持28px阅读节奏；活动组、最终回答与消息元信息使用统一细节间距。
- 呈现：模型消息块与 Composer 共用同一内容列宽度，文本行直接进入阅读流，与消息流左对齐；代码块、表格和其他 Markdown 结构在该列内展开。
- 流式呈现：Renderer 以 `turnId` 接收归一化正文和完整调用集合，以 `toolCallId` 关联工具操作和结果；活动组聚合连续的多个模型 turn。共享 commentary 投影为每个 turn 生成一条用户说明，随后呈现该回合的一个工具组；空工具回合直接使用公开正文形成段落。实时与历史共用固定 `completedAt` 作为回答日期。
- 最终回答：运行成功完成时，`runCompleted.finalTurnId` 确认最终助手回复，投影将该 turn 的 `assistantContent` 移至折叠外下方，以普通模型消息呈现 Markdown、时间戳与复制交互；最终回合的旧 `progressContent` 继续归入活动折叠。活跃组在最终身份确认前保留全部原生正文于活动详情，已由应用 steer 结束的前组遵循任务回答边界规则。

统一 commentary 与来源字段。

- 字段职责：Provider Adapter 将原始协议归一化为 `content`、`reasoning` 与 `toolCalls`，并映射可选原生阶段事实；Provider 分支集中在该层。`TurnState.assistantContent` 保存正文，`reasoningContent` 保存原始思考，`progressContent` 承载旧记录说明，`ToolCall.input.purpose` 保存各项动作目的。
- 增量链路：Adapter 将原生 `content` 映射为 `text_delta`，Runtime 经既有正文回调与 IPC `assistantDelta` 更新对应 turn 的 `assistantContent`；原始思考沿独立事件进入思考字段。新响应直接使用原生正文与结构化工具调用。
- 完成与恢复：`assistantCompleted` 以完整 `content` 对齐正文，历史投影从 `payload.content` 恢复同一状态；旧事件和旧 payload 中的可选 `progress` 继续恢复为 `progressContent`，两条读取链路汇入同一展示投影。
- commentary 投影：`assistantActivity.ts` 为每个 turn 生成单一 `commentary` 字符串。投影先采用 `progressContent` 与仍处于活动区的 `content`，再按调用顺序追加去重后的 `purpose` 行；完整集合到达后，缺失正文的工具回合仍能显示动作说明。
- 去重规则：投影把连续空白折叠为单个空格并修剪首尾空白，对完整行执行精确比较；重复行保留第一次出现的原文，语义相近的不同目的分别保留。数据库保存原始字段，不保存派生 commentary。
- 回合定义：一个 turn 表达一次逻辑模型请求及其返回的完整工具批次；模型重试沿用相同 `turnId` 并递增 attempt，回合确认后按工具调用原顺序生成一个工具组。工具集合为空时，该 turn 保留公开文字区。
- 生成与语言：主模型按最新已应用用户输入的语言填写工具 `purpose` 并生成公开正文，共享投影使用已有模型文本组织说明。目的缺失时，共享投影按关联输入的 zh/en 语言生成工具动作与实际目标说明；原始 reasoning 保留持久化、协议续轮与诊断职责，语言约定见[模型请求](../../../agent/model-request.mdx)。

最终回答 Markdown 结构。

- 行内强调（`**加粗**`、`*斜体*`、`~~删除线~~`）：以纯文本呈现，标记消失；结构类格式化（列表、标题、表格、代码块、引用、任务列表）保留。
- 基础节奏：相邻块统一8px上边距。
- 结构块（标题、列表、表格、代码块、引用）：上边距与下边距各12px，与正文段落拉开层级。
- 字号层级：Markdown 一级至四级标题依次为18px、17px、16px和15px，行高1.3；行内代码使用父级字号的0.92倍，围栏代码12px/20px，表格13px/20px。
- 代码块：使用次级表面颜色、通用边界和16px圆角，最大宽度跟随消息内容列；保留源码空格与原始换行，并根据可用宽度软折行，连续长 token 在需要时折行。
- 分隔线（`---`）：上边距与下边距各12px，以透明空隙分隔区块。
- 行内断行：单次换行以 `<br>` 呈现、行距24px，构成连续文本，沿用行内间距。

最终回答时间与复制行。

- 位置：左对齐，与消息下缘间距8px。
- 时间来源：完整模型输出成功提交后固定 `completedAt`，实时完成事件与历史 entry 提供相同值；最终身份确认后，折叠外正文、日期与复制入口共同呈现。
- 可见性：时间与复制按钮始终可见；鼠标悬停和键盘聚焦期间保持稳定显示。
- 组成：消息时间加复制图标，同行。
- 时间文字：13px，低强调文字颜色，格式如 Thu Sep 17 11:45 AM（英文星期缩写、英文月份缩写、日期、12小时制时:分和AM/PM，字段以空格衔接）。
- 复制图标：复用系统 Icon 复制图标，14×14px、`strokeWidth=2`，低强调文字颜色，无背景，悬停保持相同颜色；点击写入剪贴板，成功后切换为相同14×14px和`strokeWidth=2`的 Check 图标，使用主要文字颜色保持2秒，随后恢复复制图标；失败时使用危险色和失败提示；按钮提供 Tooltip、动态无障碍名称和状态播报。
- 图标间距：与时间文字约8px。

活动组边界与折叠内容。

- 分组边界：初始已应用用户消息锚定首个活动组，首个模型 turn 启动前该组呈现等待状态，并沿用同一 blockId 接收后续活动。Renderer 收到 steer ACK 后立即按 `acceptOrder` 显示用户消息，并以 `accepted` 标记等待应用；正在执行的助手活动和计时继续归属已有组。Runtime 发出 `inputsApplied` 并启动下一 `turnId` 后，后续活动进入新组，并锚定该批已应用输入中最后一条消息的 `inputId`。
- 回合归组：`turnId` 标识一次模型请求及其工具批次并承担事件关联身份；可见分组身份由已应用输入的 `inputId` 承担。同一已应用输入锚点下的模型请求、工具调用和工具结果共同累积在一个活动组中。时间线里的待应用用户消息先行呈现，助手活动依据实际应用边界归组，计时由最新真实助手组持有。
- 锚点生命周期：ACK 先于排队中的 `turnStarted` 到达时，新 turn 仍捕获当时已应用的输入。`inputsApplied` 更新后续回合使用的边界，已有 turn 保持启动时捕获的锚点和稳定 blockId。
- 迟到 ACK：`inputsApplied` 可以先在时间线中建立已应用的 `inputId` 顺序，后续 ACK 补齐同一输入的正文和时间。用户气泡与助手活动组沿用原有身份和顺序；实时投影与历史恢复通过同一个 MessageBlock 构造器建立分组。
- 任务回答边界：已应用 steer 的下一活动组启动后，前组结束当前工作阶段，并可将组内最后一个已提交、工具集合为空的有效回答作为 `answerTurnId` 放在折叠外，沿用原 blockId 与搜索行为。该身份由输入锚点、回合状态和工具事实派生；活跃组继续等待运行完成确认最终回答，各已应用人类任务分别保留所属回答。
- 折叠结构：组内按 turn 顺序呈现一条 `commentary`、该回合的一个工具组、下一回合 commentary。commentary 以兼容 `progressContent` 和已有 `content` 为公开文本，本批 `purpose` 作为补充或空正文回退；空工具回合直接展示公开正文。最终身份确认后，该 turn 的回答正文进入折叠外，先前回合保留在活动详情。
- 内容来源：原生响应的 commentary 以模型公开 `content` 为首段，兼容 `progress` 保留旧记录既有段前顺序；工具目的按原调用顺序补充动作意图。工具组标题与操作行由实际调用生成，原始 reasoning 保留数据与协议职责。
- 目的去重：同一回合按空白归一化后的完整文字去重，保留第一次出现的目的原文；与已有公开正文、兼容过程正文或其中单行完全相同的目的复用已有展示。目的按换行连接为一个说明块，语义相近的不同原文分别保留，数据库字段保持原值。
- 目的回退：缺失、空白或类型异常的 `purpose` 使用工具类别和实际路径、查询或实体生成对应语言的明确操作说明；命令类缺省目的使用“执行命令”等类别文字，完整命令保留在工具操作行。回退文字描述实际动作，结果结论沿用公开正文与工具结果。
- 运行等待：当前活动组持续显示 `Working for` 工作指示并保持可展开；整组的首段公开说明或工具活动到达前，展开区显示等待状态，中文文案为“正在等待过程说明。”，英文文案为 `Waiting for a process explanation.`。已有过程说明与工具活动按顺序保留，首个可见活动到达后等待状态由真实内容接续。
- 历史可见性：含中间正文、旧 `progress` 或工具活动的历史组生成活动折叠行；仅保存原始 reasoning 的中断组保持数据记录形态。回答按最终回合身份或已应用输入的任务回答边界进入折叠外；活动等待与内容可见性由公开正文和工具事实决定。
- 身份待确认：活跃组的最终身份由成功运行的 `finalTurnId` 确认，历史由最终 Assistant entry 的持久化时长恢复该身份；身份待确认的记录继续在活动详情中呈现已有公开正文和工具事实。取消或失败终态按相同输入锚点规则保留前组已提交回答。
- 推理记录提示：已完成回答的工具集合与活动文字区为空、原始 reasoning 已保存时，活动行可展开查看记录说明；中文为“原始推理已保存，公开正文见下方回答。”，英文为 `Raw reasoning is saved; the public response appears below.`。原生响应与旧记录共用该事实提示及 `work-legacy-notice` 样式，公开回答在折叠外呈现，原始 reasoning 继续承担数据与协议职责。
- 旧正文兼容：历史 `content` 按同一回合身份规则分配到活动详情或最终答案，旧 `progress` 按实际保存值进入所属回合文字区；原始 reasoning 保持原文字段与协议职责。原生正文响应直接进入相同投影。
- 活动文案与时长：run 运行期间，所有已建立活动组统一使用 `Working for` 状态文案；实时耗时只由当前活动组展示，并从 `runStarted` 起算。steer 输入应用并启动后续组后，前组保留折叠内容与 `Working for` 状态文案，计时归属转到新组。成功完成后，前组继续呈现活动内容与状态文案，完整时长由最终活动组集中呈现为 `Worked for <run 总时长>`。总时长从 `runStarted` 计至 `runCompleted` 终态。实时身份来自 `runCompleted.finalTurnId` 和 `finalDurationMs`；历史身份来自最终 Assistant entry 的 `durationMs`，投影将最终 turn 映射到所属活动组。
- 活动行样式：最小高度26px，文字14px、行高22px、次要文字颜色，背景透明；文案与箭头间距8px。Chevron-right 为15×15px，收起指向右，展开后旋转90度向下，过渡180ms并沿用统一缓动。
- 活动行交互：当前工作组依据既有 `run.status` 与 `isWorking` 默认展开，模型正文增量、工具执行和续轮期间持续沿用该默认值；成功 `runCompleted` 确认 `finalTurnId` 时默认收起，并将最终正文放到折叠外。已应用 steer 启动下一组时，前组采用工作结束后的收起默认值；取消、失败和已完成历史采用结算后的收起默认值。折叠箭头始终可见，悬停保持图标与文字原有颜色和笔重，行背景透明；点击与键盘操作控制展开，箭头旋转过渡180ms，展开高度过渡200ms、透明度过渡180ms。
- 状态归属：展示投影复用 `run.status`、`isWorking`、`finalTurnId`、`turn.status` 和 `tool.status` 派生正文位置与默认展开值；文本增量更新所属 turn 的正文，生命周期事件更新运行与执行事实。React 保存当前工作或结算阶段的本地手动覆盖，同一阶段沿用用户选择，阶段变化后重置为对应默认值；持久化保存模型与执行事实。
- commentary 排版：每个 turn 只渲染一个 `work-commentary-text` Markdown 块，公开正文与目的段之间保留空行，正文大小、行高和次要文字颜色沿用过程文字样式；单次换行继续由 `MarkdownText` 保留，commentary 与相邻工具组间距6px。
- 工具组折叠：每个 turn 的完整调用集合形成一个工具组，标题按实际工具类别汇总为固定英文，如 `Read files`、`Ran commands`、`Read files, ran commands`。等待执行与执行中的调用共用 `running` 状态，调用集合在完整 Assistant 消息到达时建立；所属 run 与 turn 处于运行态，且该 turn 任一工具为 `running` 时默认展开。全部工具 `completed`、turn 终态或 run 终态时默认收起；组身份为 `runId + turnId`，组内按原调用顺序显示各工具行。
- 组内工具行：每行包含折叠箭头、16×16px语义图标与实际操作文本，最小行高26px、行间距0。读取按实际 `path` 生成 `Read <path>`，命令按实际 `command` 生成 `Ran <command>`，其他调用按工具类别与实际目标生成标签；`purpose`、`targets` 保留在调用参数和展开详情中。字体为 PingFang SC regular 400、14px、行高22px、次要文字颜色。
- 行宽省略：工具行标题采用 `white-space: nowrap`、`overflow: hidden` 和 `text-overflow: ellipsis`，布局容器允许文本区域收缩；完整标签按原文保留，省略号随消息流实际可用宽度溢出而出现，字符长度由 CSS 布局决定。
- 单行详情：每条工具行以 `toolCallId` 独立控制展开，展开后展示完整输入、命令或路径、结果与错误；详情区域在行展开时惰性挂载，收起后释放详情内容，标题与状态继续保留。组级、行级和外层折叠分别使用对应稳定身份管理交互。
- 详情排版：输入参数以格式化 JSON 呈现，结果保留已保存的输出原文，错误使用紧凑文字；详情距工具行左侧24px，顶部4px、底部8px。输入与输出代码区域各使用240px最大高度、内部滚动、8px内边距和8px圆角，文字为等宽字体12px、行高20px，长文本按可用宽度换行。
- 语言与历史回退：主模型按关联的最新已应用用户任务及明确语言要求生成公开 `content`，Renderer 呈现已有原文；等待文案按该 turn 的 `anchorInputId` 所关联输入选择 zh/en。工具标签由实际参数与工具类别生成；`Working for`、`Worked for` 和工具组标题沿用固定英文。
- 工具组布局：工具行沿活动行左缘依序堆叠，首行与后续行盒间距均为0；展开列表使用 `max-height: 320px` 与内部纵向滚动，短列表按内容自然高度呈现，展开的行详情计入同一工具列表高度。外层活动区随内容自然增长，内部限高滚动由工具列表承担；最终答案显示在活动组之后。
- 状态反馈：工具组与单行标题各自提供展开状态和键盘交互，失败工具行附紧凑失败标记，完整结果与错误在行详情中呈现。工具的 `running` 与 `completed` 状态参与默认展开判断；活动组标题、用户与最终回答的时间和复制行使用常显样式。
- 无障碍：三层折叠入口使用原生按钮与 `aria-expanded` 表达展开状态；外层活动区和工具组收起时以 `aria-hidden` 与 `inert` 管理内容和焦点，工具行详情随本行展开挂载。系统启用减少动态效果时，折叠高度、透明度和箭头旋转直接完成状态切换。
- 最终 Assistant entry 持久化 `durationMs`（毫秒），记录整个 `runId` 从 `runStarted` 到运行终态的总时长。时长格式为：不足10s保留一位小数；不足60s取整秒；60s以上转分钟（126s → 2m6s）；1小时以上转小时。

活动展示与执行数据。

- 分组职责：`messageBlocks.ts` 从统一 AgentState 确定已应用输入锚点、稳定 blockId、组内 turn、回答身份与计时归属，消息渲染与搜索共同消费同一消息块序列。
- 投影职责：`toolActivity.ts` 从调用参数生成 `purpose`、实际操作标签与类别，引用原 ToolState 提供详情；`assistantActivity.ts` 按 turn 生成单一 commentary 与批次运行状态。实时与历史共同调用这组规则，Provider 差异停留在 Adapter，commentary 语义在共享层保持统一。
- 组件职责：`AssistantMessage.tsx` 消费投影，按阶段默认值与用户选择控制外层活动组和内层工具组，单条工具行独立展开输入与结果，CSS 负责排版、限高滚动与按宽度省略。实时事件与历史恢复共同使用这组投影与组件职责。
- 数据归属：原生正文、命令、原始 input JSON、完整工具输出与错误详情保存在执行、模型上下文和项目历史数据中，工具行展开时按需呈现详情；原始 reasoning 保留在数据层并用于 DeepSeek 工具续轮所需的协议回放。
- 恢复兼容：`runId`、`turnId`、`toolCallId` 与已应用输入锚点持续关联正文、调用与结果。Assistant JSON payload 按保存值兼容读取 `progress`，`ToolCall.input` 保存 `purpose`、`targets` 与实际操作参数；原生响应通过 content 与 toolCalls 交付公开内容，存储结构沿用既有消息表。

工具图标。

- 复用系统 Icon 语义图标，尺寸16×16px，1.8px描边，圆角端点，使用 currentColor。
- 工具映射：bash 使用 terminal 图标，read 与 history 使用 book-open 图标，write/edit 与 Canvas 使用 edit 图标，search 使用 search 图标，目录列表使用 folder 图标，其他类别使用 tool 图标；失败行使用 warning 图标与危险色。

网页搜索工具活动。

- 类别：`web_search` 使用独立的网页搜索活动类别，工具组标题由现有类别摘要规则生成；操作目的继续进入本回合共享 commentary。
- 操作行：单行显示真实查询词与运行状态，成功结果显示本次网页数量，失败沿用现有失败标记；单工具默认收起并按需展开。
- 来源列表：详情区按搜索源顺序显示站点图标、网页标题与域名，标题沿可用宽度单行省略，点击来源由系统浏览器打开原网页。
- 视觉：网页来源沿用消息流字体、次要文字颜色、透明背景和工具区的紧凑间距；站点图标使用16×16px尺寸，缺失时呈现系统 globe 图标。
- 图标加载：使用结果中的站点图标地址或同源 `/favicon.ico`，按需异步加载，浏览器缓存复用同一地址；图标加载状态独立于搜索执行结果。
- 展开交互：工具组与单工具继续使用既有折叠状态、箭头、过渡与320px工具区滚动；来源链接位于展开详情中，折叠按钮承担展开收起。
- 历史恢复：查询来自原始调用，标题与链接来自已保存的 `web.pages`，实时消息和恢复历史共用同一活动投影与来源列表。
- 结果边界：搜索结果列表表达本次找到的网页，实际网页正文读取由对应工具执行事实表达。
