安全边界。

明文 API Key 存在于 Renderer 的当前编辑草稿和发往 Main 的保存或发现请求中。Main 使用 Electron `safeStorage` 加密后，以 `encryptedApiKey` 字段写入 `provider-profiles.json`；该文件按 `providerProfileId` 独立保存每个提供商的名称、Base URL、密文和模型目录。临时文件权限为 `0600`，写入完成后以 rename 替换正式文件；应用重启后，在系统解密能力可用时继续使用已保存凭据。加密能力不可用时，Main 拒绝保存新凭据；不回退到明文存储。eye/eye-off 只改变当前草稿的输入显示。

提供商列表只向 Renderer 返回是否已配置凭据和模型可用状态，不返回密文或已保存的明文。模型可用状态同时受系统解密能力约束。运行开始时，Main 解析模型所属提供商并捕获该连接的 Base URL 和密文快照；每次模型请求通过 `apiKeyProvider` 解密该快照，保证运行中的地址与凭据来自同一连接版本。随后编辑或轮换凭据只影响新解析的连接。模型发现使用当前草稿中的显式 API Key，或同 origin 的已保存密文；发现本身不保存草稿或轮换已保存凭据。AgentRunner 和模型适配器当前同在 Main 进程执行。运行请求、公共事件与工具结果类型不包含专门的凭据字段。

独立保存提供商并不足以阻止把旧凭据发送到新地址。保存和模型发现都由 Main 检查凭据复用边界：Base URL 的协议、主机或端口变化时，留空 API Key 的请求被拒绝；用户须显式输入新地址的凭据。只调整同 origin 的路径时允许复用，域名大小写和默认端口按标准 URL origin 规范化。Renderer 使用相同规则控制输入提示与按钮启用状态；草稿变更不会删除或修改已保存的连接，只有保存成功后才替换该 profile。版本 1、2、3 的历史数据继续加载，历史凭据按其已保存 Base URL 应用相同规则。

敏感信息不得进入消息、事件和普通日志是设计约束。模型请求只向 UI 暴露稳定错误码与安全文案；完整诊断进入受限、可清理的日志并以 `diagnosticId` 关联。Bash/tool 输出使用有界内存、脱敏策略和 TTL 临时文件，项目历史只保存经过边界处理的模型可见事实。

输出文件访问使用 Main 维护的 runId 和 fileId 注册表。可读路径只用于界面识别，不构成读取和打开授权。

预览和打开前，Main 重新检查真实路径是否仍与登记路径一致、目标是否仍为普通文件。注册范围与生命周期见[输出文件侧边栏](./titlebar/sidebar/index.mdx)。输入附件也由 Main 的原生文件选择器登记，Renderer 提交 attachmentId；Main 在运行前解析并复查文件，再把本地路径加入模型任务文本。

Renderer 负责呈现状态和发起用户意图。Preload 负责暴露受限的类型化接口。Main 负责凭据，文件系统，系统能力和 Provider 网络请求。Agent Runtime 负责模型调用，工具执行和运行生命周期。

窗口已启用 `contextIsolation`、关闭 `nodeIntegration` 并启用 Renderer sandbox。Main 必须拒绝非工作台来源的顶层导航，并对每个 IPC handler 校验 trusted sender/frame、运行时输入 schema、大小和 origin；生产 Renderer 还必须提供 CSP。模型 Markdown 的图片只允许受控的本地/内联资源，远程或相对图片默认不加载；外链只允许明确的 `https:` 等协议并交给系统浏览器。它们隔离 Renderer 的直接 Node 能力；本地 Bash 仍以应用用户权限执行，cwd 仅表示初始工作目录，不是文件访问隔离边界。当前没有独立 Runner 进程、命令审批层或 Bash 文件系统沙箱。Preload 的 TypeScript 类型也不替代 Main 的运行时输入校验。

实现状态：Provider JSON 加密存储、Main 的保存与发现 origin 校验、连接快照及 Renderer 的凭据提示已实现。导航、IPC sender 校验和 CSP 尚未完整落地；其差异记录在[实现状态与工程审计](../../../IMPLEMENTATION_STATUS.md)。
