历史投影。

历史投影把 Main 返回的当前项目或无项目历史页转换为统一的 `AgentState`。Renderer 使用 `projectId` 识别当前历史范围，使用 `entryId` 去重，使用 `entryOrder` 维护稳定顺序。

## 页面数据

```ts
interface HistoryPageRequest {
  cursor: string | null;
  limit: number;
}

interface HistoryPageEntry {
  entryId: string;
  entryOrder: number;
  projectId: string | null;
  type: "user_message" | "assistant_message" | "tool_result";
  status: "streaming" | "completed" | "interrupted" | "failed";
  runId: string;
  turnId: string | null;
  toolCallId: string | null;
  revision: number;
  payload: ModelMessage;
  createdAt: number;
  updatedAt: number;
  durationMs: number | null;
}

interface HistoryPageResult {
  projectId: string | null;
  entries: HistoryPageEntry[];
  nextCursor: string | null;
  hasMore: boolean;
  snapshotOrder: number;
}
```

Main 以当前 `projectId` 或 `NULL` 范围过滤 entries，再按 `entry_order DESC` 读取尾页，并在交付 Renderer 前恢复为 `entryOrder ASC`。`snapshotOrder` 表示当前范围读取到的最大顺序。

## 运行中输入投影

HistoryService 按现有 `entryOrder` 游标分页 `entries`。安全边界应用的补充输入形成 completed 用户 entry；停止、失败和启动恢复归档的补充输入形成 interrupted 用户 entry。两类 entry 都以 `inputId` 为稳定 `entryId`，`entry.status` 提供其持久化状态。

Renderer 以 `projectId`、历史请求代次和 `inputId` 合并持久化 ACK、后续 `inputsApplied` 事件以及历史 entries。Main 为初始输入生成 `inputId`，通过运行 ACK 交给 Renderer，并把同一个 ID 传入 Recorder 作为初始用户 entry ID；实时投影、历史恢复和搜索因此共用稳定身份。运行中的补充输入沿用其持久化 `inputId`；连续输入的顺序采用 Main 的 `acceptOrder`，历史顺序采用 `entryOrder`。

安全边界提交 completed 用户 entry 时，实时投影以相同 `inputId` 更新对应状态。`inputsApplied` 记录本批用户消息进入模型上下文的时刻；后续 `turnStarted` 使用新的 `turnId`。reasoning、Assistant Message、工具调用与 Tool Message 使用各自的 `turnId` 和 `toolCallId` 关联。历史恢复依照 `entryOrder` 重建用户消息、Assistant 与 Tool entries 的先后关系。

Renderer 使用一条显式消息时间线承载每个 run 的事件投影顺序：

```ts
type MessageTimelineItem =
  | { kind: "user"; inputId: string }
  | { kind: "assistant"; turnId: string };
```

ACK 以 `inputId` 追加用户项；`turnStarted` 以 `turnId` 追加模型请求事实；`inputsApplied` 保持用户项身份并记录补充消息的上下文提交。Assistant 增量和 Tool 事件更新已有 turn 与 tool 状态。历史投影以 `entryOrder` 重建持久化序列。用户输入边界到助手活动组、消息块身份及展开内容的映射由[消息流视图规范](./message-stream.mdx)统一定义。

`runCompleted.unappliedInputIds` 与 interrupted entries 通过相同 `inputId` 对应；历史重载从 entries 恢复输入状态与文本。搜索索引以 MessageBlock 稳定 ID 关联命中。视图状态和定位交互由[消息流视图规范](./message-stream.mdx)说明。

Runtime 以 `runStarted.startedAt` 建立一个 `runId` 的计时起点；成功完成时，最终模型回复的 `durationMs` 保存从该起点至运行终态的总时长。实时事件通过 `runCompleted.finalTurnId` 与 `finalDurationMs` 标识最终回合和相同总时长；历史投影通过最终 assistant entry 的 `turnId` 与 `durationMs` 恢复相同数据。`projectId = null` 的输入记录进入通用历史范围，并使用相同身份与顺序规则。总时长的活动组归属由[消息流视图规范](./message-stream.mdx)统一定义。

## Hydrate 流程

```text
Main active project scope
  → loadHistoryPage(cursor, limit)
  → HistoryPageResult
  → mergeHistoryEntries
  → mergePersistedEntries
  → AgentState / MessageStream
```

目标项目确定后，Renderer 先将历史投影切换到目标 `projectId` 并进入加载状态；目标页面返回后，Reducer 将该范围的 `HistoryPageEntry` 投影为新的 `AgentState`。旧项目的 `entriesById` 保持在 SQLite 中，当前页面只显示新范围。

## 项目范围切换与滚动状态

`projectId` 同时标识历史投影和 MessageStream 的虚拟窗口作用域，`null` 表示无项目历史。Renderer 在开始切换时立即将当前页面标记为目标范围加载中，并清空旧范围的 `runs`、`runOrder` 与当前历史页投影；Composer 展示的目标项目和消息流范围保持一致。

每次历史读取在 Renderer 内绑定目标 `projectId` 与请求代次。Main 在请求开始时捕获对应历史范围；异步结果返回后，Reducer 仅接收仍匹配当前作用域及最新代次的页面。该门控覆盖首次 hydrate、项目切换后的 reload、旧页分页与搜索读取，保证切换前发起的迟到结果不会污染当前项目。

MessageStream 接收当前 `projectId` 和 hydrate 就绪状态，并据此管理虚拟窗口：

- `projectId` 或历史替换代次改变时，虚拟窗口清理旧作用域的高度测量、前一布局、分页在途标记、视口快照和底部跟随状态；同一项目重新 hydrate 也建立新的首屏布局。
- 新范围的消息使用估算高度建立布局；首轮 DOM 提交和 ResizeObserver 测量将累计高度逐步修正为真实值。
- hydrate 完成后，有消息的范围将首屏直接定位到最新消息；空范围显示空状态并将滚动位置置零。
- 真实高度后续变化时，底部跟随状态依据最新虚拟总高度更新 `scrollTop`；该过程使用瞬时定位，不呈现从顶部移动到中间的过渡帧。
- 同一范围内加载更早页面时，虚拟窗口保留首个可见 `blockId` 与视口偏移；实时追加按是否停留在底部决定跟随，搜索定位按目标 `blockId` 居中。
- 搜索活动目标随着作用域切换清除，搜索控制器只从当前范围的 MessageBlock 序列构造结果。

作用域切换策略和虚拟高度重建细节以[消息流](./message-stream.mdx)为准。历史投影负责提供可靠的范围身份、请求代次和 hydrate 状态；MessageStream 负责把它们落实为布局重建和滚动策略。

## 实时事件

Hydrate 完成后，Renderer 将排队的 AgentEvent 交给 Reducer。`runId → turnId → toolCallId` 继续作为模型与工具事件身份链，`inputId` 负责补充用户输入归并，`entryOrder` 负责已应用历史排序。迟到的旧 run 事件保持被过滤，项目切换在运行空闲状态完成。

## 搜索和分页

- 首页读取当前范围的最新记录。
- `nextCursor` 指向更早的 `entryOrder` 边界。
- 搜索读取复用当前范围游标，并按需加载更早页。
- 虚拟消息流消费投影后的 `runOrder` 和 `RunState`。
- 项目上下文缓存通过 Main/Runtime 进入模型请求，历史投影只处理 entries。

## 代码入口

- `shell/main/session-history.ts`：当前范围的 Main 历史分页服务。
- `shell/shared/ipc.ts`：`history:load-page`、`HistoryPageRequest` 和 `HistoryPageResult`。
- `shell/preload/index.ts`：`loadHistoryPage()`。
- `frontend/src/store/sessionHistory.ts`：当前历史范围、游标和页面合并。
- `frontend/src/store/sessionProjection.ts`：历史记录到 `RunState`、`TurnState` 和 `ToolState` 的转换。
- `frontend/src/hooks/useSessionHistory.ts`：首次加载、项目切换后的 reload、分页和搜索读取。
