Canvas 入口。

- 入口：侧栏入口打开当前范围 Canvas；入口页规范见[右侧工作侧栏](./sidebar/index.mdx)，画布编辑、范围与保存规则由本页定义。
- 位置：普通范围使用资源区域中的 `Open Canvas` 胶囊按钮，位于 `View All Outputs` 下方；项目范围使用入口页中的 `Open canvas` 卡片。
- 普通入口：按钮靠左排列，30px最小高度、胶囊圆角、次级表面背景、13px共享英文字体与500字重；line-squiggle 图标18px、2px描边、透明底，与文字间距8px。
- 项目排布：`Open workspace files` 与 `Open canvas` 两张卡片组成居中纵向列表。
- 项目卡片内部：两张卡片使用28px左内边距和同一图标起始轴，图标槽宽44px，图标与文案间距12px。
- 项目尺寸：整张卡片作为按钮热区，最小高度72px、内边距12px、圆角12px，图标位于44px的8px圆角图标区。
- 项目材料：使用工作侧栏入口卡片的表面、1px通用边界与共享悬停反馈颜色。
- 项目图标：line-squiggle 语义图标24px，使用2px描边、圆角端点和 currentColor。
- 文案：普通入口显示 `Open Canvas`，项目卡片显示 `Open canvas`；当前范围由左侧导航与项目列表提供。
- 交互：点击后在右侧壳体中打开当前范围 Canvas；左上角浮动圆角返回按钮回到入口页，侧栏按钮控制整个壳体开合。
- 范围：普通 I 使用 `projectId = null` 的 Canvas，具体项目使用其稳定 `projectId` 对应的 Canvas。
- 语义：两种入口使用原生按钮与对应文字名称，键盘支持 Tab 聚焦和 Enter 激活。

Canvas 面板。

- 位置：Canvas 使用右侧壳体内容区域，编辑器填满侧栏可用的完整高度；面板顶部保持连续画布表面。
- 返回控件：左上角固定30×30px浮动按钮，使用8px圆角、半透明表面、12px背景模糊和轻阴影；悬停使用 `--hover` 与主要文字颜色。
- 布局：侧栏面板、顶部区域与 Canvas 绘图场景统一使用 `--workbench-frame-surface`，与中间消息流保持同一底色。
- 表面层级：浮动返回按钮位于 Canvas 内容上方并保持独立点击热区，Canvas 编辑器从侧栏顶边延伸至侧栏底边。
- 界面字号：Canvas 工具栏、菜单、对话框和提示文字通过全局 `--ui-font-offset` 统一调整，当前偏移为 `0px`，各级界面文字采用原始字号。加载与错误提示为 11px，状态提示为 10px，选区操作文字为 9px，Zoom 文字为 14px，Tooltip 为 13px。界面字号由 CSS 排版规则管理，画布文档文字由元素自身的 `fontSize` 管理。
- 工具条：电脑端 Canvas 使用同一套底部工具栏。缩放/撤销区位于左侧，绘图工具位于右侧，两者沿同一底部基线排列。底部布局按控件固有宽度分配空间，按钮尺寸、顺序与单行结构保持固定；宽侧栏中的绘图工具居中于剩余区域，窄侧栏中的超出部分由 Canvas 可视区域裁切，随侧栏展开呈现。工具按钮直接显示在 Canvas 表面，选中、悬停、按下和键盘聚焦反馈使用 I 灰色 token。选区浮层随当前选区位置稳定跟随。
- 尺寸响应：CanvasSurface 的 CSS 确定可视区域尺寸与裁切边界；编辑器通过 ResizeObserver 同步 viewport 尺寸与页面偏移，renderer 根据场景元素和 viewport 重绘。侧栏宽度变化时，元素场景坐标、视图缩放和工具栏组件身份保持稳定。
- 工具：只保留选择、手型平移、矩形、圆形、菱形、线、箭头、自由绘制、文字、图片、橡皮擦、撤销和重做。
- 默认工具：Canvas 初始化、项目场景替换与缺省工具恢复使用手型工具。主按钮拖动执行画布平移，光标在 `grab` 与 `grabbing` 之间切换；工具栏同步显示手型选中态。用户通过工具栏或快捷键选择绘图工具。
- 临时选择：用户在 Canvas 交互区域按住 macOS Command（Meta）键时，编辑器保存进入临时会话前的工具，并将 `activeTool` 切为选择工具。画布光标与底部选择图标立即显示选择态；按住 Command 可点选、框选和移动元素。松开 Command 后恢复进入会话前的工具，选区继续提供 Use selection 和导出操作。正在进行的拖动、绘制或多段线手势先完成，随后应用临时工具切换。
- 临时选择的状态边界：指针编辑使用普通选择语义，Command 键负责临时工具切换；组合快捷键使用原始键盘事件。文字输入、输入法组合和 Zoom 编辑保持各自的键盘处理路径，Space 与鼠标中键继续提供平移。粘贴沿用当前抓手或选择工具并选中新增内容，Command 临时会话持续至松键，异步粘贴完成时采用当前导航状态。用户明确选择另一工具后使用该工具，下一次 Command 按键建立新的临时选择。左右 Command 键共同决定按住状态；窗口失焦、项目切换与画布卸载同步结束临时态。工具切换属于交互状态，元素内容、撤销历史和自动保存由实际场景编辑决定。
- 选区反馈：选中元素增加一条与背景及图形均有足够对比度的选择轮廓；浅色编辑器使用 `--accent`，深色编辑器使用 `#F8F8F8`。轮廓与元素自身描边保持清晰间距，控制点保持可见；元素自身描边与文档数据保持原样。
- 选区浮层：选择一个或多个元素时，在选区附近显示 Use selection、Save image、Save JSON；三个操作位于同一个圆角浮层中，以贯穿浮层内容高度的竖线分隔。浮层操作区高度与底部工具栏单个按钮热区一致；每个操作区使用完整的 hover/active 背景。Save image 打开图片导出对话框，默认导出选区且可改为整个画布，并保留所选图片格式对应的扩展名；Save JSON 导出整个画布为标准 `.json` 文件。已有文件句柄继续使用用户原有文件名和扩展名。Use selection 引用当前非删除选区；全画布引用通过全选元素后执行 Use selection 创建。Canvas 操作区呈现核心编辑工具与导出入口；空状态保留纯画布空间。
- 样式：新建线条固定黑色，默认线宽为中等；自由绘制与普通线条使用同一视觉宽度。新建文字采用 I 左侧的无衬线系统字体栈和 14px 默认字号；文档恢复保留已有描边和文字样式。文字工具使用无衬线 T 图标；工具序号保持 8（图片9、橡皮擦0）。
- 图形渲染：矩形、圆形、菱形与闭合路径绘制轮廓，箭头端点绘制线形箭头。场景模型、编辑状态、命中检测和 PNG/SVG 导出共享轮廓语义；恢复旧场景时清理图形的 `backgroundColor` 与 `fillStyle` 字段。自由绘制的笔迹轮廓、文字字形、图片像素和交互控制点沿用各自的绘制路径。
- 底部操作：Zoom 以整数百分比显示，四舍五入到最近的 1%；聚焦时整段进入编辑态并全选含 `%` 的值，输入 `24` 或 `24%` 均表示 24%。输入值限制在 10%–3000%，确认后以视口中心缩放；输入框使用纯文本式表面，焦点反馈应用于整个 Zoom 操作区。Zoom、Undo、Redo 的垂直热区与绘图工具按钮一致，Zoom 字段宽度按百分比文本内容保留必要空间；滚轮、触控板和手势缩放保持可用。Zoom、Undo、Redo 共享一个底部浮层外框，并与选区操作浮层复用相同的背景材质、边框、圆角、阴影、分隔线与 hover/active token；操作之间以贯穿内容高度的竖线分隔，内部按钮保持统一操作区样式。
- 视口定位：当当前选区移出视口，或画布内容整体处于视口之外时，从视口中心向目标作射线，并在射线与完整视口边界的交点显示透明的 30×30px 点击热区；显示 18px、2px 描边的 mouse-pointer-2 图标并旋转指向目标，采用纯透明表面样式。选区优先，否则指向最近的画布内容。点击图标将视口平移到目标附近，缩放比例保持当前值；目标可见或画布为空时隐藏指针。指针与普通画布内容共享层级，UI 控件保持点击优先级。
- 关闭：侧栏关闭到零宽后编辑器实例保持一段时间；用户再次选择 `Open canvas` 时，在具有确定非零尺寸的容器中恢复编辑器。
- 生命周期：应用启动后预热 Canvas 编辑器模块和当前项目文档；Canvas 首次打开后保持编辑器实例。侧栏关闭时隐藏编辑器并进入静态保留状态。连续关闭 10 分钟后才释放 renderer、图片解码缓存和撤销状态，Canvas 文档快照与编辑器模块缓存继续保留。
- 滚轮：Canvas 保留 CanvasEditor 的平移、缩放和选择行为；Canvas 滚轮交互与消息流、输出文件列表保持独立。
- 安全：Canvas 提供受控 JSON 保存与图片导出；Canvas 内容、项目数据和应用工作台保持独立边界。
- 异常状态：编辑器模块或文档恢复失败时，Canvas 区域显示错误和重试入口，工作台其他区域保持可用。

本地引擎边界。

- 源码：桌面 Renderer 通过本地别名编译 `canvas/engine/editor`、`utils` 和 `math`。绘图核心沿用开源快照的来源与许可记录，产品样式、场景命令、上下文引用和项目持久化由本项目维护。
- 能力：编辑器的工具注册与当前绘图工具清单一致；选择、拖动、分组、复制、图层排序、锁定、图片裁剪和翻转共享场景提交与撤销规则。`canvas_edit` 通过同一实时编辑器取得保存确认。
- 界面：画布使用英文界面字典、系统无衬线默认字体和 Electron 原生 Canvas/DOM。中文、emoji 与已有文档引用的运行字体、字形分片继续参与显示和 PNG/SVG 导出。服务端专用字体编号按默认系统字体恢复。
- 数据：已有场景、剪贴板和 PNG/SVG 元数据沿用兼容的元素与编码格式。历史 iframe、远程嵌入和 magic-frame 元素以静态几何及占位文字显示，仍可选择和编辑位置。
- 兼容范围：核心几何、画布交互、导出、上下文和保存共用本地引擎契约；依赖与资源清理以 Main、工作台、真实引擎的运行引用和现有数据兼容为依据。

Canvas 持久化。

- 范围：每份 CanvasDocument 归属一个项目 ID；`projectId = null` 对应应用独立范围。Main 根据每次请求携带的 `projectId` 定位该范围的 `scene.json` 和图片资源目录。
- 文档：`scene.json` 保存最新的 `revision`、场景元素、可恢复 AppState 和图片资源元数据；图片字节按 `fileId` 保存在同一项目范围的资源文件中。
- 实时编辑：Canvas 编辑器拥有当前内存场景。用户操作与模型的 `canvas_edit` 命令共同更新该场景和撤销历史；编辑器 `onChange` 将完整内容交给 Renderer 的 CanvasDocument 草稿，项目文件承担保存与恢复。
- 加载基准：Renderer 保留加载结果的保存版本。编辑器完成场景初始化后的首次 `onChange` 提供规范化元素、图片资源和持久视图；CanvasSurface 以这份内容建立协调器基准并开放交互。后续内容变化从该基准推进 dirty generation，焦点重绘沿用已有基准。
- 变化识别：编辑器的 `getDocumentVersion()` 追踪元素版本、删除状态、数组顺序、层级索引和图片资源变化。元素比较使用有序的 `id/version/versionNonce/index/isDeleted` 标记，图片比较使用稳定资源 ID、资源版本、元数据和 data URL；CanvasSurface 独立比较主题、背景、网格、缩放和滚动位置等持久视图字段。绘制缓存的 nonce 管理 renderer 重绘，文档保存由内容版本与持久视图变化触发。
- 保存协调：每个已加载项目持有固定项目身份的 `CanvasSaveCoordinator`，集中拥有最新文档、dirty generation、已确认 generation 和保存基准。协调器通过防抖合并连续变化，同时保持一个进行中的请求和一份最新待保存快照；新编辑更新待保存快照。应答推进对应 generation，随后提交仍待保存的最新内容。`flush()` 等待调用时目标 generation 的保存确认。
- 编辑写入：协调器通过 Preload 的受限 IPC 提交 `projectId/document/expectedVersion`。Main 为每个项目安排一条串行写入队列，依次完成路径解析、输入校验、保存基准比较、资源提交、场景原子替换和保存应答。
- 项目切换：工作台先等待当前项目的 `flush()` 成功，再切换项目身份并加载目标场景。Canvas 组件保持挂载，编辑器规范化并替换元素、图片资源和持久视图，为新场景建立完整 Store 快照，并清理选区与撤销历史。加载请求绑定项目 ID 和请求代数，当前项目的最新结果进入编辑器；每份保存请求及其应答始终归属创建它的协调器。
- 恢复：应用从所属项目的场景文件和保存版本恢复 Canvas。保存成功推进已确认 generation；I/O 失败保留最新草稿并提供重试；版本冲突保留内存草稿和磁盘场景，并进入用户处理状态。侧栏切换延续当前编辑器实例的生命周期策略。
- 剪贴板：普通文字、截图和本地图片沿用画布编辑器的粘贴行为；富文本聊天内容中的远程资源由独立的导入流程处理。

`scene.json` 数据结构。

- `revision`：记录该项目最后一次成功提交的场景序号，用于保存应答和恢复诊断。
- `elements`：保存完整的画布元素数组。普通文字以 `type: "text"` 的元素保留文字、坐标、尺寸、字体、颜色和容器关系。
- `appState`：保存主题、背景色、网格、缩放和滚动位置等可恢复的项目视图状态。
- `files`：以 `fileId` 关联图片元素和资源元数据；图片字节保存在独立的资源文件中。
- 格式：项目内的 `scene.json` 使用 `revision/elements/appState/files`；用户触发 Save JSON 时，导出文件使用 `type/version/source/elements/appState/files` 结构的 `.json` 格式。两条链路共享画布元素数据。

普通文字保存。

- 用户输入或粘贴普通文字时，编辑器生成或更新 text element。
- `onChange(elements, appState, files)` 交付完整场景，Renderer 将 text element 原样纳入当前 CanvasDocument 草稿。
- 编辑器的内容版本标记文字变化；保存协调器推进 dirty generation，合并连续编辑，并携带所属项目的保存基准提交最新文字内容。
- Main 完成内容提交后推进文档 revision；协调器按 generation 处理保存应答，I/O 失败时保留最新草稿并提供重试，版本冲突时呈现草稿恢复操作。

图片资源保存。

- 图片元素通过 `fileId` 指向 `files` 中的资源。Main 校验 MIME、资源 ID、data URL 格式和单文件大小。
- 图片资源按文件 ID 和图片内容的 SHA-256 摘要命名，形成稳定的独立资源文件。新图片先进入临时文件并完成资源提交，随后提交引用该资源的场景元数据；场景提交成功后，资源回收流程处理失去引用的旧文件。
- 选区引用中的图片元素保留 `fileId` 与元素结构；模型需要视觉内容时，Host 将对应图片作为独立 media 输入交给 Adapter。

Canvas 保存版本。

- 加载结果携带 `document` 和 `version: { revision, fingerprint }`。revision 由 Main 为每个项目生成，初始值为 0；每次提交变化内容后递增一次。fingerprint 使用 SHA-256 标识规范化持久内容，输入包含元素、持久视图和资源元数据，图片内容摘要随资源文件名参与比较，revision 单独参与版本比较。
- 保存请求携带加载或上次保存确认得到的 `expectedVersion`。Main 在项目队列内读取当前持久版本：内容相同时返回 `saved` 和当前版本，revision 保持原值；内容变化且基准匹配时提交新内容并返回新版本；基准分歧时返回 `conflict` 和当前版本，磁盘内容保持原状。
- Renderer 的 dirty generation 表示本地草稿顺序，Main 的项目写入队列表示持久化顺序，revision 和 fingerprint 表示保存基准。应答关联提交时的 generation，后续编辑继续保持待保存状态。
- 参与 Main 保存队列的写者按项目串行完成校验与提交。独立文件写者的变化在保存读取时通过版本比较识别；fingerprint 同时识别内容变化和沿用原 revision 的直接文件修改。
- `CanvasContextSnapshot` 固化项目 ID、所选元素 ID 和选区 JSON；引用生成流程直接读取内存场景，文档 revision 保持由编辑保存链路管理。

Canvas 引用。

- 触发：用户点击 Use selection 后，CanvasSurface 为当前项目的已选元素生成一次性上下文。用户全选后使用同一入口创建全画布引用。
- 内容：选区复用 Save JSON 的元素序列化规则与 `type/version/source/elements/appState/files` 外层结构；`elements` 包含当前选中的有效元素，普通文字直接使用 text element 的 `text` 字段。图片元素通过 `fileId` 关联资源，Host 按模型能力添加独立 media 输入。
- 坐标：元素现有的 `x/y/width/height/angle` 表示画布场景坐标与几何信息；箭头绑定、文字容器关系和元素 ID 随选区 JSON 一起提供。引用快照另外记录 `coordinateSpace: "scene"` 和选区的轴对齐边界 `selectionBounds: { x, y, width, height }`。Main 将这两项写入模型消息的 `canvasContext` 元数据，供模型相对已有元素定位；Save JSON 文件继续使用原有格式。
- 准备：CanvasSurface 从内存场景冻结选区 JSON，并向 Main 提交项目 ID、选中元素 ID 与快照。Main 校验项目归属、选区 ID 与 JSON 元素的对应关系、数据结构和大小，随后在有界内存 registry 中登记快照并返回 contextId、元素数量与图片数量。画布持久化由独立的编辑保存链路负责。
- 生命周期：contextId 默认有效 10 分钟，Main 最多保留 32 条待使用引用。快照创建后保持固定内容，后续编辑通过再次点击 Use selection 创建新的引用。
- 并行编辑：快照保留创建时的元素 ID、版本与位置。`canvas_edit` 收到命令后按实际目标与联动关系预约局部编辑权限，目标已有的人工操作完成交接；用户继续编辑独立对象。编辑器随后读取最新场景，以引用快照为基准核对目标元素及待修改字段。可独立合并的操作接到最新场景；重叠修改返回受影响元素的当前数据，供模型调整对应操作。
- Composer：Canvas 引用与上传文件共享附件区的 chip 布局、移除交互和发送时机。Renderer 以 contextId 持有画布引用，以 attachmentId 持有文件引用，并在 RunRequest 中提交两类 ID。模型新增图片时使用本次 Run 上传的图片附件 ID，由 Main 读取受限资源并交给 Canvas 编辑器导入。
- 项目范围：contextId 绑定创建时的项目 ID；项目切换刷新画布场景和 Composer 的画布引用。Main 在运行开始时校验引用归属。

Canvas 上下文链路。

- 引用登记：CanvasSurface 准备选区 JSON；Main 的 Canvas registry 登记短生命周期引用。文件选择器经 Main 登记本地文件引用。
- 草稿提交：Composer 将两类引用作为同一份待发送草稿展示，用户发送时在 RunRequest 中提交 attachmentIds、canvasContextIds 和 projectId。
- 引用解析：Main 在启动 Run 前验证文件可读性与 Canvas 项目归属，并解析两类 ID。文件引用提供路径与文件工具提示；Canvas 引用提供已冻结的选区 JSON 和按需附带的图片 media。
- 请求组装：Runner 将文件提示并入当前任务，将 Canvas JSON 映射为本次运行的 `ModelMessage`；Runtime 依次装入历史、运行期上下文和本次用户消息。
- 引用消费：Main 在 Run 启动成功后标记 Canvas contextId 已使用；Composer 在成功 ack 后清理两类引用。Adapter 将 Runtime 消息转换为 Provider 请求。

运行边界。

- `HistoryRecorder.commitUser` 保存用户输入的任务文字；Canvas 选区 JSON 在本次 Run 的内存 messages 中提供上下文。
- 同一 Run 的模型重试和工具续轮使用同一个冻结快照；新的 Run 通过新的用户引用取得画布内容。
- 图片元素的视觉内容遵循模型 media 能力；界面展示实际加入模型请求的内容类型。

Canvas 模型编辑。

- 任务入口：既有 `canvas_edit` 工具请求按当前 Run 和项目身份直接进入 Canvas 执行表面，显示命令执行与保存反馈；用户通过工作侧栏按钮展开时采用入口页选择流程。
- 工具入口：桌面 Runner 向模型提供唯一的 [`canvas_edit`](../../../../agent/tools/canvas-edit.mdx) 工具，并在该工具注册时提供实时画布编辑指令。模型可依据用户指令新增元素；更新、删除、复制、分组、锁定、层级、图片裁剪/翻转和箭头绑定命令以 Use selection 或本 Run 先前创建的元素 ID、类型和场景坐标为目标。本次 Run 持有冻结引用快照。
- 执行位置：`canvas_edit` 的桌面执行器运行随应用构建的 Canvas CLI，并通过 stdin 传入操作 JSON。CLI 使用本次调用的父子进程 IPC 将操作交回 Main；Main 保持 Run、窗口、项目、选区基准与图片资源的绑定，核对命令后经既有桥接交给 CanvasSurface。工作台打开并加载当前项目编辑器；CanvasSurface 向编辑器的 `applyCanvasEdit` 传递请求身份、期限和取消信号，等待局部交接与命令结果，再协调保存和工具应答。编辑器拥有目标定位、临时保护、绑定维护、批次提交、绘制和撤销历史。
- 编辑保护：Canvas 编辑器的 `EditProtectionSession` 持有请求 ID、场景加载代次、执行期限与受影响元素集合。直接目标、绑定文字和容器、关联箭头及标签、相关组合成员与 frame 子元素按命令语义进入保护范围；直接关系的影响保持局部。已有人工拖动、绘制、文字输入和输入法组合先完成场景及历史提交，后续重叠修改由统一编辑门禁协调。独立对象继续编辑，阅读、复制、平移与缩放继续可用。
- 交互门禁：指针修改、文字输入、删除、剪切、擦除、组合与快捷键检查同一份受影响对象集合；撤销与重做在历史栈变化前检查整笔步骤的影响范围。等待中的目标显示 Agent 编辑状态，用户已开始的手势保持连续。保护状态归属编辑器运行时，永久锁定与文档保存继续遵循元素内容契约。
- 提交：目标交接后，编辑器读取最新场景，在隔离副本中按数组顺序完成整批计算，并以全部元素内容识别实际变化。联动范围扩大时补充保护并重新完成交接；成功时只采用变化对象的新结果，独立对象保持实时内容与原实例。同步计算与提交共享同一执行时段，Agent 批次与人工手势各自形成完整撤销步骤。内存提交后释放临时保护，编辑器 `onChange` 更新 Renderer 草稿；CanvasSurface 捕获该请求所属的项目协调器，并通过该实例的 `flush()` 等待目标 generation 的保存确认，再向模型报告成功。变化批次与等值批次共享保存确认规则。
- 冲突：用户和模型操作同一元素时，以最新场景为准核对引用快照。更新命令按几何、文字或路径字段组比较，保留用户在其他组上的改动；删除命令核对完整元素版本。冲突返回元素 ID、冲突字段组和当前元素，整批保持原状。
- 生命周期：CanvasSurface 接受当前项目、当前 Run 和已就绪编辑器对应的工具命令。等待中的请求在取消、期限到达、场景替换与卸载时结算并释放保护；提交前核对请求身份、场景加载代次和有效期。编辑器释放后由工作台重新打开并加载；项目切换、加载失败或运行取消返回明确状态。已提交的编辑通过项目保存链路和画布撤销历史继续可见。
- 文件边界：应用的保存链路维护项目内部 `scene.json` 和图片资源。文件工具服务项目文件与用户请求的导出；应用内 Agent 的实时画布编辑通过 `canvas_edit` 提交。外部 Agent 的受控本地连接作为后续独立能力，复用相同命令与保存协议。
- 反馈：保存确认通过 Main 回传 CLI，CLI 输出结果 JSON，执行器核对结果后由 Runtime 回填 Tool Message。模型工具活动在对话中显示执行与结果；Canvas 显示编辑成功或冲突提示。取消、退出和执行期限归属调用级生命周期，已提交的异常请求报告待核对结果。用户当前选区与视口位置由其交互控制。

失败、失效与恢复。

- 场景加载失败时，Canvas 显示错误和重试入口，原项目场景文件保持原状。
- 场景保存遇到 I/O 失败时，协调器保留最新 dirty generation 和保存基准，Canvas 显示保存失败状态和重试入口，重试使用最新草稿。
- 场景保存遇到版本冲突时，协调器暂停自动保存并保留最新草稿；Main 保留当前磁盘内容。Canvas 显示“重新加载”和“导出草稿”：重新加载采用磁盘场景并建立新保存基准，导出草稿将当前内存内容保存为独立 JSON 文件。项目切换等待冲突处理后的保存确认。
- 模型批次已进入内存且保存发生冲突时，工具结果给出 `persistence_conflict` 和 `appliedInMemory`；已进入内存且保存遇到 I/O 失败时给出 `persistence_failed` 和 `appliedInMemory`。模型根据工具结果说明实际状态，用户通过 Canvas 保存控件恢复草稿。
- 选区准备失败时，Composer 保持原有草稿，Canvas 显示可重试错误。
- contextId 过期或超出容量时，Main 返回引用失效错误，Composer 保留任务草稿并提示用户重新建立引用。
- 用户移除 chip 时，Composer 更新待发送 ID 列表，registry 按 TTL 回收对应快照。
- Run 启动失败时，Composer 保留任务、文件附件与 Canvas 引用；Main 保留仍有效的 contextId 供再次提交。
- Provider 返回图片能力错误时，界面展示对应资源类型与重试入口；Canvas 场景继续保持当前编辑状态。
