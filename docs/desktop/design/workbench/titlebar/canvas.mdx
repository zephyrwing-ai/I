Canvas 按钮。

- 位置：标题栏操作区第二位，位于输出文件按钮右侧、搜索按钮左侧。
- 尺寸：热区30乘30px，圆角8px。
- 材料：透明背景，次要文字颜色；悬停和激活状态使用悬停反馈颜色和主要文字颜色。
- 图标：line-squiggle 语义图标18px，使用2px描边、圆角端点和 currentColor。
- 交互：触发后将右侧工作侧栏切换到 Canvas 面板；Canvas 已显示时触发关闭侧栏。按钮使用 `aria-expanded` 表示 Canvas 面板是否打开，并以 `aria-controls` 关联右侧工作侧栏。

源码所有权。

- Canvas 使用仓库内维护的 Agent Canvas engine，不依赖 npm registry 中的画布包。
- 源码位于 `canvas/engine/`，内部保留 `editor`、`utils` 和 `math` 三个引擎模块；Renderer 通过 Vite alias 直接解析这些源码目录。
- 本地开发使用 `npm run dev` 直接编译 Canvas 源码并在 Electron Renderer 中显示效果，不需要发布 npm 包。
- 宿主 UI 位于 `canvas/ui/CanvasSurface.tsx`；编辑器 UI、颜色、元素渲染和交互位于 `canvas/engine/editor/`。
- 源码保留初始上游实现所需的 MIT 许可证和第三方依赖边界；后续修改以 Agent Canvas 为所有权边界。


Canvas 面板。

- 位置：Canvas 使用右侧工作侧栏的完整内容区域。
- 布局：Canvas 背景使用 Agent Studio 的 `--bg` 颜色，不绘制可见背景网格；网格吸附仍作为独立的绘图辅助状态，不会自动显示背景线。编辑器区域从窗口顶部延伸至侧栏底部；透明标题栏和右上角应用按钮浮在 Canvas 上方，按钮保持可点击。Canvas 面板自身不产生外层滚动。
- 工具条：绘图工具固定在 Canvas 底部，与缩放/撤销区沿用同一底部基线；工具按钮直接显示在 Canvas 表面，不使用额外 Island 卡片容器，也不显示工具提示说明行。工具的选中、悬停、按下和键盘聚焦反馈使用 Agent Studio 灰色 token。选区定位最多每帧计算一次，传给编辑器的回调与配置保持稳定，避免拖动元素时反复重渲染整个编辑器。Help 按钮及其快捷键帮助对话框入口从 Canvas 源码中移除。
- 工具：只保留选择、手型平移、矩形、圆形、菱形、线、箭头、自由绘制、文字、图片、橡皮擦、撤销和重做。
- 选区反馈：选中元素只增加一条与背景及图形均有足够对比度的选择轮廓；轮廓与元素自身描边保持清晰间距，控制点保持可见。不绘制多层平行光晕，不改写图形本身的描边或文档数据。
- 选区浮层：选择一个或多个元素时，在选区附近显示 Use selection、Save image、Save JSON；三个操作位于同一个圆角浮层中，以贯穿浮层内容高度的竖线分隔。浮层操作区高度与底部工具栏单个按钮热区一致；按钮的 hover/active 背景填满各自分隔区域，不在按钮内部额外绘制小块背景。Save image 打开既有图片导出对话框，默认导出选区且可改为整个画布，并保留所选图片格式对应的扩展名；Save JSON 导出整个画布为标准 `.json` 文件。已有文件句柄继续使用用户原有文件名和扩展名。Use selection 只引用当前非删除选区；如需引用全画布，用户可先全选元素再执行 Use selection。默认菜单按钮及 Stroke/Background/Layers 属性面板和样式操作入口不再由 Canvas 挂载；无状态提示内容时不渲染空提示容器。
- 样式：新建线条固定黑色，默认线宽为中等；自由绘制与普通线条使用同一视觉宽度，不通过压力将画笔放大。新建文字采用 Agent Studio 左侧的无衬线系统字体栈和 14px 默认字号；现有文档中的元素样式不在加载时改写。文字工具使用无衬线 T 图标；工具序号保持 8（图片9、橡皮擦0）。
- 底部操作：Zoom 以整数百分比显示，四舍五入到最近的 1%；聚焦时整段进入编辑态并全选含 `%` 的值，输入 `24` 或 `24%` 均表示 24%。输入值限制在 10%–3000%，确认后以视口中心缩放；输入框无独立边框或内层框，焦点反馈应用于整个 Zoom 操作区。Zoom、Undo、Redo 的垂直热区与绘图工具按钮一致，Zoom 字段宽度按百分比文本内容保留必要空间。不提供 Reset Zoom 动作、快捷键或命令面板入口；滚轮、触控板和手势缩放保持可用。Zoom、Undo、Redo 共享一个底部浮层外框，并与选区操作浮层复用相同的背景材质、边框、圆角、阴影、分隔线与 hover/active token；操作之间以贯穿内容高度的竖线分隔，内部按钮不各自形成卡片。
- 视口定位：当当前选区移出视口，或画布内容整体不可见时，从视口中心向目标作射线，并在射线与视口边界的交点显示透明的 30×30px 点击热区；只显示 18px、2px 描边的 mouse-pointer-2 图标并旋转指向目标，不对 TopBar 或底部工具区设置位置禁区，也不添加圆形底色、边框或阴影。选区优先，否则指向最近的画布内容。点击图标将视口平移到目标附近，不改变缩放比例；目标可见或画布为空时不显示。与普通画布内容一致，指针可能被更高层的 UI 遮挡，UI 控件仍保留点击优先级。
- 关闭：侧栏关闭到零宽后短时间内不销毁编辑器实例；再次打开时在具有确定非零尺寸的容器中恢复编辑器。
- 生命周期：应用启动后预热 Canvas 编辑器模块和当前项目文档；Canvas 首次打开后保持编辑器实例。侧栏关闭只隐藏并设置不可交互状态。连续关闭 10 分钟后才释放 renderer、图片解码缓存和撤销状态，Canvas 文档快照与编辑器模块缓存继续保留。
- 滚轮：Canvas 保留 Excalidraw 的平移、缩放和选择行为，不接入消息流或输出文件列表的弹性滚动。
- 安全：关闭远程 embeddable 内容、内置 Load、通用 Export、Library、Live Collaboration、Publish、分享和 AI/diagram 入口；Save 通过受控文件对话框输出 JSON，Save as image 保留图片导出。
- 异常隔离：编辑器模块或文档恢复失败时，只在 Canvas 区域显示错误和重试入口，不得让主工作台 Renderer 变成空白。

Canvas 持久化。

- 范围：每份 CanvasDocument 归属一个项目 ID；`projectId = null` 对应无项目范围。Main 根据每次请求携带的 `projectId` 定位该范围的 `scene.json` 和图片资源目录。
- 文档：`scene.json` 保存最新的 `revision`、场景元素、可恢复 AppState 和图片资源元数据；图片字节按 `fileId` 保存在同一项目范围的资源文件中。
- 项目切换：Canvas 组件保持挂载。Renderer 观察 `projectId` 变化并加载对应场景，替换元素、图片文件和项目视图状态，同时清理旧项目的选区与撤销记录。加载请求带项目 ID 和请求代数，Renderer 只应用当前项目的最新结果；待保存快照始终携带创建时的项目 ID。
- 编辑写入：Renderer 通过 Preload 的受限 IPC 提交最新场景，并用 dirty generation 关联保存应答。Renderer 防抖合并连续编辑产生的快照；Main 为每个项目安排一条串行写入队列，按请求中的项目 ID 完成路径解析、输入校验、资源提交、场景原子替换和保存应答。
- 恢复：应用从所属项目的场景文件恢复 Canvas；保存成功应答推进已持久化 generation，保存失败保留最新草稿并提供重试。侧栏切换延续当前编辑器实例的生命周期策略。
- 剪贴板：普通文字、截图和本地图片沿用画布编辑器的粘贴行为；富文本聊天内容中的远程资源由独立的导入流程处理。

`scene.json` 数据结构。

- `revision`：记录该项目最后一次成功提交的场景序号，用于保存应答和恢复诊断。
- `elements`：保存完整的画布元素数组。普通文字以 `type: "text"` 的元素保留文字、坐标、尺寸、字体、颜色和容器关系。
- `appState`：保存主题、背景色、网格、缩放和滚动位置等可恢复的项目视图状态。
- `files`：以 `fileId` 关联图片元素和资源元数据；图片字节保存在独立的资源文件中。
- 格式：项目内的 `scene.json` 使用 `revision/elements/appState/files`；用户触发 Save JSON 时，现有导出序列化器生成 `type/version/source/elements/appState/files` 结构的 `.json` 文件。两条链路共享画布元素数据。

普通文字保存。

- 用户输入或粘贴普通文字时，编辑器生成或更新 text element。
- `onChange(elements, appState, files)` 交付完整场景，Renderer 将 text element 原样纳入当前 CanvasDocument 草稿。
- Renderer 用 dirty generation 标记草稿变化；防抖与串行写入队列合并等待中的快照，并提交最新文字内容。
- Main 完成场景提交后推进文档 revision；Renderer 按 generation 处理保存应答，保存失败时保留最新草稿并提供重试。

图片资源保存。

- 图片元素通过 `fileId` 指向 `files` 中的资源。Main 校验 MIME、资源 ID、data URL 格式和单文件大小。
- 新图片先进入独立资源临时文件，资源就绪后提交场景元数据；场景提交成功后，资源回收流程处理失去引用的旧文件。
- 选区引用中的图片元素保留 `fileId` 与元素结构；模型需要视觉内容时，Host 将对应图片作为独立 media 输入交给 Adapter。

Canvas revision。

- revision 由 Main 为每个项目的最新持久场景生成，初始值为 0；每次成功提交最新场景后递增一次。
- Renderer 的 dirty generation 表示本地草稿顺序，Main 的项目写入队列表示持久化顺序；保存应答关联提交时的 generation。
- `CanvasContextSnapshot` 固化项目 ID、所选元素 ID 和选区 JSON；引用生成流程直接读取内存场景，文档 revision 保持由编辑保存链路管理。

Canvas 引用。

- 触发：用户点击 Use selection 后，CanvasSurface 为当前项目的已选元素生成一次性上下文。用户全选后使用同一入口创建全画布引用。
- 内容：选区复用 Save JSON 的元素序列化规则与 `type/version/source/elements/appState/files` 外层结构；`elements` 包含当前选中的有效元素，普通文字直接使用 text element 的 `text` 字段。图片元素通过 `fileId` 关联资源，Host 按模型能力添加独立 media 输入。
- 准备：CanvasSurface 从内存场景冻结选区 JSON，并向 Main 提交项目 ID、选中元素 ID 与快照。Main 校验项目归属、选区 ID 与 JSON 元素的对应关系、数据结构和大小，随后在有界内存 registry 中登记快照并返回 contextId、元素数量与图片数量。画布持久化由独立的编辑保存链路负责。
- 生命周期：contextId 默认有效 10 分钟，Main 最多保留 32 条待使用引用。快照创建后保持固定内容，后续编辑通过再次点击 Use selection 创建新的引用。
- Composer：Canvas 引用与上传文件共享附件区的 chip 布局、移除交互和发送时机。Renderer 以 contextId 持有画布引用，以 attachmentId 持有文件引用，并在 RunRequest 中提交两类 ID。
- 项目范围：contextId 绑定创建时的项目 ID；项目切换刷新画布场景和 Composer 的画布引用。Main 在运行开始时校验引用归属。

Canvas 上下文链路。

```text
CanvasSurface 的 Use selection → 选区 JSON → Main Canvas context registry ┐
Main 文件选择器              → 文件引用 → Main attachment registry    ├→ Composer chips
                                                                      → RunRequest 两类 ID
                                                                      → Main 按项目校验并解析
                                                                      → Runner 组装本次运行输入
                                                                      → Runtime messages
                                                                      → Adapter → Provider
```

1. CanvasSurface 准备选区 JSON；Main 的 Canvas registry 登记短生命周期引用。文件选择器经 Main 登记本地文件引用。
2. Composer 将两类引用作为同一份待发送草稿展示，用户发送时在 RunRequest 中提交 attachmentIds、canvasContextIds 和 projectId。
3. Main 在启动 Run 前验证文件可读性与 Canvas 项目归属，并解析两类 ID。文件引用提供路径与文件工具提示；Canvas 引用提供已冻结的选区 JSON 和按需附带的图片 media。
4. Runner 将文件提示并入当前任务，将 Canvas JSON 映射为本次运行的 `ModelMessage`；Runtime 依次装入历史、运行期上下文和本次用户消息。
5. Main 在 Run 启动成功后标记 Canvas contextId 已使用；Composer 在成功 ack 后清理两类引用。Adapter 将 Runtime 消息转换为 Provider 请求。

运行边界。

- `HistoryRecorder.commitUser` 保存用户输入的任务文字；Canvas 选区 JSON 在本次 Run 的内存 messages 中提供上下文。
- 同一 Run 的模型重试和工具续轮使用同一个冻结快照；新的 Run 通过新的用户引用取得画布内容。
- 图片元素的视觉内容遵循模型 media 能力；界面展示实际加入模型请求的内容类型。

失败、失效与恢复。

- 场景加载失败时，Canvas 显示错误和重试入口，原项目场景文件保持原状。
- 场景保存失败时，Renderer 保留最新 dirty generation、显示保存失败状态，并继续使用最新草稿重试。
- 选区准备失败时，Composer 保持原有草稿，Canvas 显示可重试错误。
- contextId 过期或超出容量时，Main 返回引用失效错误，Composer 保留任务草稿并提示用户重新建立引用。
- 用户移除 chip 时，Composer 更新待发送 ID 列表，registry 按 TTL 回收对应快照。
- Run 启动失败时，Composer 保留任务、文件附件与 Canvas 引用；Main 保留仍有效的 contextId 供再次提交。
- Provider 返回图片能力错误时，界面展示对应资源类型与重试入口；Canvas 场景继续保持当前编辑状态。
