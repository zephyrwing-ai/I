# 文本渲染与标点规范化

## 渲染管道

模型思考块、过程文本与最终答案共用唯一出口 `MarkdownText`（`frontend/src/middle-column/message-stream/MarkdownText.tsx`）：

```
模型原始文本
  → ReactMarkdown 解析出 mdast（结构此时已知）
  → 标点规范化：遍历全部 text 节点（mdast 级，punctuation-md.ts）
  → 渲染 React 元素
```

- `remark-gfm`：表格、删除线、任务列表。
- `remark-breaks`：单个换行渲染 `<br>`，延续消息区"行贴着行"的既有节奏。
- `components` 覆盖：`strong`、`em`、`del` 直接渲染子内容——行内强调（`**加粗**`、`*斜体*`、`~~删除线~~`）都以纯文本呈现，结构类格式化（列表、标题、表格、代码块、引用）保留。
- 规范化插件排在解析之后：结构已知后再改文本；代码与行内代码不产生 text 节点，天然豁免；链接地址/图片地址只存在于节点属性，从不进入规范化视野。
- 原始数据零改动:agent/loop 聚合、IPC、reducer 均保持模型原文；展示层完成全部规范化与结构转换；复制与导出取原文。

## 标点规范化规则

全局默认生效，无设置开关。中文文本的标点统一为**英文半角 + 标点后英文空格**，避免全角标点与无空格导致的"太挤、看不清"。

- 纯英文文本：短路返回（英文本就使用 ASCII 标点与空格）。
- 含汉字（含中英混排）：所有全角标点转半角（`，、` → `,`），每个半角标点后补一个英文空格（`你好，世界。` → `你好, 世界.`）。

### 全角 → 半角映射表

| 全角 | 转 | | 全角 | 转 |
|---|---|---|---|---|
| 逗号 ， | `,` | | 感叹号 ！ | `!` |
| 顿号 、 | `,` | | 问号 ？ | `?` |
| 分号 ； | `;` | | 括号 （ ） | `( )` |
| 冒号 ： | `:` | | 方括号 【 】 | `[ ]` |
| 句号 。 | `.` | | 引号 “ ” ‘ ’ | `" '` |
| 波浪 ～ | `~` | | 百分号 ％ | `%` |

### 补空格规则

半角标点 `, . ; : ! ?` 后补一个 ASCII 空格，以下情形跳过：

- 已带空格或相邻标点/闭合括号（`好的, 然后.`、`…)`）。
- 词内标点：前后都是字母数字下划线（`3.14`、`1.2.3`、`10:30`、`package.json`、`goo.gl` 保持原样）。
- URL 或路径分隔（`://` 后的 `/` 后不补：`https://example.com`）。
- 引号前**补**：`他说: "你好"`（规则优先于视觉偏好）。

## 结构级豁免（相对字符串级的改进）

- 围栏代码块与行内代码：按节点类型豁免。字符串级只能扫描 ``` 围栏，行内代码内的全角标点会被转换；mdast 版按节点判断，行内代码整体豁免。
- 节点边界补空格用**下一可见字符**：`你好,**世界**` 中逗号后看到的是「世」而非标记字符 `*`，空格补在正确位置；`10, **30**` 这类数字相邻时保持词内保护。
- 表格单元格、任务列表文本属于行内文本节点，走同一套规范化。

规则同源：映射表、补空格集合、词内保护与字符串级（punctuation.ts）共用同一份常量，与用户气泡路径的行为保持一致。

## 实现位置

- `frontend/src/utils/punctuation-md.ts` — remark 插件 `normalizeMdast`：遍历全部 text 节点做映射+补空格，边界用下一可见字符（`firstVisibleChar`）。
- `frontend/src/utils/punctuation.ts` — 字符串级纯函数，用于用户消息气泡与复制行任务文本（引用回显场景保持纯文本段落观感）。
- `frontend/src/middle-column/message-stream/MarkdownText.tsx` — 唯一结构出口：`Memo` 包裹；外链带 `target="_blank"` + `rel="noopener noreferrer"`，由 Main 的 `setWindowOpenHandler` 转系统浏览器；表格包 `.md-table-wrap` 横向滚动；`strong`/`em`/`del` 按纯文本渲染（只保留结构类格式化）。
- `frontend/src/middle-column/message-stream/message-stream.css` — `.markdown` 结构样式：块间距节奏（基础相邻块8px，与思考块一致；标题、列表、表格、代码块、引用、分隔线等结构块上下边距各12px）、代码块表面填充+边框+横向滚动、表格细边框、任务列表只读复选框、链接下划线、标题与列表排版。

## 数据链路

- 无后端改动:`agent/loop.ts` 的 `assistantDelta`、IPC、`agentReducer` 维持原样,全部搬运原始文本。
- 规范化与结构两条职责都在渲染层完成;数据层、复制（MessageMeta）与导出拿到的始终是模型原文。

## 测试

`tests/markdown-rendering.test.ts`（node:test，`npm test`，10 例）：加粗+标点、行内代码豁免、围栏代码块豁免、单换行 `<br>`、GFM 表格、任务列表、链接地址不改动+外链新窗口、节点边界补空格（可见字符）、纯英文短路、词内标点保护。

## 边界说明

- 未闭合 ``` 围栏按 CommonMark 规范渲染为代码块直至文末，豁免随之生效（行为与字符串级判断一致）。
- 强调标记的呈现规则：配对的 `**`/`*`/`~~` 经解析后以纯文本渲染（标记消失，不加粗、不加斜、不变删除线）；未配对的 `**`（奇数个星号，或成对被空行拆散）解析不到成对结构，按普通字符原样显示；代码块与行内代码内的标记按代码原样呈现，属正确豁免。
- 用户气泡内未被反引号包裹的粘贴代码若含全角标点，按引用原文展示（字符串级规范化的既定情形）；用户气泡接入 `MarkdownText` 之后，豁免即刻切换到结构级。
