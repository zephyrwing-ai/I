上下文管理。

- 范围：项目与 General 各自保存完整历史，模型请求使用对应范围的摘要、摘要覆盖范围之后的已提交原文和本轮材料。
- 调度：Runtime 在每次任务模型请求前调用上下文准备，负责回合推进、取消和重试；上下文模块负责读取、组装、计量与按需压缩。
- 模块：`agent/context/` 定义上下文准备与压缩策略，`agent/memory/` 的 Repository 负责 SQLite 历史读取和压缩快照保存，`shell/main/runner.ts` 提供本轮材料。
- 请求：Provider Adapter 统一处理任务请求与摘要请求的协议转换、流解析、凭据读取和错误归一化。
- 协作：[项目历史存储](./memory.mdx)定义记录与事务契约，[模型请求](./model-request.mdx)定义适配接口，[运行循环](./runtime-loop.mdx)定义调用与提交顺序。

模型能力。

- 契约：`ModelCapabilities` 保存 `contextWindowTokens`、可选 `maxInputTokens` 与 `maxOutputTokens`，分别表示完整窗口、独立输入上限与最大输出能力；可选 `inputModalities` 表达已声明的文字与图片输入能力，`source` 使用 `provider`、`catalog` 或 `manual` 标记来源。
- 获取：模型发现读取服务返回的窗口、输入和输出能力字段，统一成模型能力对象；官方原生端点使用本地目录补齐对应精确模型标识的能力资料，目录保留官方来源和核验日期。
- 保存：ProviderStore 将能力资料随模型记录保存，模型目录返回和 `resolve()` 沿用同一契约；同 origin 刷新保留手动配置，服务资料、官方目录与已保存资料依次补齐其他字段。
- 传递：Main 根据所选 `modelOptionId` 解析连接和模型能力，Runner 将能力传入 `ModelConfig.capabilities`，并结合宿主配置计算完整预算；运行期间使用本次捕获的模型资料。
- 计算位置：`agent/context/policy.ts` 的 `resolveContextPolicy()` 是上下文准备中的纯函数，统一计算和校验预算；`agent/context/config.ts` 读取环境覆盖并调用该函数，Runtime 和上下文模块在请求边界复核同一策略。
- CLI：`I_MODEL_ID` 选择模型，能力从所选原生端点的本地目录读取，`DEEPSEEK_BASE_URL` 配置连接地址；运行期能力解析使用已有资料。

上下文读取与组装。

- 摘要读取：按项目范围读取可复用的压缩快照，取得 `summary`、`coveredThroughOrder`、`baselineThroughOrder` 与 `baselineTokens`。
- 原文读取：按 `entryOrder` 分页读取 `coveredThroughOrder` 之后的 completed 原文；首次建立上下文时，从该范围起点读取已提交记录，运行期间按游标增量更新。
- 日常追加：新的用户消息、完整助手消息与工具结果按提交顺序追加原文，已有摘要继续复用，摘要更新由压缩条件驱动。
- 来源：原文保留 `entryId`、`entryOrder`、`revision`、`runId`、`turnId` 与 `toolCallId`；项目、Canvas 和附件材料保留来源身份、项目范围与捕获版本。
- 用户输入：本 run 的起始输入与最新补充输入保留原文，各输入身份进入一次；已应用的补充输入按接收顺序进入请求，摘要中的目标与约束延续较早要求。
- 请求顺序：固定指令与工具定义构成稳定前缀，已有摘要和其后的已提交原文维持历史顺序，本轮材料按运行引用位置组装；用户输入、助手消息和工具结果保持因果关系，每个输入身份贡献一次内容。
- 本轮材料：项目地图与 Canvas 文本、图片使用本轮冻结引用；附件的 ID、有预算文字与图片标签跟随所属用户消息进入请求和容量计算，图片字节在 Adapter 请求边界从应用管理的缓存读取。
- 大型结果：工具长正文使用首尾预览，并携带原始 `entryId`；完整正文、工具参数与媒体保存在原文记录中，`history_read` 按相同历史范围和记录身份分页回读。
- 回读：`history_read` 默认返回6000个 Unicode 字符，上限12000；来源头包含原文顺序与版本，内联图片在首屏返回，附件引用通过 attachment_read 读取缓存文字与图片，目录与文件内容继续使用文件工具读取。

容量与双阈值。

- 总量：完整输入包含固定指令、工具定义、摘要、保留原文、媒体、本轮材料和协议开销，使用统一估算口径；文本按 ASCII 与 UTF-8 大小估算，单张图片采用4096 tokens应用估算额度。
- 工作窗口：已知模型窗口或显式 `windowTokens` 启用自适应预算，工作窗口 `W` 取显式配置与模型窗口中的较小值；单一来源直接提供对应窗口。
- 输出预留：自动值为 `floor(W / 16)` 与16384 tokens中的较小值，下界为1；任务输出预留和摘要输出预算同时受模型 `maxOutputTokens` 与 `W - 1` 约束。
- 安全余量：自动值为 `floor(W / 16)`、16384 tokens与已声明的 `floor(maxInputTokens / 16)` 中的较小值，为估算误差与请求开销保留空间；独立输入上限缺省时由工作窗口约束。
- 安全输入上限：输入上限 `L = min(W - outputReserveTokens, maxInputTokens) - safetyTokens`；独立输入能力省略时，使用 `W - outputReserveTokens` 参与计算。
- 初始基线：首次建立上下文时，以固定指令和工具定义计量初始基线，已提交原文与本轮材料随完整输入增长，达到增长阈值时选取可整理历史。
- 压缩后基线：压缩完成后，对下一次任务请求的完整输入计量，将结果保存为 `baselineTokens`，并以 `baselineThroughOrder` 记录基线包含的最新已提交原文位置。
- 增长量：以摘要和 `baselineThroughOrder` 内的原文为基线内容，结合本次指令、工具和材料重新计量；完整输入估算减去重计基线，以零为下界，保留原文继续属于基线范围。
- 增长阈值：自动值为 `floor(W / 2)` 与 `L - 1` 中的较小值，下界为1；完整输入相对压缩后基线的增长量达到 `growthTokens` 时触发压缩。
- 总量阈值：完整输入达到安全输入上限时触发压缩，为模型容量提供独立边界。
- 触发关系：增长阈值与总量阈值采用 OR，任一满足即进入同一次摘要流程，同时满足时共享一次压缩操作。
- 计量更新：Provider usage 提供实测输入、输出和缓存计数；较高的实测输入校准后续总量估算，压缩与模型切换采用新上下文重新计量，缓存作为输入子集单独记录。
- 配置入口：`ModelConfig.context` 保存 `windowTokens`、`outputReserveTokens`、`safetyTokens`、`growthTokens`、`recentTokens` 和 `summaryTokens`，分别表达工作窗口、任务输出预留、安全余量、增长阈值、近期原文预算与摘要输出预算。
- 输出预算：任务请求使用 `outputReserveTokens`，摘要请求使用 `summaryTokens`，两类预算均传入统一 Adapter，并受对应工作窗口约束。
- 摘要预算：自动值取8192、`floor(W / 64)` 与 `floor(L / 8)` 中的较小值，下界为1，再应用模型输出约束；摘要实际长度由生成结果决定。
- 原文预算：自动值取64000、`floor(W × 0.15)` 与 `L - summaryTokens - 1` 中的较小值，下界为1，按该预算选取近期完整交互。
- 配置覆盖：显式字段覆盖对应自动值，工作窗口和两类输出预算继续受已知模型能力约束；增长阈值小于 `L`，近期原文与摘要预算之和小于 `L`，配置冲突返回 `config` 错误。
- 容量回退：模型能力与显式窗口均为空时，使用32768 tokens工作窗口、4096输出预留、2048安全余量、8192增长阈值、8192近期原文和2048摘要预算；能力待确认的网关通过服务资料、手动模型配置或显式窗口提供容量依据。
- 宿主配置：`I_CONTEXT_WINDOW_TOKENS`、`I_CONTEXT_OUTPUT_RESERVE_TOKENS`、`I_CONTEXT_SAFETY_TOKENS`、`I_CONTEXT_GROWTH_TOKENS`、`I_CONTEXT_RECENT_TOKENS` 和 `I_CONTEXT_SUMMARY_TOKENS` 分别覆盖对应字段，CLI 与桌面端共用配置读取和校验。
- 请求顺序：Runner 捕获模型能力并解析预算，Runtime 提交新输入后调用上下文准备；准备流程先复核预算，再组装包含新输入的候选上下文，完成计量和双阈值判断，按需压缩并重新组装后发送模型请求。
- 模型变化：新 run 选用对应模型能力和配置重新计算预算，已有摘要与原文在新预算下重新计量；同一能力与配置得到稳定预算，消息增长推动占用变化。

上下文压缩。

- 调用时机：Runtime 在启动恢复与用户输入提交后准备首次请求；工具续轮在整批 Tool Message 提交、边界补充输入应用后重新准备。
- 选取：从最新原文向前累积预计 token，按近期原文预算保留连续交互；最近完整工具交互中的调用与结果共同保留。
- 摘要范围：近期原文起点之前的完整交互构成本次新增覆盖区间，已有摘要与新增区间共同进入摘要请求。
- 长交互：单个用户交互包含多个助手回合时，在工具结果配齐的回合边界切分，前段要求与进展进入摘要，后段完整原文继续保留。
- 独立请求：达到任一阈值后，通过统一 Adapter 发起独立摘要请求，使用专用摘要指令与独立输入、输出预算，工具定义采用空集合。
- 摘要内容：包含目标、约束与偏好、进展、关键决定及原因、下一步和重要材料，保留精确文件路径、符号、命令、错误与证据定位。
- 合并：根据已有摘要与本次新增区间，按时间和来源整合用户修正、工作状态及待核对结果；新摘要覆盖范围延伸至 `coveredThroughOrder`。
- 分批：历史超过摘要请求容量时，按完整交互分批处理，每批合并已有摘要与新增区间。
- 摘要适配：切换到较小窗口后，已有摘要按新预算单独重整；较长摘要沿 Unicode 文本片段顺序合并，每次请求测量完整输入，片段游标单调前进。
- 完成条件：摘要请求以成功终止原因、有效正文与空工具调用列表形成结果，再以新摘要、保留原文和本轮材料组装完整输入。
- 容量检查：候选输入核对工具配对、总量与缩减收益；增长触发的候选保持原规模时，继续使用稳定上下文并记录已尝试边界，新增可整理区间推动下一次摘要。
- 容量异常：必要材料、单个完整历史交互或候选输入超出对应预算时，返回明确容量错误，引导调整材料范围或工作预算。

压缩快照。

- 内容：保存项目范围、`summary`、`coveredThroughOrder`、`baselineThroughOrder`、`baselineTokens`、来源版本、策略版本、生成模型与用量。
- 摘要游标：`coveredThroughOrder` 表达摘要覆盖的最后一条原文，之后的已提交记录继续按原文读取。
- 基线游标：`baselineThroughOrder` 表达压缩后完整输入包含的最新原文位置，与 `baselineTokens` 共同保存增长计算起点；保留原文位于摘要游标之后，可同时属于基线范围。
- 原子提交：Repository 在 SQLite 事务中核对来源并保存压缩快照，Runtime 在提交成功后采用新摘要与保留原文继续任务请求。
- 来源校验：对摘要来源截至基线游标的已提交记录身份、顺序和版本计算固定大小 digest，保存时核对来源与快照版本，版本冲突保留已有稳定记录。
- 原始记录：完整 entries、工具 outcome 与执行恢复账本持续保存在历史存储，摘要通过覆盖范围关联原始证据。
- 重启复用：加载已提交压缩快照，读取摘要覆盖范围之后的原文，结合当前请求重新计量基线并继续计算增长量。
- 来源变化：记录版本或计量配置发生变化时，重新核对快照适用范围与完整输入规模，再确定摘要与基线。

取消与恢复。

- 补充输入：整理期间接收的文本先进入持久化队列，再按既有回合安全边界应用。
- 停止：上下文准备和摘要请求沿用本 run 的取消信号与持久化取消事实。
- 摘要异常：失败、长度截断或取消保留完整历史与上一份已提交压缩快照，由 Runtime 按对应错误与取消语义收尾。
- 保存异常：压缩快照提交沿用本地事务重试边界，已生成摘要和来源身份在同一次提交重试中保持稳定。
- 普通重试：同一逻辑回合的模型重试复用已准备好的稳定上下文。
- 溢出恢复：上下文溢出使用有次数边界的重新准备流程，沿用已有工具执行事实，并通过同一摘要流程形成可用输入。
- 必要材料超限：固定指令、最新输入或必要材料超过可用容量时，Runtime 通过运行错误返回容量提示，由用户调整引用范围或模型配置。
