title: 会话存储实现清单
description: 会话本地存储跨模块实现顺序、代码入口与验证标准。

交付结果。

- Agent 使用 SQLite 保存 sessions 和 entries。
- 每次运行绑定一个确定的 sessionId。
- Runtime 从 SessionRecorder 取得 completed ModelMessage 快照。
- 用户消息、完整助手消息和工具结果在对应语义边界完成本地提交。
- 模型增量持续更新 Recorder 内存草稿，并按照500毫秒或4096字节阈值合并写入。
- Renderer 延续现有 AgentEvent 流式渲染链路。

一、实现会话存储模块。

- [x] 创建 `agent/memory/types.ts`，定义 Session、SessionEntry、EntryStatus、EntryType、MessageCommitContext、TurnCommitContext、ToolCommitContext、RecordedRunStatus 和 revision 更新结果。
- [x] 创建 `agent/memory/schema.ts`，定义 sessions、entries、唯一索引和 schema version。
- [x] 创建 `agent/memory/repository.ts`，定义 createSession、getSession、appendEntry、updateEntry、getEntry、listEntries 和 updateSession。
- [x] 在 Repository 中提供按 scopeKey 读取最近 active 或 waiting 会话的查询，供 Host 会话路由使用。
- [x] 创建 `agent/memory/sqlite-repository.ts`，使用 `node:sqlite`、prepared statements 和显式事务实现 Repository。
- [x] 创建 `agent/memory/session-recorder.ts`，实现 completed 消息快照、活动草稿、合并写入队列和终态刷新。
- [x] 在 `agent/memory/session-recorder.ts` 提供临时 Recorder 工厂，供 CLI 和隔离测试使用相同的 Runtime 契约。
- [x] 创建 `agent/memory/index.ts`，导出模块公开契约。
- [x] 使用 `journal_mode=WAL`、`foreign_keys=ON`、`synchronous=FULL` 和 `busy_timeout=5000` 初始化数据库连接。
- [x] 使用 `(session_id, session_seq)` 唯一索引和 sessions.next_entry_seq 事务生成会话顺序。
- [x] 使用 revision 条件更新会话与草稿，并为重复追加返回稳定结果。
- [x] 保存 payload_version，并按当前版本解码持久化记录。

二、接入 Runtime Loop。

- [x] 在 `agent/loop.ts` 的 AgentRunConfig 中接收 SessionRecorder，并由 Recorder 提供初始消息快照。
- [x] 删除 history 与 Recorder 并行提供上下文的双入口。
- [x] 由 Runtime 创建一次用户 ModelMessage，并在第一次 Provider 请求前等待 commitUser。
- [x] 在 reasoning_delta 和 text_delta 分支同步调用 recordAssistantDelta，并继续发出已有 AgentEvent。
- [x] 记录 completed 终态；模型流结束时校验该终态并将终态缺失归为 model_protocol 错误。
- [x] 构造完整 Assistant Message 后等待 commitAssistant，成功后加入本次运行上下文并发出 assistantCompleted。
- [x] 带 toolCalls 的 Assistant Message 提交成功后进入工具执行。
- [x] 构造 Tool Message 后等待 commitToolResult，成功后加入本次运行上下文并发出 toolCompleted。
- [x] 将 finish 改为异步终态路径，等待 finishRun 刷新活动草稿后发出 runCompleted。
- [x] 删除 onMessageFinalized 回调及其调用点。

三、接入桌面 Runner 与 Main。

- [x] SessionRecorder 和 AgentEvents 作为两个独立接收器传入 Runtime，Runtime 分别调用二者。
- [x] 保持 AgentEvents 到 `emitOnce` 的现有 IPC 转发路径。
- [x] 保持 Renderer eventQueue 与 Reducer 的现有流式消费路径。
- [x] 使用 Recorder 私有队列处理 SQLite 草稿刷新，Renderer 与 Recorder 通过稳定 ID 关联。
- [x] 在 `shell/main/index.ts` 的应用就绪阶段创建 SqliteSessionRepository，并使用 `app.getPath("userData")` 生成数据库路径。
- [x] 在应用退出阶段停止运行、等待 Runner 空闲、刷新 Recorder 并关闭 SQLite 连接。
