项目历史存储实现清单。

- 范围：记录项目历史、目录缓存、Runtime 提交和桌面装配的跨模块实现状态，具体契约由各模块设计文档维护。

数据存储。

- 项目：`projects` 已保存 `projectId`、规范化路径、显示名称和最近激活时间。
- 上下文：`project_context` 已保存有界目录树、hash、扫描策略和 dirty 状态。
- 消息：`entries` 使用可空 `project_id` 绑定项目或 General，并通过全局 `entry_order` 排序。
- 工具：`tool_invocations` 使用可空 `project_id` 与 `run_id + tool_call_id` 关联调用。
- 迁移：旧 sessions 数据归入 General，覆盖 v1 工具账本创建、v2 工作目录迁移、后续工具账本和项目范围 v8。
- 取消：schema v9 引入 `run_cancellations`，持久保存用户主动停止事实。

HistoryRecorder 与 Runtime。

- 契约：持久化接口统一为 `HistoryRecorder`，以 `projectId` 的真实 ID 或 `null` 绑定历史范围。
- 提交：用户消息、助手草稿、完整助手消息、工具结果和执行账本均沿用本地提交屏障。
- 工具计划：完整工具调用型 Assistant Message 与整批 planned invocation 在单事务登记，任一冲突使整批回滚。
- 取消：等待执行的调用结算 cancelled，结果待核对的调用结算 interrupted，已确定的 outcome 继续复用；后续运行依据取消事实恢复结算结果。
- Canvas：跨 run 调度能力为关闭状态的 planned 调用直接结算 interrupted，attemptCount 保持零。
- 上下文：项目目录地图以 transient Runtime context 注入模型请求。

Main 与 IPC。

- 项目管理：Main 负责目录规范化、项目创建、项目恢复与 General 范围。
- 桥接：Preload 提供 `getActiveProject`、`selectProject`、`clearProject` 和 `loadHistoryPage`。
- Recorder：Main 按项目范围创建并缓存 HistoryRecorder。
- 切换：运行空闲时更新历史、Canvas 和目录上下文范围。

Renderer 与 Composer。

- 项目入口：Composer 顶部显示项目选择行，空状态为 `Choose folder`，项目状态为目录名称。
- 图标：项目入口采用圆润的 `folder-closed` 图标。
- 历史：项目切换后重新加载对应范围的历史投影。
- 运行期间：项目选择与清除入口保持禁用，当前运行沿用启动配置。
