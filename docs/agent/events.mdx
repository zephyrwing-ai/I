---
title: 运行事件
description: Agent 向宿主报告运行、回合、模型消息和工具调用的结构化事件契约。
---

运行事件是 Agent Runtime 对宿主的唯一过程输出。Agent 不直接修改宿主状态，也不假设宿主使用 Electron、React、终端或其他界面技术。

## 身份层级

事件使用 `runId → turnId → attempt → toolCallId` 四层稳定身份：

| 身份 | 生命周期 | 作用 |
| --- | --- | --- |
| `runId` | 一次完整任务运行 | 隔离重试、取消和并发运行 |
| `turnId` | 一次逻辑模型回合及其工具批次 | 关联多次 attempt 的流式正文、完整消息和本回合工具调用 |
| `attempt` | 同一逻辑 turn 内的一次模型尝试 | 关联增量草稿、重试状态和终态 |
| `toolCallId` | 模型产生的一次工具调用 | 关联工具开始、增量结果、完成结果和回填消息 |

身份不能由数组位置、“最后一条消息”或显示顺序推导。事件允许异步到达，宿主仍应能够把结果归入原始运行对象。

运行中输入使用独立 `inputId`：它标识一次补充文本提交，横向关联 Main 的持久化 ACK、Runtime 的应用事件与最终用户 entry。同一个 `runId` 可以包含多个 `inputId` 和多个 `turnId`。

## 事件协议

Agent 发出以下事件：运行开始、回合开始、Assistant 正文增量、思考增量、回合重试、Assistant 完成、工具开始、工具完成、回合完成和运行完成。每类事件都携带 `runId`；回合事件还携带 `turnId`；重试事件携带当前与下一次 attempt；工具事件还携带 `toolCallId`。

`assistantCompleted` 报告归一化 Assistant Message 和停止原因；`toolCompleted` 报告结构化工具结果；`runCompleted` 携带 `completed`、`cancelled` 或 `failed`，并可附带结构化 `RunError` 和诊断信息。`runStarted` 携带 `startedAt`，其他过程事件保持各自字段。

协议中不存在 `stepLimit`、`maxSteps` 或其他按次数终止字段。可选的 `turnOrdinal` 和 `turnCount` 只用于排序与诊断，Runtime 不能读取它们作为退出条件。

## 事件与项目历史记录

AgentEvent 负责报告运行过程，HistoryRecorder 负责保存项目或无项目历史。Host 分别向 Runtime 注入事件接收器和绑定 `projectId: string | null` 的 Recorder，Runtime 在同一个语义节点分别调用两者。

- `reasoningDelta` 和 `assistantDelta` 携带 `runId`、`turnId` 与冻结的 delta 字符串。
- Runtime 把 delta 同步交给 Recorder 更新内存草稿，并把同一 delta 发为 AgentEvent。
- `turnRetrying` 只在 Runtime 已经将当前 attempt 保存为 interrupted/failed 后发出；它报告 reason、attempt、nextAttempt、delayMs 和 maxAttempts。
- `assistantCompleted` 在完整 Assistant Message 成功提交并加入 Runtime.messages 后发出。
- `toolCompleted` 在完整 Tool Message 成功提交后发出。
- `runCompleted` 在 `finishRun` 完成终态提交后发出。
- Recorder 和事件接收器分别维护自己的队列与状态，二者通过稳定 ID 和冻结事件值关联。
- `onMessageFinalized` 由 HistoryRecorder 的 `commitUser`、`commitAssistant` 和 `commitToolResult` 取代。

HistoryRecorder 的接口与写入规则由[项目历史存储](./memory.mdx)定义。Runner 的注入和 IPC 转发由[历史存储装配](../desktop/design/workbench/session-storage.mdx)定义。

## 运行中输入事件契约

`steer` IPC 的 ACK 由 Main 返回给发送方，携带 `runId`、`projectId`、`inputId`、`acceptOrder` 和 `acceptedAt`；它表示待处理输入已经持久化并绑定当前 run。ACK 是接收协议，AgentEvent `inputsApplied` 是实际模型上下文协议。

Runtime 在安全边界完成同批输入的事务提交、内存上下文更新后发出 `inputsApplied`。事件携带 `runId`、按接收顺序排列的 `inputIds` 和 `startedAt`。`startedAt` 对应这一批用户消息实际注入下一次模型请求的时刻；后续 `turnStarted` 使用新的 `turnId`。同一模型回合的助手消息和工具结果先完成提交并发出对应事件，随后才出现 `inputsApplied`。

每条 steer 提交拥有独立 `inputId`；同一安全边界应用的多条输入按 FIFO 顺序记录于 `inputsApplied.inputIds`。事件接收方依据 `inputId` 归并 ACK、应用结果与历史 entry，并依据原始 `turnId` 关联助手增量、完整消息和工具批次。

Runner 在完成路径先通过 Recorder 为剩余已接收输入提交同 `inputId` 的 interrupted 用户 entries，并把队列状态更新为 `unapplied`，随后发出唯一 `runCompleted`。事件携带 `unappliedInputIds`；成功完成的事件携带 `finalTurnId` 和整个 run 的 `finalDurationMs`。历史记录保留 completed 与 interrupted entries；启动恢复执行相同的 interrupted entry 归档。完成边界和入队由 Main 的串行门控决定，封闭后收到的 `steer` 请求获得明确拒绝。

Run 级时长以 `runStarted.startedAt` 为起点，以运行终态为终点。`runCompleted.finalDurationMs` 对应整个 `runId` 的工作时长，并与最终 Assistant Message 的持久化 `durationMs` 保持一致。`runCompleted.finalTurnId` 标识保存这份时长的最终 Assistant Message。

## 顺序与终止

同一回合中，Agent 先发出 `turnStarted`，再发出 Assistant 增量。只有完整回答或完整工具调用才发出 `assistantCompleted`；不完整 attempt 发出 `turnRetrying`，下一次 attempt 仍使用同一个 `turnId` 并递增 attempt。存在工具调用时，每个调用分别发出开始与完成事件，所有调用处理完后发出 `turnCompleted`。运行结束时只发出一次 `runCompleted`。

当前 Runtime 串行执行工具。协议以稳定 ID 关联，为未来并发完成保留空间；引入并发后，完成顺序可以不同于模型中的排列顺序。稳定 ID 是关联事实，事件到达顺序只用于过程展示，不能替代关联关系。

模型请求失败、取消信号、运行时异常和自然完成最终都必须收敛到唯一的 `runCompleted`。普通工具错误仍通过 `toolCompleted` 返回，并由 Runtime 回填模型；除非错误破坏 Runtime 本身，否则它不直接终止 run。

## 错误与敏感信息

`RunError` 当前包含稳定的错误类型、用户可读消息，以及可选的 `retryable`；`diagnosticId` 关联属于后续目标，当前类型未定义。错误类型区分配置、网络、Provider、模型协议、工具和 Runtime。

事件不得包含 API Key、Authorization header 或 Provider 的完整敏感请求负载。后续诊断日志可以通过 `diagnosticId` 关联，但不能把敏感值复制回事件。

## 验证

- 任意结束路径只产生一个 `runCompleted`。
- 同一个模型 delta 分别进入 Recorder 和 AgentEvent 接收器，并保持相同 `runId` 与 `turnId`。
- `assistantCompleted` 在 Assistant Message 本地提交完成后产生。
- `turnRetrying` 在 interrupted/failed attempt 本地提交完成后产生。
- `toolCompleted` 在 Tool Message 本地提交完成后产生。
- `runCompleted` 在 Recorder 完成终态刷新后产生。
- 两个工具调用乱序完成时仍关联到各自的 `toolCallId`。
- 工具错误完成后，Runtime 可以把同一结果回填模型并继续下一回合。
- 两条补充文本先收到各自的持久化 ACK，在安全边界获得按序的 `inputsApplied.inputIds`。
- `inputsApplied` 出现在当前 Assistant、全部 Tool Message 提交之后和下一次 `turnStarted` 之前。
- 运行终态提交后，`runCompleted.unappliedInputIds` 与已写入的 interrupted 用户 entries 对应；历史恢复依据 `inputId` 关联相同记录。
- 中止模型请求或工具执行后，运行最终进入 `cancelled`，不再产生新的模型请求。
- 任何事件都不包含 API Key 或 Authorization header。
