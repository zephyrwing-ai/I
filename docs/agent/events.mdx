---
title: 运行事件
description: Agent 向宿主报告运行、回合、模型消息和工具调用的结构化事件契约。
---

运行事件是 Agent Runtime 对宿主的唯一过程输出。Agent 不直接修改宿主状态，也不假设宿主使用 Electron、React、终端或其他界面技术。

## 身份层级

事件使用 `runId → turnId → toolCallId` 三层稳定身份：

| 身份 | 生命周期 | 作用 |
| --- | --- | --- |
| `runId` | 一次完整任务运行 | 隔离重试、取消和并发运行 |
| `turnId` | 一次模型请求及其工具批次 | 关联流式正文、完整消息和本回合工具调用 |
| `toolCallId` | 模型产生的一次工具调用 | 关联工具开始、增量结果、完成结果和回填消息 |

身份不能由数组位置、“最后一条消息”或显示顺序推导。事件允许异步到达，宿主仍应能够把结果归入原始运行对象。

## 事件协议

Agent 发出以下事件：运行开始、回合开始、Assistant 正文增量、思考增量、Assistant 完成、工具开始、工具完成、回合完成和运行完成。每类事件都携带 `runId`；回合事件还携带 `turnId`；工具事件还携带 `toolCallId`。

`assistantCompleted` 报告归一化 Assistant Message 和停止原因；`toolCompleted` 报告结构化工具结果；`runCompleted` 携带 `completed`、`cancelled` 或 `failed`，并可附带结构化 `RunError` 和诊断信息。`runStarted` 携带 `startedAt`，其他过程事件保持各自字段。

协议中不存在 `stepLimit`、`maxSteps` 或其他按次数终止字段。可选的 `turnOrdinal` 和 `turnCount` 只用于排序与诊断，Runtime 不能读取它们作为退出条件。

## 事件与会话记录

AgentEvent 负责报告运行过程，SessionRecorder 负责保存会话记录。Host 分别向 Runtime 注入事件接收器和绑定 `sessionId` 的 Recorder，Runtime 在同一个语义节点分别调用两者。

- `reasoningDelta` 和 `assistantDelta` 携带 `runId`、`turnId` 与冻结的 delta 字符串。
- Runtime 把 delta 同步交给 Recorder 更新内存草稿，并把同一 delta 发为 AgentEvent。
- `assistantCompleted` 在完整 Assistant Message 成功提交后发出。
- `toolCompleted` 在完整 Tool Message 成功提交后发出。
- `runCompleted` 在 `finishRun` 完成终态提交后发出。
- Recorder 和事件接收器分别维护自己的队列与状态，二者通过稳定 ID 和冻结事件值关联。
- `onMessageFinalized` 由 SessionRecorder 的 `commitUser`、`commitAssistant` 和 `commitToolResult` 取代。

SessionRecorder 的接口与写入规则由[会话存储](./memory.mdx)定义。Runner 的注入和 IPC 转发由[会话存储装配](../desktop/design/workbench/session-storage.mdx)定义。

## 顺序与终止

同一回合中，Agent 先发出 `turnStarted`，再发出 Assistant 增量和完整消息；存在工具调用时，每个调用分别发出开始与完成事件，所有调用处理完后发出 `turnCompleted`。运行结束时只发出一次 `runCompleted`。

当前 Runtime 串行执行工具。协议以稳定 ID 关联，为未来并发完成保留空间；引入并发后，完成顺序可以不同于模型中的排列顺序。稳定 ID 是关联事实，事件到达顺序只用于过程展示，不能替代关联关系。

模型请求失败、取消信号、运行时异常和自然完成最终都必须收敛到唯一的 `runCompleted`。普通工具错误仍通过 `toolCompleted` 返回，并由 Runtime 回填模型；除非错误破坏 Runtime 本身，否则它不直接终止 run。

## 错误与敏感信息

`RunError` 当前包含稳定的错误类型、用户可读消息，以及可选的 `retryable`；`diagnosticId` 关联属于后续目标，当前类型未定义。错误类型区分配置、网络、Provider、模型协议、工具和 Runtime。

事件不得包含 API Key、Authorization header 或 Provider 的完整敏感请求负载。后续诊断日志可以通过 `diagnosticId` 关联，但不能把敏感值复制回事件。

## 验证

- 任意结束路径只产生一个 `runCompleted`。
- 同一个模型 delta 分别进入 Recorder 和 AgentEvent 接收器，并保持相同 `runId` 与 `turnId`。
- `assistantCompleted` 在 Assistant Message 本地提交完成后产生。
- `toolCompleted` 在 Tool Message 本地提交完成后产生。
- `runCompleted` 在 Recorder 完成终态刷新后产生。
- 两个工具调用乱序完成时仍关联到各自的 `toolCallId`。
- 工具错误完成后，Runtime 可以把同一结果回填模型并继续下一回合。
- 中止模型请求或工具执行后，运行最终进入 `cancelled`，不再产生新的模型请求。
- 任何事件都不包含 API Key 或 Authorization header。
