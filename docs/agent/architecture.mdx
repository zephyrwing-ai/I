本目录描述 Agent 内核如何保存会话、请求模型、判断是否继续、执行已注册工具，以及向宿主发出运行事件。桌面窗口、Electron IPC、Renderer 状态、设置、搜索和界面偏好归入 `docs/desktop/design/`。

## 当前实现边界

当前模型层实现 OpenAI 兼容协议，工具注册表已经注册 Bash、Read、Write、Edit、List Dir、Find Files 和 Search Content。Main 装配由 `agent/memory` 提供的 SessionRecorder 与 SQLite Repository；[会话存储](./memory.mdx)定义本地持久化契约，[会话存储实现清单](./session-storage-tasks.mdx)列出跨模块落地顺序。

## 分层职责

| 层 | 职责 | 协作边界 |
| --- | --- | --- |
| Host boundary | 提交冻结运行输入、提供取消信号、接收 Agent 事件 | Runtime 负责控制流，Tool Registry 负责工具定义 |
| Session Memory | 保存会话消息与草稿，提供完成消息快照和本地恢复 | Execution 负责工具，Desktop 负责页面渲染 |
| Agent Runtime | 编排模型请求、工具调用、工具结果和下一轮请求 | Host 负责平台装配，Desktop 负责页面状态 |
| Provider Adapter | 将不同模型协议归一化为统一消息、流事件和停止原因 | Execution 负责工具调用，Runtime 负责完成判断 |
| Tool Registry | 保存模型可见的工具定义与对应执行实现 | Provider 提供结构化调用，权限策略提供运行边界 |
| Execution | 执行经过注册和校验的 Bash、文件与查询操作，返回结构化结果 | Runtime 负责模型续轮，权限策略负责能力范围 |

宿主可以是 Electron 桌面端、CLI 或测试程序。Agent 只依赖稳定的输入、事件回调和执行接口，因此桌面交互变化不会反向污染运行循环。

## 跨模块主链路

一次运行从不可变的运行输入开始。宿主创建 `runId`、取消信号和绑定 `sessionId` 的 SessionRecorder。Runtime 提交用户消息后创建 `turnId` 并请求模型，完整 Assistant Message 提交后进入工具执行，完整 Tool Message 提交后进入下一次模型请求。没有工具调用时自然完成，模型错误进入失败，中止信号进入取消。

Agent 通过 SessionRecorder 保存会话事实，并通过结构化运行事件报告过程和唯一终止结果。宿主负责跨进程传递事件和渲染状态。


## 权限边界

Agent 的工具使用宿主提供的执行能力和权限。工作目录只决定相对路径解析和命令启动位置，不自动构成文件系统沙盒；是否采用系统沙盒、远程执行或额外权限确认，必须由宿主另行实现，Agent 文档不能把不存在的隔离能力描述为已经可用。

## 参考边界

运行循环的继续与结束语义借鉴同级 `pi` 项目的 `packages/agent/src/agent-loop.ts` 和对应测试：没有数值型循环上限；存在工具调用时执行并回填结果，没有工具调用时自然结束；模型请求 `error` / `aborted` 直接终止；普通工具错误返回模型后允许其恢复。

本项目只借鉴控制语义，不依赖 `pi` 的包，也不照搬它的 steering、follow-up 或动态工具加载等当前 Agent 契约之外的能力。
