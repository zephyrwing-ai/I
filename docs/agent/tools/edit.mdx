Edit。

- 状态：已实现并注册，定义与执行位于 `agent/tools/edit.ts`。
- 职责：通过精确文本匹配修改已有文本文件的一个或多个明确片段，并通过整文件原子发布交付最终结果。
- 协作：创建文件或整体重写使用 [Write](./write.mdx)，目标内容通过 [Read](./read.mdx) 确认。

调用。

- 参数：提交文件路径与一组“原文本 → 新文本”替换。
- 路径：采用绝对路径或基于工作目录解析的相对路径，满足非空字符串和有效文件系统路径要求。
- 文本：文件内容采用有效 UTF-8，文件与替换片段满足 NUL-free 文本约束。
- 匹配：每段原文本在本 attempt 的原始内容中唯一匹配，各段区间相互独立，全部替换共同基于同一份原始快照。
- 校验：准备阶段检查参数、文件类型、UTF-8、唯一匹配和区间；任一条件失败时返回具体错误，源文件保持原内容。
- 组装：最终文本通过原始快照的连续片段与替换片段一次组装，行号和变更摘要共同来自该快照。
- 编码：保留片段沿用原 BOM 与换行字节；新文本按 UTF-8 生成字节，JavaScript 孤立代理项转换为 U+FFFD。

准备与发布。

- 准备入口：每个真实 attempt 调用一次 `RegisteredTool.prepare`，读取原始字节，并计算一次最终字节、元数据、`beforeHash`、`afterHash` 和独占 staging 身份。
- 准备资源：持有只读句柄与内存，取消、准备失败及后续 SQL 失败时，原文件与目录布局保持原状。
- 直接执行：`execute` 复用同一份准备与执行协议。
- 执行登记：Runtime 通过 `beginToolAttempt` 在同一事务中持久化 checkpoint，再执行准备好的 closure；checkpoint 保存恢复证据，closure 持有实际发布字节，`afterHash` 与这些字节一致。
- 发布队列：与 [Write](./write.mdx) 共用按真实目标路径串行化的应用内发布器，队列管理本应用参与者的发布顺序。
- staging：在目标同目录以 `wx` 独占创建临时文件，写入最终字节，保留原文件权限位、uid 和 gid，完成文件 `fsync` 与关闭。
- 发布核对：再次核对源状态、符号链接指向和 staging 身份，完成最后一次取消检查后执行 `rename`，随后 `fsync` 目标父目录。
- 发布点：`rename` 发布完整目标内容；此前失败或取消时保留源文件并清理通过身份核对的本次 staging，此后按已发布事实报告结果。
- 文件语义：符号链接保留链接形态，Edit 跟随并核对真实目标；原文件写权限参与检查；硬链接、目录和特殊文件返回明确错误并保持原语义。
- 外部变化：发布前状态核对识别外部修改并返回冲突结果。

恢复。

- 版本：恢复协议保持 `1`，新 checkpoint 使用 `version: 2`，旧 v1 继续按原始字节哈希与大小进行保守核对。
- v2 核对：严格检查版本、kind、字段、路径、原文件身份、before/after 字节哈希，以及绑定 invocation/attempt 的 staging 相对路径，并记录目录同步边界。
- after 状态：匹配后先同步目标文件与目录链，再恢复成功结果。
- before 状态：匹配后允许基于最新文件准备新 attempt。
- 状态分歧：内容分歧、权限错误和 IO 错误返回 `interrupted`；文件缺失通过 `ENOENT` 单独识别。
- 清理：恢复清理同时核对 staging 收据、文件类型、单链接状态、完整字节与权限；部分 staging 或身份分歧时保留现场并返回 `interrupted`。
- 决策：默认发布协议根据实际状态确定成功、重试或中断。

结果。

- 成功：包含修改数量、变更摘要、差异文本、第一处变更行号和文件产物。
- 发布后取消：按已发布事实返回结果。
- 目录同步异常：返回 `interrupted` 并附带已发布产物，后续恢复通过 `afterHash` 核对效果。
- 失败：说明具体条件与文件系统原因，供模型上下文、运行事件和工作台展示读取。
