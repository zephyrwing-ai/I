实现状态：已实现并注册。Edit 定义与执行见 `agent/tools/edit.ts`。

Edit 用于修改已有文本文件中的一个或多个明确片段。它通过精确文本匹配表达局部改动，并通过整文件原子发布交付最终结果。

## 调用

一次调用包含文件路径和一组“原文本 → 新文本”替换。路径采用绝对路径或基于工作目录解析的相对路径，并满足非空字符串和有效文件系统路径要求。文件内容采用有效 UTF-8，文件和替换片段保持 NUL-free 文本约束。每段原文本在本 attempt 的原始内容中唯一匹配，各段替换的区间互相独立。所有替换共同基于同一份原始快照。

准备阶段完成参数、文件类型、UTF-8、唯一匹配和区间检查。任一条件失败时，整次调用返回具体错误，源文件保持原内容。最终文本通过原始快照的连续片段与替换片段一次组装，行号和变更摘要共同来自此快照。源文件中各保留片段的 BOM 与换行字节随内容继续保留；新文本按 UTF-8 编码规则生成字节，JavaScript 孤立代理项转换为 U+FFFD。

## 准备与发布

每个真实 attempt 调用一次 `RegisteredTool.prepare`，读取原始字节并计算一次最终字节、元数据、`beforeHash`、`afterHash` 与独占 staging 身份。准备只持有只读句柄和内存；取消、准备失败以及后续 SQL 失败都保留原文件与目录布局。直接 `execute` 复用这份准备与执行协议。

Runtime 将 checkpoint 随 `beginToolAttempt` 在同一事务中持久化，再执行准备好的 closure。checkpoint 是恢复证据，closure 发布其持有的最终字节，`afterHash` 与这些实际字节一致。

Edit 与 [Write](./write.mdx) 共用真实目标的应用内串行发布器。发布器在目标同目录以 `wx` 创建临时文件，写入最终字节，保留原文件权限位、uid 和 gid，完成文件 `fsync` 与关闭，再次核对源状态、符号链接指向和 staging 身份。最后一次取消检查通过后执行 `rename`，随后 `fsync` 目标父目录。`rename` 是发布点：此前的失败或取消保留源文件并清理经身份核对的本次 staging，随后按发布事实报告结果。

符号链接保持链接形态，Edit 跟随并核对其真实目标。原文件的写权限参与检查；硬链接、目录和特殊文件通过明确错误保留原语义。应用队列管理本应用发布顺序，外部修改通过状态核对触发冲突结果。

## 恢复

恢复协议版本保持 `1`，新 checkpoint 使用版本 `2`。v2 严格核对版本、kind、字段、路径、原文件身份、before/after 字节哈希以及绑定 invocation/attempt 的 staging 相对路径，并记录目录同步边界。旧 v1 按原始字节哈希和大小进行保守核对。after 状态匹配时先同步目标文件与目录链，再恢复成功结果；before 状态匹配时允许基于最新文件准备新 attempt，状态分歧和权限、IO 错误返回 `interrupted`；文件缺失通过 `ENOENT` 单独识别。

恢复清理同时核对 staging 收据、文件类型、单链接状态、完整字节及权限。部分 staging 或身份分歧保留现场并返回 `interrupted`。默认发布协议以状态核对确定成功、重试或中断。

## 结果

成功结果包含修改数量、变更摘要、差异文本、第一处变更行号和文件产物。rename 后的取消按已发布事实返回结果；目录同步异常返回 `interrupted` 并附带已发布产物，后续恢复通过 `afterHash` 核对效果。失败结果说明具体条件和文件系统原因，供模型上下文、运行事件与工作台展示读取。

Edit 负责精确局部替换。创建新文件或整体重写文件使用 [Write](./write.mdx)，修改目标的确认通过 [Read](./read.mdx) 获取最新内容。
