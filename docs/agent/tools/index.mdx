工具是项目明确提供给模型的可执行能力。模型可以决定是否调用工具、选择哪个工具并填写参数，但不能仅凭提示词获得项目没有实现和注册的能力。

## 工具与运行循环

每次模型请求都会携带当前可用工具的名称、用途和输入说明。模型返回工具调用后，运行循环把调用交给工具执行模块；工具执行完成后，结果进入模型上下文，运行循环再决定是否请求下一轮模型。工具系统不形成第二个 Agent Loop，也不判断任务是否完成。

工具执行模块负责连接模型调用与真实实现；每个具体工具负责完成自己的操作。Bash 负责通用终端命令，文件工具负责结构化的读取、修改、写入和查询。两者能力可以重叠，但承担的产品语义不同：Bash 是处理长尾任务的通用能力，文件工具为高频操作提供稳定输入、可控结果和清晰的活动记录。

## 工具目录与实现状态

当前 `agent/tools.ts` 的注册表只提供 `bash`。Read、Edit、Write、Query 尚未实现或注册；以下保留其设计入口，不能据此认为模型已经拥有这些结构化工具。

| 工具 | 能力 | 是否修改文件 | 实现状态 |
| --- | --- | --- | --- |
| [Bash](./bash.mdx) | 执行本机终端命令、运行本地文件、安装依赖和运行测试 | 取决于命令 | 已注册 |
| [Read](./read.mdx) | 读取文本文件或模型支持的图片 | 否 | 待实现设计 |
| [Edit](./edit.mdx) | 对已有文件执行可验证的局部文本替换 | 是 | 待实现设计 |
| [Write](./write.mdx) | 创建文件或使用完整内容覆盖文件 | 是 | 待实现设计 |
| [Query](./query.mdx) | 列出目录、查找文件和搜索文件内容 | 否 | 待实现设计 |

工具只有经 Runtime 注册才成为模型可调用的 Agent 能力，不是 Composer 的单次运行参数。宿主可以展示工具调用与结果，但界面不能临时添加工具、改变工具定义或根据普通文本猜测并执行操作。

## 新增工具

新增网页搜索、第三方服务或 Pull Request 等能力时，需要同时定义模型能够理解的用途与输入、宿主可以执行的实现，以及回填给模型和运行事件的结果。只有完成注册的工具才会进入模型请求；实现文件存在但没有注册，不代表 Agent 已经拥有该能力。

所有工具共同遵守的调用、校验、取消和结果规则见 [工具执行](./execution.mdx)。
