工具系统。

- 定位：工具是项目向模型明确提供的可执行能力，模型选择已实现并注册的工具并填写参数。
- 模型请求：每次请求携带当前可用工具的名称、用途与输入说明。
- 调用链路：模型返回工具调用后，运行循环交给工具执行模块；执行结果进入模型上下文，再由运行循环决定下一次模型请求。
- 调度归属：工具执行模块连接模型调用与真实实现，每个具体工具完成自身操作，Agent Loop 与任务完成判断统一归属运行循环。
- 能力分工：Bash 处理通用终端与长尾任务，文件工具为高频读取、修改、写入和查询提供稳定输入、可控结果与清晰活动记录。

公共活动元数据。

- 模型 schema：Runtime 为基础注册表与宿主附加工具统一增加模型可见 input 字段 `purpose: string` 与 `targets: string[]`；`purpose` 为必填操作目的，`targets` 为可选目标列表，每个工具沿用自身操作参数与校验契约。
- 主模型生成：同一次常规工具调用响应通过 `content` 提供简洁工具前说明，并为各调用提供用户语言的 `purpose` 和对应 `targets`。
- 目标依据：工具行从实际结构化操作参数提取命令、路径、查询或实体；读取使用 `Read <path>`，shell 使用 `Ran <command>`，其他工具按类别与实际目标生成标签，旧 `purpose`、`targets` 保留兼容数据职责。
- 数据链路：活动元数据保存在 `ToolCall.input`，随现有事件与项目历史恢复；现有 JSON 消息字段承载扩展。Runtime 公共执行边界向工具实现提供纯操作参数，覆盖 execute、prepare 与 reconcile，具体见[工具执行](./execution.mdx)。
- 展示协作：桌面活动按 turn 交替呈现原生正文与一个工具组，工具组按实际类别生成英文标题，如 `Read files, ran commands`。操作行显示实际命令或路径，单行 CSS 省略随可用宽度溢出出现；各行可独立展开完整输入与结果，详情惰性挂载，失败行附紧凑标记。实时与历史共用相同投影，原始 reasoning 保持数据与协议续轮职责，交互与语言规则见[消息流](../../desktop/design/workbench/message-stream.mdx)。

工具目录。

- 基础注册表：提供 `bash`、`read`、`write`、`edit`、`list_dir`、`find_files` 和 `search_content`，CLI 沿用此注册表。
- [Bash](./bash.mdx)：已注册，执行本机终端命令、运行本地文件、安装依赖和执行测试，文件副作用由具体命令决定。
- [Read](./read.mdx)：已注册，以只读方式获取文本文件或模型支持的图片。
- [Edit](./edit.mdx)：已注册，对已有文件执行可验证的局部文本替换，并发布修改结果。
- [Write](./write.mdx)：已注册，创建文件或用完整内容覆盖文件。
- [Query](./query.mdx)：已注册，以只读方式列出目录、查找文件与搜索文件内容。
- [Canvas Edit](./canvas-edit.mdx)：桌面端已注册，按用户指令新增元素，依据 Use selection 编辑引用元素并保存画布变化。
- 桌面注册：桌面 Run 按 Canvas 编辑能力附加 `canvas_edit`，Runner 将其绑定当前窗口、项目与 Run。
- 元素引用：Use selection 为更新、删除等已有元素操作提供身份与冲突基线，新增元素依据用户指令创建。

扩展与协作。

- 新增能力：网页搜索、第三方服务或 Pull Request 等工具同时定义模型可理解的用途与输入、宿主执行实现，以及回填模型和运行事件的结果。
- Canvas 边界：命令与场景契约见 [Canvas Edit](./canvas-edit.mdx)。
- 执行契约：调用、校验、取消和结果规则见[工具执行](./execution.mdx)。
- 恢复契约：持久化阶段、重启恢复与安全重放规则见[工具执行恢复](./recovery.mdx)。
