---
title: Canvas Edit
description: Agent 使用用户引用的画布选区编辑当前项目 Canvas 的工具契约。
---

实现状态：桌面端已实现。`canvas_edit` 是模型唯一的画布工具，内部执行器通过随应用构建的 Canvas CLI 传递编辑命令。桌面 Runner 在本次 Run 注册该工具；用户通过 Use selection 提供已有元素的 JSON、ID 和场景坐标。新增元素可依据用户文字指令创建；更新、删除、复制、分组、锁定、层级、图片裁剪/翻转和箭头绑定操作以已引用元素为目标。组合操作接受同一 frame 中的根元素，解组接受完整组成员。终端版 Agent 的通用工具注册表继续提供文件和终端能力。

实时 Canvas 编辑通过 `canvas_edit` 进入当前编辑器的内存场景，并沿应用保存链路取得磁盘确认。桌面 Runner 在工具注册时提供相同路由的系统指令；文件工具服务项目文件和用户请求的导出，项目内部 `scene.json` 与图片资源由应用保存链路维护。外部 Agent 的受控本地连接作为后续独立能力，复用相同命令与保存契约。

## 输入与目标范围

一次调用接收有序的 `operations` 数组。命令采用画布场景坐标；元素 ID 用于定位已有元素。工具从当前 Run 的冻结选区引用建立目标表，允许命令访问这些元素及本 Run 先前通过工具创建的元素；`create` 可依据用户指令新增元素。同一元素出现在多份引用中时，以 Composer 提交顺序中的最后一份引用为比较基准。

| 命令 | 输入 | 效果 |
| --- | --- | --- |
| `create` | 元素类型、位置和该类型的必要内容 | 在当前场景增加矩形、椭圆、菱形、线、箭头、自由绘制、文字或图片；箭头端点可绑定到引用元素，图片复用引用场景的 `fileId` 或导入本次 Run 上传的图片附件。编辑器分配稳定元素 ID。 |
| `update` | 目标元素 ID 和待修改字段 | 修改位置、尺寸、角度、文字、路径点或图片裁剪；Canvas 默认样式继续生效。 |
| `delete` | 目标元素 ID | 删除目标元素，并由编辑器维护相关绑定与撤销记录。 |
| `duplicate` | 目标元素 ID 和可选偏移 | 复制目标元素及绑定文字，编辑器分配新的元素 ID。 |
| `reorder` | 目标元素 ID 和方向 | 调整元素在当前层级中的位置。 |
| `flip` | 图片元素 ID 和水平/垂直方向 | 翻转图片元素。 |
| `setLocked` | 目标元素 ID 和锁定状态 | 锁定或解锁目标元素。 |
| `group` / `ungroup` | 元素 ID 数组 | 建立或移除所引用元素的组合关系。 |

工具按 Canvas 产品规则填充新元素默认值，校验数值范围、文字长度、路径点数量、图片来源和元素关系。图片附件通过本次 Run 的 `attachmentId` 引用，并受单文件大小限制。输入只表达允许的编辑字段；编辑器生成 `id/version/versionNonce/index` 等内部字段。调用大小与命令数量设上限。模型收到的选区 JSON 是已有元素的定位依据，命令输入是局部编辑意图，`scene.json` 的完整内容由 Canvas 持久化链路维护。

示例：

```json
{
  "operations": [
    { "action": "create", "element": { "type": "rectangle", "x": 120, "y": 80, "width": 160, "height": 90 } },
    { "action": "update", "id": "selected-text-id", "changes": { "text": "新的说明" } }
  ]
}
```

## 执行链路

1. Main 在 Run 启动时保留 Use selection 的冻结快照，按 Run 的项目 ID、窗口与工具调用身份构造桌面专用执行器；新增元素命令可直接依据用户指令执行。Runtime 使用既有 ToolCall → 工具执行 → Tool Message → 模型续轮的调用与结果持久化顺序。
2. 工具执行器启动固定的 Canvas CLI `apply` 命令，通过 stdin 提交 `operations` JSON；CLI 使用本次调用的父子进程 IPC 连接将操作交回 Main。Main 核对操作与调用快照一致，继续使用绑定的 Run、项目、窗口、选区基准和图片附件；每个 CLI 进程提交一个编辑批次。
3. Main 经既有 `CanvasEditBridge` 将命令交给当前项目的 CanvasSurface；工作台打开并加载当前项目编辑器。CanvasSurface 调用编辑器的 `applyCanvasEdit` 命令入口，并协调保存与应答。编辑器拥有最新内存场景，项目内 `scene.json` 承担恢复与持久化。
4. 编辑器在同步编辑事务中完成整个命令数组的目标定位、权限与冲突校验，构造下一场景并一次提交。该批次形成一个可撤销编辑步骤；编辑器负责元素关系、绑定、绘制与历史。
5. 编辑器 `onChange` 更新 CanvasDocument 草稿。固定项目身份的 `CanvasSaveCoordinator` 持有最新文档、dirty generation、已确认 generation 和保存基准；CanvasSurface 捕获该请求所属的协调器并调用该实例的 `flush()`，等待 Main 按项目串行保存并确认目标 generation，然后返回保存结果。变化批次与等值批次共享保存确认规则。
6. Main 将结果回传 CLI；CLI 在 stdout 输出结果 JSON，并使用成功或失败的退出状态。执行器核对输出与编辑器结果一致，再交给 Runtime 写入 Tool Message，继续既有模型回合；Canvas 以轻量提示展示本次编辑结果。

### CLI 模块边界

- `agent/tools/canvas-edit.ts` 定义模型契约、目标授权和工具结果；Host 注入桌面执行器。
- `canvas/cli/index.ts` 解析固定命令与 stdin JSON，`canvas/cli/client.ts` 负责父进程连接，`canvas/cli/protocol.ts` 定义传输消息与大小边界。
- `shell/main/canvas-cli-executor.ts` 拥有固定程序路径、调用快照、子进程生命周期和结果核对；项目、窗口与引用权限归属 Main。
- CLI 输入与结果各设 16 MiB 边界，执行器提供 25 秒确认期限。取消、应用退出和超时结束对应子进程并中止请求；已发往编辑器的异常调用返回 `outcome_unknown`，由用户核对当前画布并提供新引用后继续编辑，Runtime 沿用当前工具恢复契约。CLI 结果传输包含约定状态与受影响元素，完整场景留在编辑器和 Main 的既有保存链路中。
- 生产构建生成 `out/main/canvas-cli.js`，桌面执行器使用 Electron 的 Node 执行模式启动它。Canvas CLI 使用工具执行器提供的调用级 IPC 连接；独立外部客户端连接沿专门接入设计继续扩展。

编辑器的 `getDocumentVersion()` 标记真实元素、顺序和图片资源变化，CanvasSurface 独立比较持久视图字段。绘制缓存的 nonce 负责 renderer 重绘；自动保存由内容版本与持久视图变化触发。协调器同时保持一个进行中的保存请求和一份最新待保存快照，连续编辑合并到最新快照，保存应答归属创建请求的项目实例。

Main 加载文档时返回 `version: { revision, fingerprint }`，保存请求携带 `expectedVersion`。fingerprint 使用 SHA-256 标识规范化持久内容，revision 单独参与版本比较。Main 在项目队列中读取并比较当前版本：内容相同返回 `saved` 并保持 revision；内容变化且基准匹配时提交新版本；基准分歧返回 `conflict`，磁盘内容保持原状。参与 Main 保存队列的写者按项目串行提交，独立文件写者的变化在保存读取时通过版本比较识别。

## 并行编辑与批次语义

`update` 按冻结引用比较目标字段组：位置和尺寸属于几何组，文字内容属于文字组，线条点列属于路径组。目标组自引用创建后保持原值时，命令应用到当前元素并保留用户对其他组的修改。`delete` 使用引用中的元素版本校验完整目标。编辑器维护所改元素已有的绑定关系。新增元素由编辑器分配 ID，结果向模型返回这些 ID，供本 Run 后续调用使用。

整批操作先完成目标定位、权限、数据和冲突校验，然后一次提交。任一命令冲突或参数无效时，整批返回错误并保持当前场景。批次内命令按数组顺序解释；新建元素 ID 在结果中返回，供本 Run 的后续调用使用。同步提交期间，用户编辑与工具调用沿 Renderer 事件循环顺序进入同一编辑器状态。

## 结果、失效与恢复

成功结果包含已应用元素及新建元素 ID，并在保存确认后回填模型。元素冲突结果包含目标元素 ID、原因和当前元素，模型据此调整下一次调用。项目切换、窗口身份失配、引用失效、编辑器加载失败或运行取消分别返回明确错误码；Canvas 保留用户当前选区与视口位置。Canvas 编辑器释放后，工作台打开画布并等待加载，再执行属于当前项目的命令。项目切换先等待当前协调器的 `flush()` 成功，再加载目标项目。

保存遇到 I/O 失败时，协调器保留已编辑的内存草稿、dirty generation 和保存基准；Canvas 提供重试入口，工具结果标明 `persistence_failed` 与 `appliedInMemory`。保存发生版本冲突时，协调器暂停自动保存并保留草稿，Main 保留磁盘内容；工具结果给出 `persistence_conflict`，已应用批次同时给出 `appliedInMemory`。Canvas 提供“重新加载”和“导出草稿”：重新加载恢复磁盘场景并建立新保存基准，导出草稿将内存内容保存为独立 JSON 文件。模型根据实际保存状态向用户说明结果，并由用户通过 Canvas 控件处理保存冲突。

工具执行记录在真实编辑前进入 `effect_pending`。首版使用 `never` 恢复模式：异常中断后保留现场并给出 `interrupted` 结果，用户从当前项目画布核对效果，再通过新的引用继续编辑。提交前取消使整批保持原状；已提交批次继续完成保存结算。

工具注册同时声明 `resumePlanned: false`。旧 run 留下的待执行 `planned` 调用由 Runtime 直接结算为 `interrupted`，attemptCount 保持零，并提交对应 Tool Message；新 run 使用新的画布引用和新的调用身份继续工作。恢复协调由 Runtime 执行，Canvas 工具声明这次冻结引用的生命周期和恢复能力。

画布工具结果只描述本次命令的状态与涉及元素。Canvas 编辑器和当前项目负责实际绘制、图片资源、撤销/重做与保存；对话界面展示工具开始、完成、冲突或保存失败的状态。

图层排序、分组、复制、锁定和解锁均通过同一个 `canvas_edit` 命令数组执行，并沿用当前场景校验、单批次提交、撤销历史和保存确认链路。
