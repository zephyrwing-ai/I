Canvas Edit。

- 状态：桌面端已实现，`canvas_edit` 为模型提供统一画布入口，内部执行器使用随应用构建的 Canvas CLI 传递编辑命令。
- 注册：桌面 Runner 在本次 Run 注册工具并提供相同路由的系统指令；终端版 Agent 的通用注册表继续提供文件与终端能力。
- 引用：用户通过 Use selection 提供已有元素的 JSON、ID 和场景坐标；新增元素依据用户文字指令创建。
- 目标：更新、删除、复制、分组、锁定、层级、图片裁剪与翻转、箭头绑定使用已引用元素；组合接受同一 frame 的根元素，解组接受完整组成员。
- 场景归属：实时编辑进入当前编辑器内存场景，并通过应用保存链路取得磁盘确认；文件工具服务项目文件和用户请求的导出，内部 `scene.json` 与图片资源由应用维护。
- 后续接入：外部 Agent 的受控本地连接作为独立能力，复用相同命令与保存契约。

输入与目标范围。

- 调用：接收有序 `operations` 数组，使用画布场景坐标与已有元素 ID。
- 目标表：从本 Run 的冻结选区引用建立，命令可访问引用元素及本 Run 先前通过工具创建的元素，`create` 可依据用户指令新增元素。
- 重复引用：同一元素出现在多份引用中时，以 Composer 提交顺序最后一份为比较基准。
- `create`：输入元素类型、位置与必要内容，可创建矩形、椭圆、菱形、线、箭头、自由绘制、文字和图片；箭头端点可绑定引用元素，图片可复用引用场景的 `fileId` 或导入本 Run 上传的图片附件，编辑器分配稳定元素 ID。
- `update`：输入目标元素 ID 与待修改字段，修改位置、尺寸、角度、文字、路径点或图片裁剪，Canvas 默认样式继续生效。
- `delete`：输入目标元素 ID，编辑器删除元素并维护相关绑定与撤销记录。
- `duplicate`：输入目标元素 ID 与可选偏移，复制目标及绑定文字，编辑器分配新 ID。
- `reorder`：输入目标元素 ID 与方向，调整当前层级位置。
- `flip`：输入图片元素 ID 与水平或垂直方向，翻转图片。
- `setLocked`：输入目标元素 ID 与锁定状态，更新永久锁定状态。
- `group` 与 `ungroup`：输入元素 ID 数组，建立或移除引用元素的组合关系。
- 默认值与校验：按 Canvas 产品规则填充新元素默认值，校验数值范围、文字长度、路径点数量、图片来源与元素关系。
- 图片附件：通过本 Run 的 `attachmentId` 引用，接受单文件大小限制。
- 字段归属：输入表达允许的局部编辑字段，编辑器生成 `id/version/versionNonce/index` 等内部字段。
- 容量：调用大小与命令数量分别设置上限。
- 内容职责：选区 JSON 提供已有元素定位依据，命令表达局部编辑意图，Canvas 持久化链路维护完整 `scene.json`。
- 创建示例：`operations` 首项使用 `action: "create"`，`element` 包含 `type: "rectangle"`、`x: 120`、`y: 80`、`width: 160` 和 `height: 90`。
- 更新示例：同一次 `operations` 后续项使用 `action: "update"`、`id: "selected-text-id"` 与 `changes: { text: "新的说明" }`，按数组顺序应用。

执行链路。

- Run 启动：Main 保留 Use selection 冻结快照，按项目 ID、窗口与调用身份构造桌面执行器；新增命令直接依据用户指令，Runtime 沿用 `ToolCall → 工具执行 → Tool Message → 模型续轮` 的调用与结果持久化顺序。
- CLI 提交：执行器启动固定 Canvas CLI `apply` 命令，通过 stdin 提交 `operations` JSON；CLI 使用本次调用的父子进程 IPC 将操作交回 Main，每个进程提交一个编辑批次。
- Main 核对：核对操作与调用快照一致，沿用绑定的 Run、项目、窗口、选区基准及图片附件。
- 编辑器路由：Main 经 `CanvasEditBridge` 将命令交给当前项目 CanvasSurface，工作台打开并加载编辑器；CanvasSurface 向 `applyCanvasEdit` 传递请求身份、期限与取消信号，等待编辑并协调保存和应答。
- 场景职责：编辑器拥有最新内存场景，项目 `scene.json` 提供恢复与持久化。
- 命令调度：编辑器同步认领请求并预约初始目标，进入 `scheduled` 状态；微任务调度在调用方当前生命周期结束后继续，重新核对请求取消、场景加载代次和截止时间，并按最新场景重算影响范围，再进入目标等待或同步提交。
- 目标交接：编辑器计算目标与联动对象影响范围并预约编辑权限，等待目标已有人工手势完成场景及历史提交，再读取最新场景、核对引用基线。
- 编辑事务：在同步事务中完成整批校验、隔离计算与一次提交；批次形成一个可撤销步骤，编辑器维护元素关系、绑定、绘制与历史。
- 文档更新：编辑器 `onChange` 更新 CanvasDocument 草稿。
- 保存归属：固定项目身份的 `CanvasSaveCoordinator` 持有最新文档、dirty generation、已确认 generation 和保存基准；CanvasSurface 捕获请求所属协调器并调用该实例 `flush()`。
- 保存确认：Main 按项目串行保存并确认目标 generation，再返回保存结果；变化批次与等值批次使用同一确认规则。
- 结果回传：Main 回传 CLI，CLI 在 stdout 输出 JSON 并使用成功或失败退出状态；执行器核对输出与编辑器结果一致，再由 Runtime 写 Tool Message 并继续模型回合，Canvas 使用轻量提示展示结果。

CLI 模块。

- 工具契约：`agent/tools/canvas-edit.ts` 定义模型契约、目标授权与工具结果，Host 注入桌面执行器。
- 命令入口：`canvas/cli/index.ts` 解析固定命令与 stdin JSON。
- 连接与协议：`canvas/cli/client.ts` 负责父进程连接，`canvas/cli/protocol.ts` 定义传输消息和大小边界。
- 桌面执行器：`shell/main/canvas-cli-executor.ts` 拥有固定程序路径、调用快照、子进程生命周期与结果核对；项目、窗口和引用权限归属 Main。
- 传输容量：CLI 输入与结果各设16 MiB边界，结果传输包含约定状态与受影响元素，完整场景沿编辑器和 Main 保存链路维护。
- 确认期限：执行器提供25秒期限；取消、应用退出或超时结束对应子进程并中止请求。
- 异常状态：已发往编辑器的异常调用返回 `outcome_unknown`，用户核对当前画布并提供新引用后继续，Runtime 沿用现有工具恢复契约。
- 构建：生产构建生成 `out/main/canvas-cli.js`，桌面执行器使用 Electron 的 Node 执行模式启动，CLI 使用调用级 IPC 连接。
- 外部客户端：按独立接入设计扩展连接方式。

文档版本与保存。

- 内容版本：编辑器 `getDocumentVersion()` 标记真实元素、顺序和图片资源变化，CanvasSurface 独立比较持久视图字段。
- 绘制：缓存 nonce 负责 renderer 重绘，自动保存由内容版本与持久视图变化触发。
- 保存合并：协调器同时保持一个进行中的请求与一份最新待保存快照，连续编辑合并到最新快照，应答归属创建请求的项目实例。
- 加载版本：Main 返回 `version: { revision, fingerprint }`，保存请求携带 `expectedVersion`。
- 版本身份：fingerprint 使用 SHA-256 标识规范化持久内容，revision 独立参与比较。
- 保存比较：Main 在项目队列中读取并比较当前版本；内容相同返回 `saved` 并保留 revision，内容变化且基准匹配时提交新版本，基准分歧返回 `conflict` 并保留磁盘原内容。
- 写入顺序：Main 保存队列参与者按项目串行提交，独立文件写者的变化在保存读取时通过版本比较识别。

编辑保护。

- 所有者：Canvas 编辑器的 `EditProtectionSession` 管理临时保护，记录请求 ID、场景加载代次、执行期限、受影响元素 ID 集合及 `waiting/applying` 状态。
- 手势身份：人工指针与文字编辑持有各自手势 token，临时保护随会话释放，场景数据和永久元素 `locked` 继续表达文档内容。
- 影响范围：由命令语义与实时关系共同决定，直接目标、绑定文字及容器、关联箭头与箭头标签共同保护；frame 整体操作包含子元素，组合与层级操作包含相关组成员。
- 绑定扩展：按直接影响关系扩展，独立对象与远端图分支保持可编辑；新建普通元素直接进入场景，新建绑定箭头同时预约已有端点。
- 已有手势：目标正在进行的拖动、绘制、文字输入与输入法组合完成当前交互，等待请求继续保留目标预约。
- 人工门禁：后续重叠修改等待下一次交互，移动、尺寸调整、输入、删除、剪切、擦除、组合和快捷键共用同一门禁。
- 历史交互：撤销与重做先计算整笔步骤影响对象，再决定应用；独立元素修改、画布阅读、复制、平移与缩放保持可用。

批次与冲突。

- 字段比较：`update` 依据冻结引用按组比较，位置与尺寸属于几何组，文字内容属于文字组，线条点列属于路径组。
- 局部应用：目标字段组自引用创建后保持原值时，命令应用当前元素，同时保留用户对其他组的修改。
- 删除：`delete` 使用引用中的元素版本校验完整目标。
- 元素关系：编辑器维护被修改元素已有绑定，新建 ID 回传模型并供本 Run 后续调用使用。
- 隔离计算：目标交接后，以最新场景建立隔离副本，按全部元素内容计算实际变化集合；联动范围扩大时补充预约并重新交接。
- 批次提交：按数组顺序完成目标定位、权限、数据与冲突校验，随后一次提交；已变化元素使用新结果，独立元素保留实时内容与原对象实例，持续人工手势继续更新这些实例。
- 撤销步骤：Agent 批次与人工手势各自形成完整撤销步骤。
- 校验失败：任一命令冲突或参数无效时，整批返回错误，当前场景保持原状。
- 同步边界：读取最新场景、隔离计算与变化提交共享 Renderer 同步执行时段；提交后释放临时保护，保存协调器继续合并最新快照，工具应答等待所属批次保存确认。

结果与生命周期。

- 成功结果：包含已应用元素与新建元素 ID，取得保存确认后回填模型。
- 请求实例：CanvasSurface 按每次执行实例管理取消、保存等待和结果反馈；实例结束时释放自己的执行标记，当前实例更新界面提示，各实例按原请求身份分别结算结果，后继请求接续执行。结果回调更新时，当前请求沿用自身执行实例并使用最新回调。
- 冲突结果：包含目标 ID、原因与当前元素，模型据此调整后续调用。
- 等待结束：调度与等待阶段的取消立即撤销预约；期限到达、场景替换与编辑器释放分别结算会话状态。取消、期限、占用与场景失效分别返回 `canvas_edit_cancelled`、`deadline_expired`、`editor_busy` 与 `project_changed`，后续执行按请求实例核对权限。
- 提交校验：每次内存提交核对请求身份、场景加载代次和有效期。
- 路由错误：项目切换、窗口身份失配、引用失效、编辑器加载失败或运行取消分别返回明确错误码，Canvas 保留用户选区与视口。
- 编辑器恢复：编辑器释放后，工作台重新打开画布并等待加载，再执行当前项目命令。
- 项目切换：先等待当前协调器 `flush()` 成功，再加载目标项目。

保存异常。

- I/O 失败：协调器保留内存草稿、dirty generation 与保存基准，Canvas 提供重试入口，工具返回 `persistence_failed` 与 `appliedInMemory`。
- 版本冲突：协调器暂停自动保存并保留草稿，Main 保留磁盘内容；工具返回 `persistence_conflict`，已应用批次同时返回 `appliedInMemory`。
- 重新加载：Canvas 从磁盘恢复场景并建立新保存基准。
- 导出草稿：Canvas 将内存内容保存为独立 JSON 文件。
- 用户处理：模型根据实际保存状态说明结果，用户通过 Canvas 控件处理保存冲突。

执行恢复与展示。

- 执行登记：真实编辑前，工具执行记录进入 `effect_pending`。
- 首版恢复：使用 `never` 模式，异常中断后保留现场并返回 `interrupted`，用户在当前项目画布核对效果，再通过新引用继续。
- 取消：提交前取消时整批保持原状，已提交批次继续完成保存结算。
- 待执行调用：注册声明 `resumePlanned: false`，Runtime 将旧 run 的 `planned` 调用直接结算为 `interrupted`，attemptCount 保持零，并提交对应 Tool Message。
- 新请求：新 run 使用新画布引用与调用身份，Runtime 负责恢复协调，Canvas 工具声明冻结引用生命周期与恢复能力。
- 展示归属：工具结果描述本次命令状态及涉及元素，Canvas 编辑器与当前项目负责绘制、图片资源、撤销重做和保存，对话界面展示开始、完成、冲突或保存失败。
- 统一命令链路：排序、分组、复制、锁定与解锁均使用同一 `canvas_edit` 数组，沿用场景校验、单批次提交、撤销历史和保存确认。
