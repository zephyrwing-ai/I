---
title: 工具执行
description: 模型工具调用如何分发到真实实现并将结果回填模型。
---

工具执行模块接收运行循环交付的模型工具调用，找到已注册的工具实现并返回结果。它不主动请求模型、不形成独立循环，也不判断整个任务是否完成。

## 调用与结果

每次工具调用都包含稳定的调用编号、工具名称和参数。每个工具结果必须保留相同的调用编号，并包含供模型理解的内容、成功或失败状态以及该工具需要的诊断信息。调用编号保证同一模型回合包含多个工具调用时，每份结果仍能准确对应原始请求。

工具结果只有一个事实来源：同一份结构化结果进入模型上下文，也通过运行事件提供给宿主。宿主不能重新解析命令或普通文本来猜测工具状态。

## 执行顺序

运行循环交付调用后，工具执行模块依次完成以下职责：确认工具已经注册，校验参数是否完整，发出开始事件，调用真实实现，再把成功、失败、超时或取消统一转换为工具结果并发出完成事件。

当前工具默认按模型给出的顺序执行，以保持文件修改和命令副作用可预测。同一回合的结果也按原始调用顺序写回模型上下文。未来只有明确声明互不依赖且不会产生冲突的只读工具，才可以并行执行。

## 错误与取消

未知工具、无效参数、文件不存在、命令返回非零状态或工具自身异常都会成为可读的错误结果。普通工具错误不会直接结束 run；结果回填模型后，由模型决定修正、换用其他工具或向用户解释。

宿主取消运行时，工具与模型请求共享同一次取消信号。正在执行的 Bash 命令及其子进程必须终止，文件工具在写入前后都要检查取消状态，Runtime 最终只发出一次取消完成事件。

Assistant Message 因长度限制而截断且仍包含工具调用时，不执行其中任何调用，因为参数可能不完整。运行循环的继续、终止批次和宿主回合钩子由 [运行循环](../runtime-loop.mdx) 定义，不在本文件重复。
