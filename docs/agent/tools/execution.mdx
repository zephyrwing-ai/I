---
title: 工具执行
description: 模型工具调用如何分发到真实实现并将结果回填模型。
---

工具执行模块接收运行循环交付的模型工具调用，找到已注册的工具实现并返回结果。它不主动请求模型、不形成独立循环，也不判断整个任务是否完成。

当前实现位于 `agent/loop.ts` 的分发逻辑与 `agent/tools/index.ts` 的注册表中，已注册 Bash、Read、Write、Edit 与三个查询工具（list_dir、find_files、search_content）。

## 调用与结果

每次工具调用包含 `id`、`name`、`input` 和 `inputComplete`。执行结果使用 `ok`、`output`、`returncode`、`truncated` 和可选 `error` 等字段；调用编号由外层工具消息与事件保留，结果对象本身不重复存储编号。同一回合多个调用的结果由 `toolCallId` 对应原始请求。

工具结果只有一个事实来源，但按用途投影：Runtime 将返回码与输出格式化为文本工具消息，附带 `isError`；Runner 将结构化公共字段发给宿主，并单独登记文件产物。内部完整输出路径只进入模型工具消息，不随公共工具结果直接发往 Renderer。宿主不能重新解析命令或普通文本来猜测工具状态。

## 执行顺序

Runtime 在工具执行前完成带 `toolCalls` 的 Assistant Message 本地提交。运行循环随后发出 `toolStarted`，校验 `inputComplete` 与工具注册情况，并调用对应执行实现。Bash 实现校验 command 为非空字符串后执行；未知工具和无效调用生成结构化错误结果。

工具返回 `ToolResult` 后，Runtime 构造携带 `toolCallId` 的完整 Tool Message，并等待 SessionRecorder 完成本地提交。提交成功后，Runtime 把 Tool Message 加入本次运行的内存上下文并发出 `toolCompleted`。同一工具批次的结果全部完成该顺序后，Runtime 开始下一次模型请求。

工具返回的业务失败仍然形成 completed 状态的会话记录，`isError` 与错误内容保存在 Tool Message payload 中。持久化失败形成 Runtime 失败，并结束本次自动续轮。

当前工具默认按模型给出的顺序执行，以保持文件修改和命令副作用可预测。同一回合的结果也按原始调用顺序写回模型上下文。未来只有明确声明互不依赖且不会产生冲突的只读工具，才可以并行执行。

## 错误与取消

未知工具、无效参数、文件不存在、命令返回非零状态或工具自身异常都会成为可读的错误结果。普通工具错误不会直接结束 run；结果回填模型后，由模型决定修正、换用其他工具或向用户解释。

宿主取消运行时，工具与模型请求共享同一次取消信号。当前 Bash 执行器只对直接启动的 Bash 进程发送 SIGKILL，目录快照扫描没有接入取消信号；不能保证其所有后代进程都已退出。超时、取消目前也没有独立工具结果状态，通常表现为非零或 -1 返回码，运行层在检查取消信号后结束为 cancelled。

待完善目标：停止整个命令进程组、让文件扫描及时响应取消，并给超时与取消提供可区分诊断。未来文件工具须在写入前后检查取消状态。Runtime 应保证每次运行只有一个终止事件。

Assistant Message 因长度限制而截断且仍包含工具调用时，适配器将 `inputComplete` 标为 false，执行器拒绝调用并回填错误。运行循环的现有控制流及后续扩展边界见 [运行循环](../runtime-loop.mdx)。

## 会话提交验证

- 带 `toolCalls` 的 Assistant Message 完成本地提交后，工具执行器收到对应调用。
- 每个 Tool Message 完成本地提交后，`toolCompleted` 进入事件接收器。
- 同一工具批次的 Tool Message 全部完成本地提交后，Runtime 开始下一次模型请求。
- 工具业务失败形成 completed 会话记录，Tool Message 的 `isError` 保存失败语义。
- 会话提交失败形成 Runtime 失败，并保持后续调用处于待执行或待请求状态。

## 持久化执行恢复

`entries` 保存模型可见消息；`tool_invocations` 保存每个逻辑 ToolCall 的登记阶段、恢复策略快照、checkpoint 与结果入口。两类记录共同构成工具执行恢复事实。

恢复协调器根据 `planned → effect_pending → outcome_ready → completed` 阶段，决定重新调度、安全重放、状态核对、结果物化或停止。模型通过完成后的 Tool Message 获取执行结果；模型回合重试与工具级恢复分别由 Runtime 的对应控制路径处理。完整规则见[工具执行恢复](./recovery.mdx)。
