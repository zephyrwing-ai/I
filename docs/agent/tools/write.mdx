Write。

- 状态：已实现并注册，定义与执行位于 `agent/tools/write.ts`。
- 职责：创建文件或使用完整内容覆盖已有文件，一次调用表达一次整文件发布；精确局部替换使用 [Edit](./edit.mdx)。

调用。

- 参数：提交目标路径与完整文件内容。
- 路径：采用绝对路径或基于工作目录解析的相对路径，满足非空字符串和有效文件系统路径要求。
- 内容：采用 UTF-8 编码，空字符串创建空文件，NUL 字符按实际字节写入，JavaScript 孤立代理项按 UTF-8 编码规则转换为 U+FFFD。
- 目标目录：在执行阶段创建。
- 覆盖：已有文件覆盖构成真实副作用，模型通过 [Read](./read.mdx) 确认现有内容与覆盖意图，再选择整文件 Write 或局部 Edit。

准备与发布。

- 准备入口：每个真实 attempt 先调用 `RegisteredTool.prepare`，读取原始字节、解析符号链接真实目标，并计算一次最终写入字节、大小、权限、`beforeHash`、`afterHash` 和独占 staging 身份。
- 准备资源：限于内存与只读文件句柄，准备失败、取消及后续 SQL 失败时，原文件和目录布局保持原状。
- 直接执行：`execute` 使用同一准备函数与执行计划。
- 执行登记：Runtime 通过 `beginToolAttempt` 在同一事务中持久化本 attempt 的 checkpoint，再执行准备好的 closure；checkpoint 保存恢复证据，`afterHash` 对应 closure 持有的实际 UTF-8 字节。
- 发布队列：执行阶段按真实目标串行处理应用内 Write/Edit 发布，队列负责本应用参与者的顺序。
- staging：在目标同目录以 `wx` 独占创建临时文件，写入准备好的字节，设置权限与已有文件所有者信息，完成文件 `fsync` 与关闭。
- 发布核对：再次核对原文件字节、inode、元数据、符号链接指向和 staging 身份，检查取消后执行 `rename`，最后 `fsync` 目标父目录。
- 发布点：`rename` 发布完整目标内容；此前失败或取消时保持源文件，此后按已发布事实报告结果。
- 文件语义：已有文件保留权限位、uid 和 gid，并接受原文件写权限检查；符号链接保留链接形态，内容写入真实目标；硬链接、目录和特殊文件返回明确错误并保持原语义。
- 外部变化：发布前状态核对检测外部程序修改。

恢复。

- 版本：恢复协议保持 `1`，新 checkpoint 使用 `version: 2`，旧 v1 继续按原始字节的 before/after 哈希与大小进行保守核对。
- v2 核对：检查版本、kind、路径、原状态、字节哈希、绑定 invocation/attempt 的同目录 staging 相对路径，以及既有祖先目录身份。
- 目录同步：发布后按子目录到既有祖先的顺序同步新目录链。
- after 状态：匹配后先同步目标文件与目录链，再恢复成功结果。
- before 状态：匹配后允许准备新 attempt；状态分歧与检查错误返回 `interrupted`。
- 运行中清理：严格核对本次独占创建的 staging inode。
- 恢复清理：同时核对收据、文件类型、单链接状态、完整字节与权限；部分 staging 或身份分歧时保留现场并返回 `interrupted`。
- 决策：默认发布协议根据实际状态确定成功、重试或中断；文件缺失由 `ENOENT` 表达，权限与 IO 错误保留各自分类。

结果。

- 成功：确认实际发布路径、内容大小和文件产物。
- 发布后取消：按发布事实返回结果。
- 目录同步异常：返回 `interrupted` 并附带已发布产物，恢复通过 `afterHash` 核对实际效果。
- 消费：同一结果进入模型上下文与运行事件，供后续模型请求和工作台展示读取。
