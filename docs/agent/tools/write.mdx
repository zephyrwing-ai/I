实现状态：已实现并注册。Write 定义与执行见 `agent/tools/write.ts`。

Write 用于创建文件，或使用调用中提供的完整内容覆盖已有文件。一次调用表达一次整文件发布；精确局部替换使用 [Edit](./edit.mdx)。

## 调用

一次调用包含目标路径和完整文件内容。路径采用绝对路径或基于工作目录解析的相对路径，并满足非空字符串和有效文件系统路径要求。内容采用 UTF-8 编码，空字符串创建空文件；NUL 字符按其实际字节写入，JavaScript 孤立代理项按 UTF-8 编码规则转换为 U+FFFD。目标目录的创建发生在执行阶段。

覆盖已有文件属于真实副作用。模型通过 [Read](./read.mdx) 确认现有内容和覆盖意图，再选择整文件 Write 或局部 Edit。

## 准备与发布

每个真实 attempt 先调用 `RegisteredTool.prepare`。准备阶段读取原始字节、解析符号链接的真实目标，并计算一次最终写入字节、大小、权限、`beforeHash`、`afterHash` 和独占 staging 身份。此阶段的资源限于内存与只读文件句柄，因此准备失败、取消和后续 SQL 失败都保留原文件与目录布局。直接调用 `execute` 使用同一准备函数和执行计划。

Runtime 将本 attempt 的 checkpoint 随 `beginToolAttempt` 在同一事务中持久化，再执行准备好的 closure。checkpoint 是恢复证据，`afterHash` 对应 closure 持有的实际 UTF-8 字节。

执行阶段按真实目标串行处理应用内的 Write/Edit 发布。工具在目标同目录以 `wx` 独占创建临时文件，写入准备好的字节，设置权限和已有文件的所有者信息，然后完成文件 `fsync` 与关闭。工具再次核对原文件的字节、inode、元数据、符号链接指向和 staging 身份，检查取消后执行 `rename`，最后 `fsync` 目标父目录。`rename` 是发布点：此前的失败或取消保持源文件，随后按已发布事实报告结果。

已有文件保留权限位、uid 和 gid，并通过原文件写权限检查。符号链接保持链接形态，写入发生在其真实目标。硬链接、目录和特殊文件通过明确错误结果保留原语义。外部程序的修改通过发布前状态核对检测；应用内串行队列负责本应用参与者的顺序。

## 恢复

工具恢复协议版本保持 `1`，新 checkpoint 使用版本 `2`。v2 核对版本、kind、路径、原状态、字节哈希和绑定 invocation/attempt 的同目录 staging 相对路径，并记录既有祖先目录的身份。发布后按子目录到既有祖先同步新目录链。旧 v1 按原始字节的 before/after 哈希和大小进行保守核对。after 状态匹配时先同步目标文件与目录链，再恢复成功结果；before 状态匹配时允许准备新 attempt，分歧和检查错误返回 `interrupted`。

运行中清理严格核对本次独占创建的 staging inode；恢复清理同时核对收据、文件类型、单链接状态、完整字节及权限。部分 staging 或身份分歧保留现场并返回 `interrupted`。默认发布协议通过状态核对确定成功、重试或中断。文件缺失由 `ENOENT` 表达，权限与 IO 错误保留各自分类。

## 结果

成功结果确认实际发布的路径、内容大小和文件产物。rename 后的取消按发布事实返回结果；目录同步异常返回 `interrupted` 并附带已发布的产物，恢复通过 `afterHash` 核对实际效果。结果进入模型上下文和运行事件，供后续模型请求与工作台展示读取。
