# Agent Studio UX 设计

> 版本：v0.2 · 日期：2026-08-27
> 负责人：UX 设计
> 关联：`docs/product-behavior/`（PM 规格）、`docs/UI-DESIGN.md`（视觉规范）、`docs/ENGINEERING-ARCHITECTURE.md`（实现契约）

## 0. 文档边界

本文只回答“用户如何完成任务，以及界面如何组织和反馈”。

- PM 文档决定产品做什么、范围是什么、规则是什么。
- UX 文档决定信息架构、用户流程、交互行为、状态语义、错误恢复、响应式结构和可访问性要求。
- UI 文档决定颜色、字体、图标、尺寸、间距、组件视觉状态和动效。
- 工程架构文档决定事件协议、状态落点、进程边界和实现顺序。

本文不把尚未实现的会话列表、附件、历史任务画进当前 MVP。

## 1. 产品范围与核心任务

### 1.1 当前 MVP

Agent Studio 是一个以单次运行（run）为中心的桌面工作台。用户完成以下闭环：

1. 选择工作目录并配置模型提供商、模型和执行环境。
2. 输入任务并发送。
3. 观察 Agent 的进度摘要、命令执行和输出结果。
4. 在运行中停止，或在失败后检查原因并重试。
5. 阅读最终回答，并按需展开执行证据。

一次新的运行会替换当前 transcript；会话历史、多会话、附件和持久化不属于本版本。

### 1.2 设计成功标准

- 用户在任意时刻能回答“现在发生什么、下一步是什么、是否需要我处理”。
- 最终回答优先于执行细节；执行细节可审计但不压过结论。
- 失败必须能区分 API/网络错误、命令失败、步数上限和用户主动停止。
- 用户无需打开设置抽屉，也能完成阅读、搜索和停止操作。
- 键盘、读屏器和窄窗口下的关键路径可用。

## 2. 信息架构

### 2.1 工作台骨架

```text
┌────────────────────────────────────────────────────────┐
│ 当前任务标题   · 运行状态                 搜索  设置   │
├────────────────────────────────────────────────────────┤
│                                                        │
│                       对话流                           │
│   用户任务 → Agent 进度 → 工具执行 → 最终回答            │
│                                                        │
│                                                        │
├────────────────────────────────────────────────────────┤
│  +  输入任务……                              发送/停止  │
└────────────────────────────────────────────────────────┘
```

- 不使用左侧导航窄栏。
- 顶部只保留当前任务标题、运行状态、搜索和设置入口。
- 中央区域是唯一主内容区，负责阅读与回溯。
- 底部 composer 固定在对话流下方，负责输入、附件入口（本版本暂不启用）和发送/停止。
- 设置不是常驻面板；从标题栏右侧打开右侧抽屉。

### 2.2 内容层级

对话流按“结论优先、证据可展开”组织：

1. **用户任务**：本次输入的原文。
2. **进度摘要**：Agent 对当前回合正在做什么的短说明。不要把内部推理作为稳定产品契约。
3. **执行详情**：命令、状态、返回码、输出、工作目录和耗时；默认按回合折叠或压缩显示。
4. **最终回答**：运行完成后的面向用户结论，可包含下一步建议。
5. **运行结果摘要**：完成、部分完成、达到上限、取消或失败的明确结果。

## 3. 核心交互

### 3.1 输入与发送

- `Enter` 发送；`Shift + Enter` 换行。
- 中文输入法组合态（`isComposing`）时，Enter 只确认候选，不发送任务。
- `Cmd/Ctrl + Enter` 作为可选的显式发送快捷键，若与系统输入习惯冲突则只保留 Enter 发送。
- 运行中 composer 变为只读，发送按钮变为“停止”。
- 未选择工作目录或任务为空时，发送按钮禁用，并在输入区下方给出原因，而不是只依赖灰色按钮。
- 发送时保存一份不可变的 run snapshot；设置抽屉中的编辑不会影响当前运行。

### 3.2 设置入口与抽屉

- 标题栏右侧提供图标按钮“设置”。
- 点击后从右侧展开设置抽屉；抽屉打开/关闭是布局动画完成后再提交业务状态。
- 抽屉包含：Provider、Model、Base URL/API Key（按 Provider 显示）、Docker、Steps 上限、工作目录。
- 运行中抽屉仍可查看，但所有字段只读，并显示“当前运行配置已锁定”。
- 关闭抽屉不丢失未发送的配置草稿；下一次运行使用最新草稿。
- API Key 只显示掩码，错误时在对应字段附近给出可操作说明。

### 3.3 搜索

#### 当前版本范围

搜索只覆盖当前 run 的 transcript，不搜索历史任务或磁盘文件。

可检索字段：用户任务、进度摘要、命令、命令输出、最终回答和错误详情。

#### 交互行为

- 点击标题栏搜索按钮，或使用 `Cmd/Ctrl + F`，打开搜索浮层。
- 输入后显示匹配数量、当前匹配位置和上/下一个结果。
- 匹配结果在对话流中高亮；跳转时滚动到对应消息，并短暂显示定位反馈。
- 搜索浮层可用 `Esc` 关闭；焦点关闭后返回搜索按钮或触发搜索的元素。
- 运行中也允许搜索已产生的内容；新增流式内容进入索引后更新匹配数量。
- 无结果时显示“当前运行中没有匹配内容”，不显示空白区域。

#### 边界

- 搜索不改变 transcript 的展开/折叠状态，只负责定位。
- 搜索不读取 API Key、运行配置私密字段或未展示的本地文件内容。
- 将来增加会话历史时，搜索索引迁移到 session store；本版本不预埋历史列表 UI。

### 3.4 执行详情

- 每个回合显示一条进度摘要和一个执行详情组。
- 命令状态明确区分：等待执行、执行中、成功、失败、已取消。
- `rc=0` 视为成功；非零返回码必须使用失败语义，不得显示成绿色“已完成”。
- 输出过长时显示预览、字符数和“展开完整输出”；后端截断且存在文件路径时提供“打开完整输出文件”。
- 执行详情默认折叠不影响内容可搜索；搜索命中时自动临时展开命中上下文。

### 3.5 运行结束与恢复

结束结果分为：

- **已完成**：显示最终回答和“重新运行”。
- **达到步数上限**：保留已有证据，提示可提高 Steps 上限后重试。
- **已停止**：明确是用户主动停止，不标记为系统错误。
- **失败**：展示具体原因、错误来源和下一步操作。

恢复动作保持在原上下文内：

- API Key/Provider 错误 → 打开设置抽屉并聚焦对应字段。
- 网络或模型错误 → 提供“重试”，复用任务文本和配置草稿，但创建新的 run snapshot。
- 命令失败 → 保留失败命令和输出，用户可复制命令或重新运行整个任务。

## 4. 状态模型（UX 视图）

四个维度独立表达，不用一个 `scene` 字符串组合所有状态：

| 维度 | 示例值 | 用户看到什么 |
|---|---|---|
| 连接 | connecting / connected / disconnected | 标题栏状态或设置抽屉连接提示 |
| 运行 | idle / running / stopping / completed / cancelled / error / step_limit | composer、标题栏和结果摘要 |
| 回合 | queued / thinking / executing / done / failed | 对话流中的进度行 |
| 注意 | none / needs-config / needs-retry / truncated | 就地行动提示 |

状态组合必须满足：

- `stopping` 期间禁止重复发送，并持续告知“正在停止”。
- `cancelled` 不显示为 `error`。
- 连接断开可以发生在 idle 或 running 中，不改变已有执行证据。
- 最终结果和当前回合状态同时存在时，结果摘要优先级更高。

## 5. 响应式与可访问性

### 5.1 窗口宽度

- `≥ 900px`：完整标题栏、居中对话列、右侧设置抽屉覆盖内容。
- `640–899px`：收紧标题栏，搜索和设置只显示图标，内容列保留最小可读宽度。
- `< 640px`：composer 允许多行，设置抽屉占满宽度；执行详情默认折叠，按钮保持可触达。

### 5.2 键盘与读屏

- 所有图标按钮必须有可见 tooltip 和 `aria-label`。
- 动态状态使用 `role="status"` 或 `aria-live="polite"`；错误使用 `role="alert"`。
- 搜索浮层打开后焦点进入输入框，关闭后回到触发按钮。
- 所有操作目标最小热区为 40×40px；窄窗口不以缩小热区换空间。
- `:focus-visible` 必须清晰可见。
- `prefers-reduced-motion: reduce` 时关闭旋转、脉冲和打字机动画，只保留状态变化。

## 6. 设计验收清单

- 首屏是否明确输入位置、当前工作目录要求和发送条件？
- 运行中是否能在不打开设置的情况下停止并确认正在停止？
- 最终回答是否比执行证据更容易被找到？
- 搜索是否能定位命令、输出和错误，而不误搜配置密钥？
- 失败、取消、步数上限是否有不同文案和恢复动作？
- 640px、375px 宽度和键盘操作是否仍能完成主流程？
